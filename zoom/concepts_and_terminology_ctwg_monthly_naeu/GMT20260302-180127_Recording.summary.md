## Overview

The meeting focused on discussing the process of publishing specifications using SpecupT and Zenodo. Carly and Henk reviewed the steps involved in publishing a specification, including reserving a DOI, creating a release in GitHub, and copying the release to Zenodo. They identified issues with the current process, such as incorrect versioning and the need for manual updates. Kor, the Emperor of SpecupT, explained the functionality of the tool and suggested improvements to the process. The group agreed to create a standardized template for Trust Over IP specifications and to test it with upcoming projects. They also discussed the challenges of decentralized systems and the importance of accuracy in specification publishing.

## Details

Carly and Henk discussed the metadata and authorship details for a project, confirming that Sam Smith is the primary author with others as sole contributors. ### Zenodo Document Versioning Process

Carly and Henk discussed the process of publishing a document through Zenodo, focusing on how to handle versions and ensure stability in the document's URL. They clarified that the correct version to link to is the frozen version 1.0, which has been hashed to ensure stability. Carly explained that the DOI would point to the latest version by default, but linking to the frozen version would provide a stable reference. They also discussed the importance of accurately describing the document in Zenodo, including the version number and a link to the full specification.

### Zenodo Versioning System Instructions

Carly explained the DOI versioning system in Zenodo, noting that each version of ACDC would need its own Zenodo record to maintain clear versioning. She decided to write instructions for creating new Zenodo records for each version, rather than trying to manage different versions within a single record. The team agreed this approach would provide clearer version tracking through ACDC references to previous specifications.

### Version Number Discrepancy Discussion

Carly and Henk discussed version numbers and discrepancies between ACDC and Zenodo, noting that version 1.1 in ACDC corresponds to version 2 in Zenodo. They considered reaching out to Zenodo to fix the issue but decided to manually update the version number in the specification. Kor mentioned a previous mistake in running a command and creating a virgin version. Carly reflected on the challenges of decentralizing systems and how errors can be permanently embedded in automated systems without a central authority.

### DOI Versioning Simplification Plan

The team discussed issues with DOI reservation and versioning for their system. Carly explained that only one DOI is visible when reserved, and it's unclear if multiple versions can be reserved. Henk suggested using a single DOI that links to all versions on the Xanadu site, which would simplify the process. The team agreed to implement this approach for future versions, with Kor confirming he could handle the HTML editing required. Carly said she would email the relevant team to clarify the DOI reservation process.
