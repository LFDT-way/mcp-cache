## Overview

<p>The meeting focused on addressing complex issues with the DTG (Decentralized Trust Graph) Credentials specification and related implementations. Glenn presented a detailed analysis of conformance defects discovered during testing, highlighting conflicts between the specification and actual implementation, particularly around R-DID, M-DID, P-DID, and C-DID usage. The team discussed creating a new VTI (Verifiable Trust Infrastructure) specification to handle cross-cutting issues between different specs rather than overloading individual specifications. They agreed to establish clear boundaries for where different types of information should be stored, with trust graph correlators and task context details living in Trust Task documents, while ZKPs (Zero-Knowledge Proofs) would handle privacy-protected proofs. The group decided to prioritize defining a single concrete ZKP use case for presentation and credential creation that could be implemented as a reference within OpenVTC and the VTI stack. They also agreed to move away from using P/M/R/C-DIDs in favor of clearer terminology and to work asynchronously for the next two weeks on documentation and implementation decisions due to the upcoming GDC conference and the approaching Plumbers Conference deadline.</p>

### DTG Specification Issues Analysis

Glenn presented a document analyzing issues with the DTG (Delegated Trust Graph) specification, explaining that as implementations caught up to the spec, conflicts emerged between the logic in the DTG spec and its intended purpose. The discussion revealed that DTG credentials serve not just as graph nodes and edges but as critical architectural elements for trust networks and VTC governance. Glenn outlined three community types ranging from completely public to highly privacy-focused, and identified several open questions that need resolution by mid-September, either through decisions on the specification or acknowledgment of deviations from it.

### Credential Specification Discussion Updates

The team discussed two main topics: a PR submitted by Brendan and Alberto regarding credential specification, and preparation for an upcoming ZKP discussion. Drummond provided feedback that the proposed content about interoperating with trust tasks should be moved out of the core credentials spec and either placed in the trust task spec or in a separate dedicated spec for specific credential types. The group agreed to potentially rework the PR to include only minimal content in the credentials spec, with more detailed interoperability information being addressed elsewhere, though they needed to determine the specific location for this additional content.

### Trust Specifications Discussion

Glenn and Drummond discussed the complexity of specifications, particularly around DTG Credentials, trust tasks, and ZKP. Glenn suggested creating a new specification, like a "trust over IP" or "VTI" spec, to address the gaps between existing specs rather than overloading individual ones. Drummond referenced SAML as an example of a similar approach and mentioned an action item to create a repository for the agent name spec.

### VTI Specification Development Planning

The team discussed creating a VTI specification to document core trust graph elements and cross-cutting issues. Drummond agreed to set up a repository for the VTI spec and another for agent names. Brendan confirmed he would refactor the existing PR to separate cross-cutting content from key specifications.

### DTGWG Cred Specs Review

The team discussed reviewing issues in the DTGWG cred specs document, with Glenn proposing to continue building while documenting deviations and working asynchronously until next week's meeting. Due to scheduling conflicts with GDC, the team agreed to work asynchronously for the next two weeks, with everyone reviewing the HTML document and providing feedback. Drummond praised Glenn's improved terminology in the HTML page, noting it was clearer than previous acronyms they had been using.

### Core Credentials Implementation Discussion

The team discussed implementing four definitions for Core Credentials, with Glenn suggesting they should try using these definitions both in UX and architecture to identify potential issues. Drummond expressed concern about getting the foundational "DNA" right for Core Credentials to ensure proper functionality. The discussion also addressed VTNs (Verifiable Trust Networks), with Glenn comparing them to autonomous systems in internet networking and noting that while VTNs are conceptually important, no code implementation exists yet, with current work only focusing on VTC recognition.

### ZKP Implementation Strategy Discussion

The team discussed implementing ZKP (Zero-Knowledge Proofs) solutions, with Scott and Mitchell presenting their approach to handling privacy-related questions and trust graph constructions. Glenn suggested starting with a single concrete ZKP implementation for VTC rather than trying to solve all privacy issues at once, emphasizing the need to be selective about where ZKPs are applied. The group agreed to create a prioritized list of required ZKP proofs and to focus on a specific use case that could unblock VTC implementations, with Glenn committing to provide a definition of the first ZKP use case by the next working group meeting.
