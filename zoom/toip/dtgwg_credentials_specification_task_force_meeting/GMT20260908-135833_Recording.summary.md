## Overview

The meeting focused on reviewing Working Draft 02 and discussing a new proposal for generic statement credentials. Geoff introduced an issue proposing a new "statement credential" type that would encapsulate various predicate-based claims like endorsements and observations using a subject-predicate-object structure similar to RDF triples. ### Statement Credentials Structure Discussion

Martina and Sankarshan joined the discussion to ask questions about how statement credentials work. Geoff explained that statement credentials use a subject-predicate-object structure similar to the semantic web concept, where the payload inside the verifiable credential can include specialized vocabularies defined by different sectors or groups. The discussion focused on how this approach would allow for both common and specialized terms to be used in different use cases.

### DTG Credential Verification Discussion

Geoff explained how credentials can be represented in DTG, using passport verification as an example where Martina could issue a credential stating she saw Jeff's passport. Drummond clarified that Martina would be the issuer of this self-attested credential, which Jeff could present to verify his identity within a community. Martina raised a thought experiment about attesting an AI agent as human, which Drummond noted as an interesting but separate case that might need further discussion. Sankarshan asked about whether predicate meanings and constraints could change without changing identifiers, though the discussion ended before this question was fully addressed.

### Statement Credentials Proposal Discussion

The team discussed a new proposal for "Statement Credentials" that would generalize various credential types including endorsement and observation credentials. Drummond explained that these would function as reified RDF statements about other nodes, creating a more flexible structure that could handle multiple use cases. The group debated whether to maintain credential categorization (Edge vs Attestation) or move toward a more unified approach using a table format to describe different credential types and their purposes. They agreed to add comments to issue #28 regarding the categorization discussion and to review Working Draft 02 changes before the next meeting.
