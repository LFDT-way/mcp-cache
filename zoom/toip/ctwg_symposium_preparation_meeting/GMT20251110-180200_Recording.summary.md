### CTW Presentation and Consensus Building

### SpecUpT Ecosystem and Linking Features

Henk and Drummond discussed SpecUpT's capabilities for building ecosystems of interrelated glossaries and specifications, with tools to help maintain synchronization and provide options for users when definitions change. They explored features like Markdown, preprocessing, GitHub Pages hosting, and the ability to convert documents to PDFs with specific formatting requirements. Drummond inquired about the IREF (internal reference) concept, which Henk explained as a form of transclusion that repeats definitions within the same document, and they agreed to explain the distinction between normative and informative linking in specifications.

### SpecUPT: Specification Management Tool

The team discussed SpecUPT, a tool for managing specifications and glossaries, focusing on its handling of normative references and cross-references. Henk explained how SpecUPT allows users to choose whether to adopt definitions from other sources or maintain their own, with the ability to update definitions independently while maintaining integration. Carly suggested telling a user-focused story about how SpecUPT helps manage shared terminology, emphasizing the ability to adopt definitions from other organizations while maintaining control over local modifications.

### Glossary Structure and Governance

Henk explained the structure and governance of glossary definitions, emphasizing the importance of centralizing definitions in a terms directory to avoid scattered information. He described how glossary terms use a key format with lowercase and dashes, which can be referenced using both the key and local aliases. Drummond and Carly discussed the potential for demonstrating these concepts in an upcoming presentation, with Carly suggesting linking to a live glossary example during the talk. Henk clarified the distinction between specifications and glossaries, noting that specifications contain detailed technical content, while glossaries focus on definitions and terminology, allowing for local adaptations when specifications become invalid.

### Markdown Linking System Simplification

The team discussed linking methods in Markdown, focusing on using anchors and IDs for normative references. Henk explained he had simplified the linking system by using meaningful mnemonics instead of Sam's numerical IDs. They agreed to avoid using the spec tag, as it was considered unnecessary and potentially confusing. The discussion concluded with confirmation that the presentation would be kept to 30 minutes, which was deemed appropriate for the topic.

### SpecFT Glossary Functionality Overview

Henk demonstrated the functionality of SpecFT, explaining how it categorizes information into different levels based on specific keywords. He showed Drummond and Carly how definitions are local while TREFs and XREFs point to external terms, emphasizing the importance of maintaining consistency to avoid confusion. They discussed a bug related to spaces and capitalization in the system, and Henk explained the purpose of TREFs in allowing users to easily accept extensions to glossary definitions.

### Specification Tool Functionality Overview

The team discussed the functionality of a specification tool that allows users to create snapshots of glossary terms and link them in specifications. Henk explained that once terms are XREF'd, they are locked in a specific version and will not change, even if the glossary updates. The tool includes a web graphical user interface that requires a one-time GitHub token setup, which will be covered in detail during the upcoming workshop. Drummond praised the team's work on developing these tools, noting that using the software themselves helped identify and resolve bugs.
