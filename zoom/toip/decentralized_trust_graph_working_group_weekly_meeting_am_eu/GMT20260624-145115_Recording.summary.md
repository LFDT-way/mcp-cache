## Overview

The meeting focused on discussing node types in the Decentralized Trust Graph (DTG) specification, with Glenn presenting the implementation challenges his team encountered while building a demonstration for Linux Foundation. The core issue identified was that current DTG credentials lack information about node types (person, agent, device, VTC), making it difficult to implement and scale the system. The discussion explored whether node types should be defined in relationship credentials, separate personhood/agenthood credentials, or somewhere else in the system. Key arguments included the need for clear node typing for trust relationships, the importance of allowing self-asserted types with potential verification through separate credentials, and concerns about implementation complexity and scaling issues. The group agreed to continue the discussion on GitHub, with Drummond emphasizing the need for high-trust assumptions by default and Glenn highlighting implementation challenges related to credential size and performance.

### Decentralized Trust Graph Implementation Issues

Glenn demonstrated a decentralized trust graph implementation targeting the Linux Foundation ecosystem and identified a critical gap in the current specification. The main issue is that the system cannot determine the type of nodes (whether they are VTCs, VTNs, people, agents, or devices) due to overloaded relationship credentials that serve multiple purposes. Glenn proposed solutions including adding node type information as additional credentials or potentially integrating it into the DID document, while Martina acknowledged the importance of addressing this issue from an implementer's perspective.

### Trust Graph Node Type Discussion

The team discussed how to handle node types in their trust graph system, focusing on whether credential types should be stored in edges or nodes. Drummond initially proposed extending the existing type field with node types, but after feedback from Martina and others, he revised the proposal to use a separate node type property to avoid conflicts with credential subtypes. The group debated the merits of storing node types in edges versus nodes, with Glenn and others arguing that relationships should reflect self-asserted types rather than requiring objective verification, while Drummond advocated for strict type requirements to ensure trust. The discussion highlighted implementation concerns raised by Glenn about the significant storage and signing size impacts of additional credential types, particularly with post-quantum computing signatures. The team agreed to continue the discussion on GitHub and planned a follow-up meeting for the following week to address ceremony perspectives and other related topics.
