## Overview

The meeting focused on a comprehensive demonstration of the Decentralized Trust Graph and Verifiable Trust Community (VTC) infrastructure, presented by Glenn, Brendan, Alberto, and Jeff. Glenn provided an overview of the VTC system architecture, explaining how it replaces the current PGP Web of Trust model used by the Linux kernel community with a more secure and privacy-preserving decentralized trust system. The demonstration included two main components: OpenVTC, a CLI tool designed for Linux kernel developers that must be terminal-based and programmable, and Keyring, a modern mobile interface that provides a more user-friendly experience. The team showed the complete workflow from setting up a VTA (Verifiable Trust Agent) through the vetting process, including how applicants can join communities and how administrators can approve or reject requests. They also demonstrated the use of predicate credentialing systems for zero-knowledge proofs to protect privacy during the vetting process. Mitchell provided feedback about his experience setting up an open VTC, suggesting that a guided community setup experience would be beneficial for casual users and discussing hosting considerations for keeping VTAs and VTCs running continuously.

### Verifiable Trust Community Project Overview

Glenn presented an overview of the Verifiable Trust Community (VTC) project, explaining how it replaces the current PGP Web of Trust model used by the Linux kernel community. He detailed the new zero-knowledge proof system called Predicate Credentialing System (PCS) that protects vetter anonymity while allowing validation of new members. The presentation covered the technical architecture including cryptographic helpers and executors, and highlighted the privacy benefits compared to the current system which leaks relationship data between verifiers and those they vouch for.

### VTI System Security Discussion

Glenn and Steve discussed the security of the vetting process, with Steve confirming that the randomization of vetters makes corruption difficult. Glenn then provided an overview of the VTI (Verifiable Trust Agent) system, explaining that it is built in Rust and supports various partners and implementations including WebVH DIDs. The discussion covered trust tasks as cryptographic contracts between entities, with over 530 trust tasks currently defined in the system.

### OpenVTC Platform Demonstration

Glenn demonstrated the OpenVTC platform and trust ceremonies, explaining how trust tasks can be linked together to create complex workflows like community joining. He showed the CLI-based process for connecting to a VTA and joining a community, including the security features like post-quantum cryptography and zero knowledge proofs. The demonstration concluded with Brendan introducing the Keyring mobile app as an alternative interface for easier user access to the platform.

### Keyring Onboarding Process Demonstration

Alberto demonstrated the keyring onboarding process and new features including notifications, VTA creation through a portal interface, and the vetting process for community membership. The demonstration showed how users can connect their keyring to VTAs using QR codes and undergo identity verification through a trust ceremony. Mitchell provided feedback about the community setup experience, suggesting the need for a guided tour and discussing hosting options, while Glenn explained that VTCs can handle offline messaging through queuing and confirmed plans for TEE-based hosting solutions.
