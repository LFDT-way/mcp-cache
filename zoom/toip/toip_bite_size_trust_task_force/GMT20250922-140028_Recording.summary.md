### Linkability Risks in DID Documents

Carly discussed the concept of linkability in DID documents, explaining that putting all keys in the same document could reveal actions across different services, compromising privacy. She suggested using multiple DIDs, one for each key or service, to avoid this issue. Neil and Eric explored the trade-offs between using the same DID for all communications and reusing keys across different documents, with Carly noting that key reuse is generally not recommended and may be technically difficult due to how DIDs generate new key sets.

### DID Specification Security Concerns

Carly discussed her concerns about the DID specification, particularly regarding controller identification and key management. She noted that a single controller DID could be linked to multiple service identities, which might require separate controller documents. Carly planned to consult with Marcus Sabadello about her questions, while Eric suggested that access control should be implemented to prevent unauthorized document linking. Neil explained that internal management DIDs could be kept private, and Carly mentioned that DID methods were being evaluated for security features, though cryptographic continuity verification was not mandatory in the specification.
