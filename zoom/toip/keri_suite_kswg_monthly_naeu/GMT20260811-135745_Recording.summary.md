The team discussed progress on several technical initiatives. ### KERI Suite Implementation Progress

The team discussed progress on the KERI suite implementation, with Henk planning to reach out to speakers about improving connections to human-centric values for training purposes. Kent reported on ESSR PRs merged for KERI and Signify TS, including fixes for delegation, ACDC grants, and leader election issues, with the upcoming release 1.2.14 being the final one in the 1.2x line before upgrading to 1.3. Kent identified two major deficiencies in Jonathan's spec implementation: the need to add authentication and assertion methods sections to the DID doc, and the requirement for a proofing specification when using DIDWebS with multisig. The conversation ended with Samuel planning to review pull request changes to the version 1.0 spec and proposed changes for version 1.1.

### ACDC Spec Pull Request Review

The team discussed several pull requests for the ACDC spec, with most being targeted for version 1.1 rather than 1.0. They approved a new E1E edge operator for version 1.1, which allows linking credentials issued to the same issuer across different ACDCs. The group also reviewed pull requests 202 and 203 related to pathing syntax, though they ran out of time to make a final decision and will continue the discussion in the next meeting. Samuel requested that team members review the DIDwebS latest specs to move the approval process forward next month.
