### Base64 URL-Safe String Validation

The team discussed the specification for Base64 URL-safe strings in URNs, focusing on how to properly validate them. Samuel explained that the strings must include specific character codes that correspond to different cryptographic algorithms (Blake3, Blake2S, Blake2B, etc.) as defined in Caesar version 2.0, rather than just any Base64 URL-safe string. The group debated whether to maintain specific character restrictions in the ABNF or make it more general, ultimately deciding to keep the current specific version reference while acknowledging that future updates to the Caesar specification would require updating both the version reference and the ABNF.

### ACDC Implementation Guide Discussion

Daniel Hardman presented a concept for a "Dossier Implementer's Guide" to address the challenge of handling unbounded sets of evidence in ACDC (Abstract Credential Data Certificate) format without a specific verifier request. He explained how this differs from the typical bespoke ACDC paradigm where verifiers specify exact requirements. Samuel agreed that this was an important problem domain and suggested calling it an "Implementation Guide" rather than a "spec," noting it would fill a gap between unregulated use and formal ecosystem governance frameworks. The discussion highlighted the need to address how ACDCs can wrap and handle other evidence formats like signed PDFs and W3C verifiable credentials.
