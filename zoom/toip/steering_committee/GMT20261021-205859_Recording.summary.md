### AI Policy and Working Group Updates

The team discussed AI guidance policies for the Decentralized Trust Graph Working Group, with Martina suggesting the need for more user-friendly copy-paste instructions for AI agents. Steve raised concerns about IPR-protected meetings and copyrighted content when using AI tools. Drummond announced that the Creator Assertions Working Group (COG) is separating from DIF to become a standalone organization under the Linux Foundation, following feedback from the creator community that wanted more control over the specification governance. The team also reviewed preparations for an upcoming all-members meeting where working groups will present their updates and plans.

### Meeting Slide Template Process Discussion

Scott and Carly discussed the process for creating slides for meetings, with Scott explaining that he created slides without a template for the all-hands meeting due to time constraints. They debated whether to use a master template for future meetings, with Scott suggesting it might be unnecessary for all-hands meetings but useful for larger events like symposiums. Carly then presented the current process for managing version updates, including patch, major, and minor versions, and asked the steering committee for feedback on whether the existing review process should be modified for major and minor versions.

### Version Control Process Updates

The team discussed a new version control process where major versions would require formal review by the Steering Committee with active participation, while minor versions would use negative assurance where changes are announced and reviewed passively with automatic approval if no feedback is received by the next meeting. Scott explained that major versions need Steering Committee involvement due to potential interoperability impacts across different working groups, and Nicholas suggested using conformance vectors as a quantitative trigger for version changes to help mediate potential breakages. The group agreed that impact analysis reports should accompany minor version announcements to summarize changes and their potential effects on implementations.

### Version Update Process Streamlining

The team discussed streamlining the process for minor version updates, agreeing that working groups should have public review drafts and that the Steering Committee should evaluate potential impacts before approval. Carly proposed moving governance documentation from Confluence to GitHub for better version control, and the group agreed this would be beneficial. The team also discussed upcoming participation in IAW, with David and Daniela planning to attend and potentially present about LFDT's support for community work, including recent Open Wallet projects.
