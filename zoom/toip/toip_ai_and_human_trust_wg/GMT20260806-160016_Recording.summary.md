### TSP Protocol Structure Presentation

Wenjing presented a protocol structure that sits on top of TSP, introducing concepts of signed payload and authenticated exchange. She explained two main components: delegation, which involves authority transfer through capabilities and limitations, and invocation, which allows agents to use delegated authority to interact with services. The protocol also includes accountability features for post-action verification, with TEA providing tools for applications to implement these procedures in an interoperable way.

### Authorization Channel Setup Discussion

Wenjing explained the overall setup involving two channels: the invocation channel for authorization requests and the capability channel for actual operations. She described how the current system uses OAuth tokens in HTTP headers, but the new scheme would use a TSP channel for more fine-grained authorization with potential support for complex networks and stronger authentication. The process remains similar where authorization errors redirect users to obtain necessary permissions before retrying the original MCP call.

### Service Invocation and Authorization Concepts

Wenjing and Steve discussed the concept of "invocation" in the context of a service interacting with an MCP server using authorization. Wenjing explained the distinction between two types of invocation: one involving authority recognition and another involving the actual service call. They clarified that once the authority invocation is recognized, the VID can make the service call, and this process can be applied to different types of channels beyond just MCP servers.

### Decentralized Trust Graph Implementation

Wenjing explained how the decentralized trust graph (DTG) system would work as part of the broader TSP framework, using HTTP as an example of backward compatibility where error codes trigger authorization exchanges. She clarified that DTG could be implemented as a component within the system, with flexibility in how the trust exchange process is initiated between different parties. The discussion addressed how this approach would apply generally across different applications like BTG, with specific implementation details to be determined based on each application's requirements.

### Unified Feed System Discussion

Wenjing and Steve discussed a unified feed concept where agents can facilitate service interactions and pass approved offers to users. They explained how the system allows for human-in-the-loop approval processes, particularly during payment stages, using different VIDs for agents and humans. The discussion covered how natural language text messaging can be used for approvals and how all communications can be tracked in a unified feed, with Steve noting that they need to prepare better slides and diagrams to present this proposal to the DTG group.
