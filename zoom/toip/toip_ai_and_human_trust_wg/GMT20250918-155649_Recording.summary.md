## Overview

The meeting focused on the Lightweight Agent Standards Working Group's efforts to develop foundational standards for LLM agents, particularly through the creation of agent permissions.json files to define appropriate interactions with websites. The discussion explored current challenges in implementing and enforcing these permissions, including the need for better understanding of how language models interpret rules and the development of tools to support compliance. The group also addressed potential synergies between different working groups and task forces, particularly focusing on trust frameworks and authentication mechanisms, while discussing the establishment of new collaboration efforts.

## Details

### Lightweight Agent Standards Working Group

Samuele presented an overview of the Lightweight Agent Standards Working Group, explaining its formation and current focus on developing simple standards for LLM agents, particularly agent permissions.json. He noted that while official organizations like W3C and ITF may eventually create formal standards, the working group aims to establish initial standards to promote industry maturity. The group meets bi-weekly and includes members from agent companies, universities, and labs, working towards creating foundational standards for the AI industry.

### Agent Interaction Guidelines Discussion

Samuele explained the need for a system to define what Belser agents can and cannot do when interacting with websites, similar to robots.txt. He described the agentpermissions.json file as a way to specify rules for agent interactions, including resource access, general actions, and API usage. Samuele emphasized that these guidelines are recommendations rather than enforceable rules, as the ecosystem is not yet mature enough for strict enforcement. He also noted that while these standards won't stop all malicious uses, they can help reduce invalid interactions and improve the relationship between agent companies and websites.

### Agent Permissions and Web Interactions

Samuele discussed ongoing work with partners to test the impact of additional permissions on agents and their interactions with web pages. He noted that Cloudflare has been implementing stricter measures, including blocking all agent interactions and requiring payments for certain interactions, which has led to more resistance from website developers. Samuele also mentioned the development of a white paper to promote a standard for agent permissions and the creation of tools to simplify the process of implementing these permissions. Wenjing inquired about the effectiveness of LLM-based agents in following permission rules, to which Samuele replied that while initial performance was poor, current rates are around 90% when used with tools. Samuele also addressed concerns about potential abuses of permission files, acknowledging that adversarial attacks are a challenge but emphasizing that the issue is not unique to agent permissions.

### Agent-Website Interaction Evolution Challenges

The discussion focused on the evolution of agent interactions with websites, with Eric suggesting a future where agents bypass human-facing websites entirely and interact through agent-specific interfaces. Samuele explained that while this would be ideal, practical considerations like maintaining APIs and dealing with agent camouflage make it challenging, though there's ongoing work to convert UIs into APIs. Steven proposed a managed service model where organizations without MCP servers could delegate agent interactions to a trusted intermediary, but Samuele noted that this would require significant effort and might not be more effective than directly educating agent developers about following rules.

### Language Models' Permission Rule Challenges

The discussion focused on the challenges and gaps in understanding how language models interpret and enforce permission rules across different platforms. Samuele and Wenjing explored the lack of systematic research in this area, noting that current knowledge mainly comes from internal testing by agent companies. They discussed the need for a more formal framework to evaluate and benchmark different agents' ability to follow complex rules, particularly in the context of MCP tools and permission management. The conversation highlighted the young and underdeveloped state of research in this field, emphasizing the urgent need for basic security and permission infrastructure to prevent potential financial damages.

### Trust Framework and Task Force Collaboration

The meeting discussed potential synergies between different working groups and task forces, particularly focusing on trust frameworks, agent authentication, and authorization. Wenjing explained their work on a trust framework that includes identification, authentication, and authorization, with applications in preventing prompt injection and ensuring accountability. Samuele suggested connecting with the Loyal Agents Group at Stanford for further collaboration, and Eric mentioned ongoing work with Consumer Reports in the First-person project. The group also discussed the establishment of a new task force, with Eric planning to schedule it for Mondays at 4pm, and Wenjing suggested formalizing the process for task force creation.
