## Overview

The meeting focused on discussing Wenjing's proposal for a Trust Task Layer 3 protocol using ACDC (Authentic Credential Data Container) as a container format for negotiating service agreements between agents. The group discussed how this protocol would enable both authorization and accountability by allowing agents to request capabilities while attaching conditions and constraints. Participants explored the protocol's potential applications, including API access, skill delegation for AI agents, and financial services. The discussion included comparisons with existing credential exchange protocols and considerations for making the framework compatible with other standards like OIDC4VC. The group agreed this approach could serve as a general framework for defining multiple specific use cases, with potential for collaboration between this working group and the Decentralized Trust Working Group on implementation.

### Agent Authorization Mechanism Discussion

Wenjing led a discussion about creating a mechanism to assign authority and capabilities to agents while attaching conditions, constraints, and duties. The goal is to bind authorizations with scope, time limitations, and specific obligations such as deleting private information or reporting back for audit purposes. Wenjing explained the need for verifiable identifiers for agents, suggesting either a career identifier or a web VH, which must remain secure for the duration of the task and any associated audits.

### Durable Identifiers and Protocol Integration

Wenjing discussed the importance of durable identifiers for auditing purposes, explaining that they should last as long as the information needs to be audited. She proposed using ACDC (a container and exchange protocol) in conjunction with TSP (a messaging protocol) to enable authenticity, message integrity, confidentiality, and metadata privacy. Wenjing suggested using a single general protocol instead of separate issuance and presentation protocols, arguing that the semantics could be embedded within the message itself to maintain interoperability in TSP's peer-to-peer design.

### ACDC Credential Exchange Protocol Framework

The team discussed a protocol framework for exchanging credentials and authorization messages. Wenjing explained that the proposed ACDC structure allows for attaching terms and conditions to messages, enabling flexible authorization scenarios beyond traditional credential exchange, such as API access with specific limitations. The protocol can support multiple instances and different credential formats, with Drummond noting its relevance to recent discussions at the SETI summit in Utah.

### Credential Exchange Protocol Discussion

The group discussed container formats and protocols for credential exchange, with Wenjing explaining that JSON-LD serves as a flexible container format in W3C VC 2.0. Tim confirmed observing similar patterns in his work with the Nostr protocol, while Wenjing proposed a unified authenticated exchange protocol that combines issuance and presentation into a single protocol rather than maintaining separate ones. ### Protocol Design for Interoperability Patterns

The team discussed a protocol design focused on making information verifiable and generic enough to be usable across different scenarios. Nicky introduced three functional patterns required for interoperability: orchestration, brokerage, and negotiation. The discussion explored how these patterns could work together, with Nicky suggesting different protocols might be needed at the trust task layer for each functional group. Wenjing proposed walking through specific examples of how these patterns could be implemented, particularly focusing on brokerage as a concrete example.

### Negotiation Mechanism Development Discussion

Wenjing proposed developing a simple and abstract negotiation mechanism based on proposals going back and forth between parties, similar to a Wall Street bidding algorithm. The team discussed defining common negotiation patterns, with the simplest being a "propose or accept" model. Nicky highlighted the complexity of real-world negotiations, which often involve multiple parties and governance frameworks. Drummond suggested using policy references and long-term identifiers like DIDS in the negotiation protocol. The group agreed to focus first on building the basic infrastructure before defining specific patterns and details.
