## Overview

The meeting focused on refining a diagram and framework for Trust over IP (TSP) specification, specifically discussing how to handle continuous learning models and agent composition within the proposed architecture. The group debated terminology, with Steve suggesting that complex models should be called agents rather than models, and discussed how to handle agent identification and state management across different components. Key topics included how to track agent evolution through session management, the use of Verifiable Identifiers (VIDs) for accountability, and the potential implementation of a GitHub-like approach for capturing execution history and enabling rollback capabilities. The discussion also touched on personal agent architecture, with Steve proposing a dual-agent system consisting of an internal virtual assistant and an external digital twin for enhanced security. The group agreed to move forward with the specification development, focusing next on authorization and accountability schemes.

## Details

### SSI and Identity Technology Review

The meeting focused on reviewing a proposed diagram for a specification and discussing recent developments in related technologies. The group discussed SSI (Self-Sovereign Identity) meeting Telecom, noting a trial upcoming in Great Britain across multiple telecom providers. Steve introduced the concept of fiduciary agents in distributed AI alignment, emphasizing the importance of obligations beyond contractual letters. The agenda included two main topics: addressing new discussions and perspectives, and exploring data handling, privacy, and personal data obligations beyond authorization. Recent developments mentioned included three completed IP-related specs and work on a UIM identifier.

### UI Identifier and Authorization Framework

Wenjing discussed the implementation of a standardized UI identifier based on the TSP specification, which allows for verifiable IDs in message formats. Eric raised questions about the potential impact of AI agents on authentication and authorization processes, suggesting a shift toward permission-based access control. Wenjing explained that the current framework is limiting and proposed going beyond it with a dynamic, fluid approach to authorization, emphasizing the need for constant re-evaluation of access rights.

### Authentication Framework Evolution Discussion

Neil discussed the evolution of authentication frameworks, noting that while OpenID Connect remains prevalent, especially in EU wallets, there is a gradual shift toward using SSI DIDs and other technologies under the hood. Neil explained that organizations are leveraging existing user ID and password systems as gateways while transitioning to more advanced authentication methods. Wenjing confirmed that their approach aims to go beyond current frameworks while acknowledging that existing systems like OpenID Connect will continue to coexist and evolve. Neil also mentioned his involvement with HatPro, a Hospitality and Travel Profile specification that will have its initial GitHub release on April 2nd.

### Travel Profile System Presentation

Neil presented a new travel profile system that could contain up to 10,000 data points, describing it as a JSON schema with validation mechanisms for sharing personal information with service providers. He explained that the system would allow travelers to provide necessary information on a need basis, with service providers having incentives to request updated information directly rather than storing it long-term due to liability concerns and data stale ness. Wenjing expressed interest in potentially incorporating this use case into their TEI framework for further analysis.

### Models vs Agents Architecture Discussion

The team discussed the distinction between models and agents in their system architecture. Wenjing presented a diagram showing different levels of complexity, from simple models to more complex agents with state and context. Steve suggested using the term "atomic agent" instead of "model" to better reflect that even basic models have state during execution. The group agreed that as complexity increases, what starts as a model transitions into an agent with context and state.

### OpenClaw Sessions Architecture Discussion

Tim and Wenjing discussed the concept of sessions in OpenClaw, where a session can manage state, memories, and directives, and can be switched between or saved and restored later. Tim emphasized that agents can exist across multiple sessions and potentially across multiple machines, with a beneficial controller orchestrating these sub-agents and sessions. Wenjing agreed with this approach, noting that the model allows for various execution methods including parallelization across multiple computers, as long as memory synchronization is maintained.

### Agent Identity and Context Management

The team discussed the concept of agent identity and context in their system architecture. Neil explained the distinction between trip-specific contexts and long-term preferences, while Wenjing emphasized that the agent is defined by the entity that controls the VID (unique identifier), which is used for authorization and accountability. The group debated whether changes to models, memories, or context should result in a new VID, with Wenjing suggesting that while this could happen, it's ultimately up to the service provider to decide when to create a new identity. The discussion highlighted the challenge of managing access permissions when an agent's underlying components change, with Haley raising concerns about potential security implications of unchanged VIDs during model updates.

### Agent Identification and Composition Schemes

The team discussed agent identification and composition schemes, focusing on how to track and verify agent sessions and their evolution over time. Wenjing proposed using VIDs (Verifiable Identifiers) to identify running agent sessions rather than static code, with metadata capturing details like model versions and operational history. The group explored how to handle agent credentials and accountability through signed workflows, with Steve advocating for a GitHub-like architecture that captures complete interaction dynamics for debugging and accountability purposes. The discussion concluded with plans to move forward with refining the specification document, including adding diagrams and terminology, before addressing authorization and accountability schemes in future sessions.
