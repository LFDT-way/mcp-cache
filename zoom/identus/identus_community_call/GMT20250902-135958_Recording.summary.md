The team discussed several key updates and initiatives. Yurii reported on an issue with the Cloud Agent regarding cryptography key support and outlined plans for a new patch release. ### Cloud Agent Security Enhancements

Roberto and Fábio discussed the security risks associated with exposing the cloud agent, particularly the auto-provisioning feature that allows anyone to create and publish wallets, potentially draining the wallet. They agreed that auto-provisioning should be disabled by default to prevent unauthorized wallet creation. Yurii suggested implementing rate limiting or limiting the number of operations per tenant as an additional security measure. The team considered using the proxy's built-in rate limiting feature, but Yurii preferred limiting the number of operations directly.

### Operational Security and UI Enhancements

The team discussed protecting operations by adding warnings and log messages for non-production settings, such as auto-provision and open SQL admin passwords, to prevent unauthorized access and ensure safe usage. Yurii suggested that administrators could set limits on operations, with users reaching these limits needing to contact an administrator for further actions. The team also touched on representing verifiable credentials in the UI, with Gonçalo planning to contact the W3C Foundation to create a specification. Lastly, they agreed to close a thread related to Cardano DB sync, with Fabio confirming that a summary of the work done would be provided.

### Prism Node and Sync Improvements

The team discussed improvements to the sync performance, which was fixed by switching from individual operations to batching. They also discussed plans to move towards a new Prism node with lessons learned from the current process, which will be more resource-efficient. Yurii mentioned introducing a new Prism VDR based on the filesystem and GitHub, which can use dB sync and is configured for free for one connection. The team explored the possibility of implementing a resolver for the SDK that uses GitHub as the backend, with Roberto suggesting it could be adapted from the existing TS SDK implementation.

### GitHub Rate Limiting Discussion

The team discussed GitHub's rate limiting for unauthorized users, which is 60 requests per hour. They clarified that their current method of accessing GitHub data does not use the API, but rather directly fetches from raw URLs, which still falls under GitHub's rate limiting. Yurii asked Roberto to review the prism resolver section in the document posted by Fabio and Mika, and confirmed that they use the bogtrust resolver. The conversation concluded with a brief discussion about the limitations of unauthorized access to GitHub data.
