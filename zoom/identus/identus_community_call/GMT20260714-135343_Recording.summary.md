### Mentorship Program Credential System Updates

Javi led a community call discussing mentorship program updates, explaining that three phases have been defined for the credential issuance system. Phase one is already implemented with key clock authentication and resolver functionality, while phase two focuses on completing deeds management functions with 4 of 14 tasks completed. Javi clarified that schemas are immutable in the system because changing them could break existing credentials, requiring credentials to be reissued when schema modifications are needed.

### Portal Phase Expansion Plans

Javi discussed plans to add Phase 4 and Phase 5 to the portal, which could serve as the MVP, enabling credential receipt, issuance, verification, and management. He also outlined the addition of PrismDid to DIDCOM, which would allow key binding on the issuance protocol and require updates to SDKs and the cloud agent. Javi highlighted two key components: managing deed resolution and creating new deeds or DIDCOM messages.

### PrismDid Integration Planning Discussion

Yurii discussed the need to support PrismDid for DIDCOM communication in the Mediator repository and other components of the Identus platform, including SDKTS and the cloud agent. He highlighted the importance of refactoring code to support both DeepPeer and DeepPrism and creating appropriate tickets for implementation. Javi agreed on the need for DID resolver and secret resolver support in the SDK, while noting that integrating PrismDid into the cloud agent would be more complex. Javi also explained the potential benefits of key binding in the DIDCOM message for improved security and outlined two variants of the agent: a Didcom-based Edge agent and an OIDC-based agent supporting VCI and VBP protocols.

### OIDC Extensions Implementation Discussion

Yurii and Javi discussed implementing OIDC extensions for UCI and VP, with Yurii confirming they would follow the DITCOM protocol for the Identus portal. Javi mentioned they already have tested VCI code and would need to bring that feature back. Javi also announced plans to integrate their work with the Midnight Network to enable verifiable presentations inside smart contracts, which could be used for applications like lock and claim scenarios.

### DID Method Integration Planning

Yurii announced plans to demonstrate a new DID method integration in one to two weeks, focusing on supporting DEET methods in the Identus platform and aligning with the company's roadmap. Javi explained that as developers building the SDK, their responsibility would be to minimize disruption to existing functionality while enabling the new Midnight DID method. The team discussed how the integration would allow for more complex on-chain integrations that they had not previously achieved.

### Database and Portal Development Update

Javi reported that the database is ready and provided instructions for deployment, including fixes for pagination on Cloud Agent client and local database updates. He demonstrated progress on the identity portal, which now integrates with Keycloak for single sign-on and allows creation of DIDs with automatically derived keys. Yurii suggested making the portal more user-friendly with templates, which Javi acknowledged as planned future work, and the team agreed to continue development with a focus on creating a more accessible dashboard.
