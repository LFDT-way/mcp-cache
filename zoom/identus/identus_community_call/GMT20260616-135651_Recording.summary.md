## Details

### Linux Foundation Identity Portal Update

Yurii led a weekly meeting about the Linux Foundation centralized trust mentorship program and the identity portal project. He explained that the project has moved packages from SDKTS and created a Nixified repository with a five-phase development plan focusing on identity portal functionality including admin profiles, issuance and verification, and connections. The team is waiting for Javier to return from PTO to organize a meeting with Sadie and the product manager to discuss project priorities and requirements. Yurii also provided an update on platform release 2.17, noting that most SDKs have been released but some components still need upgrading and compatibility testing.

### Integration Infrastructure Stabilization Updates

Pat reported focusing on integrating release components and stabilizing the integration harness, which currently shows many red runs due to infrastructure issues. Pat is working to move all infrastructure to GitHub Actions, though there are challenges with macOS Runner limitations and the need for real HTTPS URLs for some tests. Yurii confirmed that Cindy has been added as a maintainer with privileges to approve PRs, and mentioned that branch rules for the identity portal repository will be configured this week.

### Identity Portal Development Update

Yurii explained that the identity portal was originally part of a larger Atala tribe initiative to create a UI and SaaS solution with advanced security and Web2 to Web3 bridges, but the project wasn't delivered in time due to structural changes. Under a mentorship program, they created a new identity portal as a web application that can use cloud agents or SDKs for offline-first initiatives to create credential issuers, verifiers, or holders. Yurii noted that the project is free and open source, built using RACT and RACT Native framework, and may potentially be reused in the Lace wallet's self-serving identity capabilities.

### SDK Consolidation to Rust

Yurii shared thoughts about the current state of their SDKs, which include three different language implementations and Cloud Agent with similar functionality. He explained that managing feature parity across four code bases has become challenging, and the team is exploring a potential switch to a single Rust codebase with different language bindings. Yurii mentioned they are working on a prototype using SpecKit to define software development lifecycle specifications and plan to introduce one more SDK in about a year, with potential deprecation of the existing TypeScript, Kotlin, and Swift SDKs.

### AI-Driven Architecture Implementation Plans

Yurii and Jon discussed plans to implement an AI-driven architecture where 80-90% of the codebase would be powered by AI agents. Yurii explained that this would involve creating a Rust core that would live in every SDK, including Swift and Kotlin, with a lightweight proxy layer on top. He noted that this architecture is inspired by Signal's implementation, where a Rust core serves multiple language bindings, and emphasized that while this is a long-term vision, they are still defining the roadmap for the next year.

### iDentists Book Writing Project

Jon and Roberto are writing a book on iDentists as part of a Catalyst proposal, with the first draft due by the end of June and a more concrete draft by mid-August. Yurii confirmed that the latest platform release with SDKTS was published four days ago and recommended focusing the book on use cases and solutions rather than specific SDK versions. The team discussed the status of NIX and other deployment options, with Yurii clarifying that NIX is an infrastructure-as-code tool rather than a replacement for Docker. Jon invited community members to volunteer as book reviewers for the project, offering ADA compensation for those who can help review the content in August.
