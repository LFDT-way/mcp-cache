### VDR Integration Progress Update

The team discussed the progress on the VDR (Verifiable Data Registry) integration with the Prisma node, which is now complete and demonstrated in Pat's video. Yuri highlighted that the Cardano VDR specification is defined in the Identus repository, with implementations in three components: Scala, Prisma, and the Prisma node. The team noted that the changes have been merged into the Prisma node and published to Docker Hub, but Alan will oversee the quality gates process in the coming weeks. Future plans include using these implementations in SDKs and Cloud Agent, with two additional integrations planned for the final phase.

### REST API for Mobile Driver

The team discussed creating a REST API layer for the driver to communicate with the database indirectly, allowing for a lightweight driver that can operate on mobile devices. Yurii explained the differences between the current and new infrastructure setups, highlighting that Neoprism, a more optimized version of the Prism node, will eventually replace the current setup. They also discussed the use of BlockFrost or Neoprism for ScalaDit to publish and read operations in the Cardano blockchain.

### Blockchain SDK and API Integration

The team discussed the implementation of SDKs and the use of REST APIs for interacting with the blockchain. Yurii explained that Neoprism can expose a REST API for DID resolution and management, and Roberto clarified that SDKs can use a plugin interface to enable resolvers. Fabio proposed creating a service to separate indexing and resolving data, with the service handling indexing and the SDKs or drivers performing validation and mathematical proofs on the user's device.

### Cardano VDR Driver Implementation Demo

The team discussed the Cardano VDR driver implementation and its documentation, with Fabio presenting a demo of the driver's capabilities. The discussion highlighted that the driver, called Prism, allows for reading, creating, updating, and deleting data on the Cardano blockchain through the cloud agent. Fabio demonstrated these operations using a local testnet setup, showing how data can be created, updated, and deleted, with the changes reflected in both the cloud agent and Neoprisma UI. The team emphasized the importance of distinguishing between custodial and non-custodial solutions when using the cloud agent and SDK.

### Verifiable Data Registry Implementation Update

Fabio presented an update on the Catalyst Project, focusing on the implementation of a Verifiable Data Registry (VDR) using the blockchain. He explained the functionality of the VDR driver, which is implemented in Scala and runs on the JVM, connecting to BlockFirst for data storage and transactions. Fabio demonstrated the five basic operations of the VDR: creating, reading, updating, deleting, and verifying entries. He also discussed the implementation details, including the use of MongoDB for data management and the need for ADA or PADA for transactions on pre-prod or mainnet. The presentation concluded with a review of the code repository and potential use cases for the VDR.

### VDR Implementation and Transition Plans

Yurii presented the VDR implementation in the present node, explaining its importance for transitioning users to Cloud Agent and discussing plans to deprecate Prismode by mid-next year. He demonstrated changes in protobuf models, extended the gRPC API to support VDR operations, and showed tests for VDR data manipulations. Fabio asked about implementing schemas for VDR usage, and Yurii mentioned the need to discuss this in GitHub and compose a roadmap for 2024-2026. The team plans to adapt the VDR implementation into issuance verification flows, discuss VDR usage in SDKs, and finalize the current catalyst proposal for VDR implementation.
