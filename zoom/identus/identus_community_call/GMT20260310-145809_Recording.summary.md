## Details

The meeting focused on several topics, including the Linux Foundation mentorship program, which has a deadline of March 13 for mentors to publish their ideas. The group also discussed the integration of the Identus platform with the latest wallet, with Fabio presenting a specification for deterministic presentation that he had composed a few months ago. ### Fabio's Tool Bug Discussion

The team discussed a bug in Fabio's tool that prevents valid operation creation, so they decided to postpone the demo of the HD derivation extension to the next meeting. Fabio demonstrated a jar-based tool that allows building operations through command-line commands, including creating master keys and specifying service keys. Yurii mentioned that while the cloud agent integration is complete, there are minor issues with custom fields in Neo Prismode that need to be addressed.

### Backend Transition and Integration Planning

Yurii discussed the transition between two backends, Neopriest and Prismode, for Cloud Agent, emphasizing the ease of switching between them for Git and VDR operations. He highlighted the segregation of dependencies through integration tests and the setup of environment variables for smooth transitions. Yurii also mentioned plans to use Neopriest or BlockFrost to add VDRs to SDKs, though the timeline is unclear. The team discussed a potential mentorship program from the Linux Foundation Decentralized Trust, considering ideas like a model context protocol for AI agents, but no final decision was made on applying. Fábio suggested Elias might be interested in participating in a specific project, but Elias did not elaborate.

### Kubernetes Mentorship Program Planning

The team discussed mentorship program ideas, focusing on Kubernetes configurations and MCP (Mentorship Component Platform) implementation. Yurii shared a previous demonstration using Minikube for building reference configurations, while Javi suggested that MCP should integrate with various SDKs to create and verify prompts for model authentication. The discussion highlighted the need to demonstrate value to the community and determine the best stack to use for Kubernetes implementation.

### MCP Implementation Strategy Discussion

The team discussed three different aspects of MCP (Model Context Protocol) implementation: a cloud agent MCP, a documentation-focused MCP, and a new protocol for authentication and delegation of permissions. Javi and Fabio clarified that while MCPs can be used for various purposes, they are primarily functions that models can call correctly or not use at all, unlike code generation which is more deterministic. The team agreed to wait for a response from MCPID about their participation in the mentorship program before proceeding, and Yurii proposed continuing the discussion in Discord while gathering support for submitting a proposal.

### Linux Foundation Program Proposals Discussion

The team discussed potential proposals for the Linux Foundation program, focusing on whether they should submit their own proposals or mentor others. They explored ideas including SDK TS refactoring for blockchain agnosticism, which Javi and Yurii agreed was too complex for the current timeframe. The group also considered creating a unified UI for both cloud agent and offline-first solutions, which Javi estimated would take 3 months to develop. Yurii proposed discussing this idea further internally and sharing thoughts in Discord. The conversation ended with Elias suggesting adding the offline UI concept to a slide for presentation purposes.
