## Overview

The Hyperledger Identus committee discussed updates on the Apollo library, VDR integration, and Cardano implementation, addressing various technical challenges and approving milestones. ## Details

### Hyperledger Identus Apollo Updates

The Hyperledger Identus committee discussed updates on the Apollo library, which is experiencing difficulties with signing artifacts due to changes in the Gretel version. Gonzalo mentioned that while npm and Swift builds are working well, there are issues with publication. The team received approval for the VDR Identus milestone, which included integration with the cloud agent. Fabio inquired about the release version of these conditions, and Yurii mentioned they might spend time publishing the HTP client for the cloud agent. The next milestones include integration with Cardano and presentations/workshops, with Gonzalo suggesting a presentation at the Rave River event.

### Cardano VDR Integration Progress Review

The team discussed demonstrating their work as a workshop and reviewed progress on Cardano VDR integration, where Fabio reported on a nearly complete pull request and ongoing tool development for creating deeds. Pat shared updates on the VDR specification, including a new URL scheme for locating resources, while Yurii invited feedback on documentation improvements and mentioned upcoming documentation for Lace integration. Roberto noted that while cloud agents can resolve short dates, offline tools like the 1st API would be useful for edge cases.

### Decentralized Data Retrieval Protocol Update

The team discussed a new scheme for reading data that removes the need for hardcoding hostnames, allowing data to be retrieved from any VDR instance. Pat explained that this change, already in a pull request, simplifies the process for decentralized storage on the blockchain. Yurii highlighted that the new scheme clarifies expectations about HTTP URLs and improves boundaries between VDR proxies and drivers. FabioPinheiro provided additional context, explaining the problem of URL replacement and the need for a new protocol to better describe data retrieval in VDR. Roberto confirmed that the VDR is protocol agnostic, as long as it can access the data.

### URL Handling and Data Access

The team discussed the handling of URLs and data access in their system. Roberto explained that the URL is a description of how to access data, while the metadata verifies its content. Fabio Pinheiro raised concerns about software that might not recognize VDR-specific URLs, comparing it to the EPFS problem where different protocols (HTTP and EPFS) were supported. The team agreed that they already have the capability to support both HTTP and VDR URLs, with the URL manager handling protocol-specific parsing.

### Blockchain Trust and Verification Mechanisms

The discussion focused on trust and verification mechanisms in blockchain and HTTP implementations. Roberto raised concerns about trusting HTTP links compared to blockchain-based systems like Cardano, while Fabio explained that trust in status lists is established through their creation by the issuer. Gonçalo noted that trust mechanisms depend on specific use cases, particularly whether issuers want full control over data storage or prefer blockchain-based verification.

### Data Verification Across Driver Systems

The discussion focused on data verification processes across different drivers, with Gonçalo explaining that immutable data can be verified using hashes, while mutable data requires specific verification methods provided by each driver. Fabio Pinheiro suggested using a list of operations for verification, similar to a power block, which would allow users to cascade and verify changes on their side. The team agreed that each driver would have its own verification approach, ranging from simple signature checks to more complex methods, depending on who is performing the verification.

### Cardano VDR Protocol Implementation

The discussion focused on the VDR (Verifier Data Router) protocol and its implementation, particularly for Cardano. Fabio explained that the protocol allows verifiers to trust and work with data from VDR URLs, with the ability to recognize and connect directly to VDRs of the same family. Gonçalo and Fabio discussed how data storage works in Cardano, noting that only small amounts of data can be stored directly on the blockchain, with larger data being stored elsewhere and referenced through links. They also touched on the special case of status lists, which require a dedicated driver implementation to handle storage efficiently.

### Deterministic ID Creation Proposal

The team discussed a proposal for deterministic ID creation from a non-monolithic key in Lisk. Fabio explained the concept of using a master key to create a deterministic deed, which would allow for recovery of control over the keys from the deed. The proposal aims to be backwards compatible with existing Prisma deeds. Roberto expressed approval of the concept but had some concerns about backward compatibility, which Fabio assured would be maintained. The team agreed to create documentation for further review, and the conversation ended with plans to reconvene in a week.
