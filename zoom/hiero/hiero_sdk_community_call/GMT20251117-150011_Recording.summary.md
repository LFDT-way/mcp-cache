## Details

### SDK Version 3 Planning Updates

The team discussed updates on the JS and Rust platform work, with Roger making progress on the JavaScript SDK by changing how publishing would work, preparing for a full cutover in January. The Rust work was postponed for a few weeks to align with a new release. The main focus was on planning a version 3 SDK, specifically discussing how to handle key creation and encoding. They explored two potential APIs: a simple key creation method that attempts to understand different encodings and defaults to ECDSA if unable to determine the encoding, and a more specific method that allows users to specify both the encoding and algorithm. Rohit was consulted for his input on handling various key encodings and algorithms as the network expands.

### Key Encoding and Interoperability Discussion

The team discussed key encoding formats and interoperability between SDKs. Rohit explained that while DER encoding can be used for keys, it lacks metadata to determine the algorithm unless combined with ASN1 or PKCS8 formats. Keith suggested inventorying current and future supported keys to establish a consistent encoding standard, particularly for ECDSA keys with hex encoding. The team clarified that while private keys have significant overlap between ECDSA and ED25519, public keys have less overlap, which affects their ability to automatically determine key algorithms from DER encoding.

### SDK Encoding Standards Alignment

The team discussed key encoding standards and SDK compatibility, with Keith noting that while many cryptographic libraries support different key variations, they should focus on supporting the specific encodings used by popular wallets like MetaMask rather than every possible variation. Robert agreed that consistency between SDKs is important, and the team decided to conduct an audit of current library implementations to ensure they meet their encoding requirements. They also discussed the importance of designing APIs to be forward-compatible, particularly regarding potential future additions like quantum keys, which would require significant organizational effort.

### Post-Quantum and Python SDK Updates

The team discussed post-quantum cryptography implementation challenges and agreed to focus on supporting ECDSA as the most common use case. Sophie presented a detailed analysis of Hacktoberfest's impact on the Python SDK, highlighting a 660% increase in activity with 74 merged pull requests and 39 new contributors. The team identified the need for better automation and training to scale the Python SDK's maintenance, with suggestions to integrate with the TCK and potentially allocate dedicated resources to support Python SDK development.
