## Overview

The SDK team held a weekly community meeting to discuss updates across multiple SDKs and review a new key handling implementation for V3. Hendrik presented a Java-based prototype for key handling that combines key containers (like PKCS8) with encoding formats (such as DER or PEM), which received positive feedback from Robert. The team discussed the use of CodeRabbit for automated pull request reviews, with Angelina sharing that the tool is currently free for open source projects. The conversation ended with a debate about changing the meeting cadence from weekly to bi-weekly, with Keith and Hendrik presenting different perspectives on the timing and content needs for maintaining community engagement.

### SDK Language Updates and Coordination

The SDK teams discussed updates across multiple languages. Venilin reported progress on JS coordination with the GFI team to improve onboarding for new contributors, though they need to resolve permission issues. The Go SDK was updated with new protobufs, while Swift will release version 0.47 with Swift 6X support, accompanied by blog and Twitter announcements. C++ saw an increase in contributor activity with multiple new contributors completing issues and PRs. The teams agreed to coordinate offline regarding beta releases and maintainership permissions.

### SDK Contributor Management Strategies

The team discussed the growth and management of contributors across different SDKs, with Sophie2 highlighting challenges in managing a large number of contributors for the Python SDK and suggesting a need to slow down issue creation. Robert and Hendrik agreed that while having more contributors is positive, it's important to maintain a sustainable pace, with Robert emphasizing the need for more maintainers to handle the workload. They decided to continue discussions on strategies for smoother pipelines for new committers and maintainers in the upcoming Good First Issue meeting. Additionally, Venilin provided updates on ongoing Rust development, including progress on the pector upgrade transaction and work on TCK endpoints.

### Java Key Handling Prototype Review

Hendrik presented a Java-based prototype for key handling and import/export functionality, which includes support for various key formats and encodings. The prototype has been implemented with unit tests covering different scenarios, and a pull request has been submitted for review. Robert expressed approval of the approach, noting its flexibility for both novice and experienced users, as well as its extensibility for future key format additions. The team discussed the possibility of implementing similar functionality in other languages, though the location for such implementations remains undecided.

### SDK Development and API Guidelines

Hendrik and Robert discussed the development of SDKs and API guidelines. They agreed to store common test vectors in the SDK Hub, particularly for Rust and JavaScript. Hendrik reported that 75% of a sample project was generated by AI based on existing documentation, with plans to improve this to 90% for other languages. They discussed the use of a meta-language for defining new APIs in a language-independent way, with guidelines already created for Java. Hendrik requested help from SDK maintainers to develop best practices for other languages, aiming to create a solid foundation for prototyping proposals and V3 implementation within the next few months.

### V3 Documentation and Tools Review

The team discussed progress on V3 development, noting that documentation is about 80% complete. Robert and Hendrik agreed to focus on creating best practices documents before proceeding with prototyping, particularly for the keys functionality. They explored using CodeRabbit for pull request reviews and catching breaking changes, with Angelina confirming it's currently free for open source projects. Hendrik raised concerns about the long-term sustainability of CodeRabbit's free service, suggesting they should be mindful of potential future costs.

### CodeRabbit Review System Updates

The team discussed CodeRabbit's pull request review functionality, where Angelina shared updates on review instructions for token classes and confirmed these could be expanded to other SDKs in the future. Sophie Bulloch noted they were testing CodeRabbit's priority system and found it sometimes overreacts to issues. Robert and Angelina agreed the bot's reviews were generally effective, with Robert confirming they could be incorporated into other areas. The conversation ended with a discussion about changing the meeting cadence from weekly to bi-weekly, with Keith suggesting this was originally the plan and questioning what makes a successful community call.

### SDK Community Meeting Schedule Debate

The team discussed the frequency of their SDK community meetings, with Keith and Hendrik advocating for weekly meetings while Robert and Angelina considered both weekly and bi-weekly options. The group debated the impact of timing on attendance across different time zones, with Hendrik suggesting a dual meeting approach similar to their tech meetings to better accommodate global participants. The team agreed to continue the discussion at the next meeting, with Robert proposing to make the meeting time and scheduling preferences the first agenda item for further community input.
