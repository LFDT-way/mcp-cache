## Details

### Mirror Node Architecture Proposal Discussion

Keith led a SDK community call to discuss a new proposal for mirror node functionality. He presented a revised architecture proposal following Hendrik's feedback, which identified potential issues with the current architecture for mirror node HTTP requests, particularly affecting balance queries. Keith asked Mustafa if he had reviewed the proposal or Hendrik's comments on the Java implementation.

### HTTP Client Architecture Proposal Review

Keith presented a new HTTP client architecture proposal for SDKs, created recently and requiring Hendrick's review. The team discussed whether to proceed with existing mirror node balance query proposals using the current architecture or wait for the new architecture to be finalized. Hendrick raised concerns about the current architecture, including issues with static HTTP clients, connection management, and Android compatibility, leading to a debate about whether to continue with current implementations or pause development to address these architectural issues.

### SDK Deprecation Progress Review

Keith discussed a draft PR that needs review and feedback from the team. Mustafa and Dosi provided updates on their work on Java and Go SDKs, focusing on mirror account balance and token balance deprecations. Angelina reported progress on the Python SDK deprecation and asked about HIP 1195, which Keith confirmed is still on hold due to potential future architectural changes.

### Inactive Permission Holder Cleanup

Sophie announced that she identified permission holders across Hiero who have been inactive for over six months and created pull requests to remove them. She explained that this could address potential security issues and maintain better project hygiene. Sophie requested that maintainers review the pull requests and provide feedback through GitHub votes, particularly noting that the analytics dashboard has 100 inactive permission holders that could benefit from this cleanup.

### Inactive Maintainer Policy Discussion

The team discussed the official policy for removing inactive maintainers, which is based on having no activity for six months and not responding when contacted. Sophie clarified that inactivity is measured across multiple dimensions including creating issues, comments, approvals, and merges. The group agreed that inactive maintainers should be removed to ensure better project visibility and sustainability, though they noted concerns about maintaining activity in repositories with few PRs to review.

### Permission Management and TIP Updates

The team discussed two main initiatives. Sophie explained her work on cleaning up inactive permission holders across the project, which will be handled by individual teams rather than globally, with approximately 60 people identified as inactive for 6 months. Angelina and Sophie provided an update on the TIP HIP tracking bot, noting they are exploring ways to automate and reduce duplication in the process, including potentially creating separate tracking boards for each SDK. Keith emphasized the importance of reviewing a new PR in the SDK Collaboration Hub for the HTTP client architecture and requested feedback from the team.
