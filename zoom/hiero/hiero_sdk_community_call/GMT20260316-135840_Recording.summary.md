### CPR Merges and HIP Updates

Georgi reported merging 20 dependent CPRs and completing several documentation PRs, including changes to start instructions and examples using DCSA keys. Robert inquired about new Rust contributors, to which Georgi responded that no new contributors had started yet for Rust. Robert then discussed a new PR for HIP 13 regarding a missing field in the high volume transaction record and presented a V3 design for a new request hierarchy structure, which is still a draft and aims to make requests more modular and consolidated.

### Pull Request Strategy Discussion

Robert and Hendrik discussed two related pull requests: one for the request hierarchy and another for the transaction builder. Hendrik suggested splitting the larger PR into smaller, more manageable pieces to make review and implementation easier. They agreed to start with the transaction builder PR first, and once that is approved and merged, Robert will update the request hierarchy PR accordingly.

### PR Splitting Strategy Discussion

Robert and Hendrik discussed splitting a large PR into smaller, more manageable pieces to facilitate review and address specific issues. They agreed to create separate PRs for transaction builders, ProcNode API with subscriptions, and interface abstraction, aiming to reduce complexity and streamline the review process. Robert also mentioned waiting on the retry feature until a new HIP is released and sought feedback on the block node API design, which has been reduced to three key queries. Dosi expressed intent to review the block node API, and Hendrik noted ongoing work on standardized labels, acknowledging the need for further exploration of Swift-related aspects.

### SDK Maintainer Process Consolidation

The team discussed streamlining SDK maintainer and committer processes by consolidating multiple groups into a single global group for all SDKs. Hendrik proposed eliminating the need for multiple maintainer groups while maintaining current voting requirements for promotions, though Keith raised concerns about security and vetting processes for less popular SDKs. The group agreed to use manual tagging in code owners files rather than maintaining separate groups, and Hendrik clarified that while consolidating groups would make the process easier, it wouldn't compromise security since code ownership would still be controlled through specific file permissions.
