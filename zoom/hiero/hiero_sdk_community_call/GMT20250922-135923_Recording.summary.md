### Node Account ID Change Discussion

The SDK team is working on two main items: HIP1195, which involves high row hooks with a finalized design document and implementation in progress, and a design document for changing node account IDs to give node operators more control over where node rewards are directed. Keith noted that there is ongoing discussion about whether node account ID changes should take effect immediately or only at upgrade boundaries, which could impact SDK users who target specific nodes. The team is also considering the propagation delay of node account ID changes to the mirror node, which could potentially cause transaction failures during the transition period.

### API Changes and Node Degradation

Robert and Keith discussed the implications of potential API changes and the need to maintain a good developer experience. They also talked about a design discussion starting on how SDKs can better identify and avoid degraded nodes when sending messages. Robert mentioned that this issue would require deeper error checking at the GRPC level and potentially implementing logic for retries or trying different nodes. Keith suggested a fast-fail solution where nodes not responding within a certain time would automatically be skipped.

### Exploring Timeout Feature Alternatives

The team discussed exploring alternative solutions, including implementing a timeout feature, and considered the options provided by GRPC. Robert mentioned that the decision would depend on finding the best solution. The conversation ended with an open invitation for further discussion, and the group agreed to reconvene in a few weeks.
