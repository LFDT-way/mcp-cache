## Details

### V3 Sandbox API Development

Robert discussed the status of PRs and API design documents in the Hub, noting that Hendrik's contributions were not present due to his involvement in other PRs. Robert highlighted Hendrik's work on a V3 prototype, known as the V3 Sandbox, which includes sample designs for potential API improvements. He encouraged team members to review and contribute ideas for V3, emphasizing the importance of this initiative as they move towards 2026, with plans to develop a proof of concept by the end of next year.

### V3 API Design Updates

Robert explained the benefits of the V3 API, which include cleaning up deprecated APIs and improving user clarity, while ensuring gradual adoption without immediate disruption. Keith suggested clearly articulating the benefits and improvements of V3 to address potential concerns about its disruptive nature. Robert and Hendrik discussed updates to API design guidelines, including specifications for error types, non-basic types, and inheritance, aiming for consistency in design documents. The team also reviewed a new HIP that aligns with these guidelines.

### Bullion Fork Design Proposal

The team discussed a design proposal for high-volume entities, focusing on a single bullion fork in parent transactions. Ivan explained that while the HIP states this can be done for about 10 transactions, it would be easier to implement it for every type of transaction, with the SDK checking and throwing errors for unsupported transactions. The team agreed to keep this functionality at the transaction level, rather than derived transactions, and discussed testing challenges related to throttling, which Robert suggested consulting the performance team about. They noted that this feature is still a couple of releases away according to HIP1313.
