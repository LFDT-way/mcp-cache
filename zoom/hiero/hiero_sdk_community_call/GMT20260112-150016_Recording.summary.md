The team discussed restructuring their SDK community calls to include regular updates from maintainers and demos of new functionality. The group addressed challenges with GitHub integration for AI tools and discussed creating dedicated channels for specific concerns, with plans to share strategy documents and follow up on communication improvements.

## Details

### SDK Community Call Restructuring Plan

The team discussed restructuring the SDK community call to include regular updates from each SDK's maintainers, including demos of new functionality. Robert agreed to implement this change, with maintainers providing brief updates on their SDK's progress, issues, and blockers during the bi-weekly meetings. The group acknowledged that while not all updates may be relevant to every attendee, it would be valuable for the broader community to stay informed about advancements across all SDKs.

### Community Meeting Structure Reorganization

The team discussed how to structure their community meetings, with Hendrik suggesting that maintainers should add their updates to a shared agenda rather than following a alphabetical order. Keith and Hendrik agreed that while sprint planning should remain a private Hashgraph meeting, most other discussions and demos should move to the public community meetings. Robert will take this feedback to Simi, and Keith and Robert will explore whether to consolidate all sprint planning and syncs into the Monday community meeting.

### SDK Publishing Transition Plan

The team discussed transitioning the Rust and JavaScript SDK publishing from dual publishing to the Hiero ledger namespace only. Andrew proposed implementing this change by Monday, with preparation work happening on Thursday and Friday. Robert and the team agreed to proceed with this timeline, noting that existing SDKs would remain published while new releases would only be published to the Hiero ledger namespace. The change was confirmed to align with previously communicated plans, though specific communication details needed verification.

### Hiero SDK Community Communication Strategy

The team discussed creating a new Discord channel for the Hiero SDK community to facilitate communication and grow the Python SDK. Hendrik and Jessica created the "Hiero SDK Community" channel, and Sophie offered to help pin messages to direct users to the correct channels. Keith suggested developing a comprehensive communication strategy, emphasizing the importance of consistency and accessibility, and proposed using email as a primary communication tool, similar to other Linux Foundation groups.

### Discord for Apache Communication

Hendrik and Keith discussed the challenges and benefits of using Discord as a communication channel for the Apache Foundation and open-source projects. They agreed that creating a Discord channel is relatively easy, but maintaining it and gaining momentum is much harder. Keith emphasized the need for a clear strategy, such as posting agendas before meetings and ensuring SDK maintainers actively participate in the channel. Hendrik expressed hope that Discord could be the solution, but acknowledged the difficulty of requiring everyone to use the channel.

### SDK Communication Strategy Discussion

The team discussed communication channels for SDK maintainers and developers. Hendrik shared a two-page strategy document outlining how maintainers should handle questions from developers, particularly regarding GitHub issues and Discord channels. The group clarified that GitHub issues should remain the primary channel for specific SDK-related questions, while broader discussions could occur in Discord channels. Robert and Keith raised concerns about the workload for maintainers who might need to monitor multiple communication channels, but Hendrik clarified that maintainers should redirect questions to the appropriate channel rather than monitoring all channels themselves.

### Python Discord Community Progress

Sophie reported positive progress in the Python Discord community, which now has 11 members, and suggested that periodic check-ins and open-ended questions can help stimulate engagement. She emphasized that the Discord serves more as a social platform for casual interaction rather than a constant monitoring tool, and highlighted the benefits of maintaining an active presence. Sophie proposed reassessing the Discord's effectiveness in a few months to determine if additional support or changes are needed, while encouraging others to contribute by posting questions and participating in discussions.

### SDK Communication Strategy Discussion

The team discussed communication channels for SDK projects, agreeing to use a common SDK channel in documentation and dedicated Discord channels for individual SDK projects. Hendrik emphasized that while Discord is suitable for general questions, GitHub issues should be used for bug reports and feature requests. Keith raised concerns about an alternate communication strategy involving Slack, which Hendrik confirmed was an internal Hashgraph matter. Both agreed on the importance of stability in communication tools.

### Exploring Forums vs GitHub Discussions

The team discussed the pros and cons of different communication platforms, focusing on forums versus GitHub discussions. Andrew suggested exploring forums as an alternative to GitHub discussions due to their better searchability and indexing by AI and search engines. Hendrik and Keith agreed to investigate this further, considering the potential benefits of forums for organizing discussions and making content more accessible.

### GitHub Integration and SDK Challenges

The team discussed challenges with GitHub integration for AI tools, noting that Grok performs better than ChatGPT with their repository structure. Sophie highlighted ongoing issues with the Python SDK and requested more communication and support, particularly regarding developer engagement. Hendrik mentioned creating a strategy document to guide the management of other SDKs maintained by Hashgraph and contractors, with plans to share it internally later in the week. The group agreed to follow up on creating a dedicated Slack channel for Sophie's specific concerns and addressing the lack of first issues in certain repositories.
