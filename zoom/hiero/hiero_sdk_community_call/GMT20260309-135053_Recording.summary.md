## Details

### SDK Development and Testing Updates

The team discussed SDK updates, focusing on Java, Go, and JavaScript. Ivan reported that the Java lead was absent last week, but Go development encountered TCK issues with skipped tests. For JavaScript, they used the cooperation Hub for block note discoverability. Robert inquired about Evila's progress on implementing a crypto create load test for Solo, which Ivan explained was delayed due to Solo issues but should be fixed soon. Keith clarified that HIP1313 testing is not intended for CI but rather as a one-off end-to-end test to verify consensus node pricing curves, with Ty tasked to create an official test plan.

### Solo Tool Issues and Updates

The team discussed issues with Solo, a tool used for testing and deployment. Ivan explained that there had been problems with dependencies and CI, but these seemed to be resolved. Keith emphasized the importance of reporting any issues with Solo immediately, whether they occur on runners or locally. Sophie mentioned difficulties she had encountered with the README and documentation, which Keith clarified were due to the basic nature of the README and the availability of more comprehensive documentation. Angelina provided an update on ongoing issues with Solo on Windows 10, which she is working on with a roommate.

### Solo Platform Cross-Platform Challenges

The team discussed running Solo on Windows, which currently requires WSL2 on Ubuntu due to Docker configuration challenges. Angie reported ongoing issues with Jeremy's previous work on error messages in WSL, with no recent updates. Sophie mentioned problems with Solo on Mac, though the exact nature of the issues wasn't detailed. The team is waiting for Ty to specify the end-to-end test plan and transactions for Solo, while Ivaylo has developed new tests for crypt that will be presented in tomorrow's planning meeting.

### Testing and Bot Issues Discussion

Ivaylo discussed his work on testing, including a new testing soul and integration tests for JS, mentioning some debugging and enabling of forks. Sophie addressed issues with new bot accounts in the JavaScript SDK, explaining that while good first issues are not significantly impacted, there has been an increase in bot activity for these issues, which she has been managing by closing pull requests. She suggested relabeling or skilling good first issues to reduce confusion and proposed monitoring the situation further.

### GitHub Bot Management Discussion

The team discussed issues with GitHub bots, noting that around 50% of contributors are bots that request assignments despite failing checks. Sophie proposed making meetings 30 minutes shorter to increase accessibility for maintainers. Robert presented a new PR dashboard that automatically updates with check statuses and adds labels, potentially helping to identify and manage bot activity.

### Bot Pull Request Process Improvements

The team discussed challenges with bot pull requests, noting that bots cannot complete GPG signing and do not provide meaningful feedback. Sophie explained that unassigned issues can mislead contributors, so they are working on clearer labeling and assignment processes. Robert mentioned a new junior committer joining the C++ team, while Sophie reported on Python's progress, including the integration of TCK tests and the creation of a HIP description. The team agreed to continue iterating on their labeling system to better handle bot submissions.

### SDK v3 Collaboration Proposal

Hendrik presented a proposal for SDK v3, focusing on documentation and cross-SDK collaboration. He suggested creating a unified group of maintainers and committers for all SDKs, rather than treating them as individual silos. The proposal includes using code owners to ensure that PRs are reviewed by people with the appropriate language expertise, while allowing anyone to review README and test files. Hendrik emphasized that this approach would help the SDKs work more closely together and maintain high quality across all languages.

### SDK Cross-Review Access Proposal

The team discussed a proposal to allow maintainers of one SDK to review pull requests across all Hiero SDKs, with Hendrik sharing an example of how this could help bridge knowledge between different SDKs. Robert expressed concerns about giving full access to new maintainers across all SDKs, but Hendrik explained their solution through a new GitHub organization called "Hiero Hackers" which would serve as an incubator for new projects before they join the main Hiero organization. The team agreed to continue discussing this proposal, with Robert planning to follow up in a week, and Sophie suggesting that the junior committer role could be extended to 4-5 months while maintaining a 4-6 month requirement for committer status.

### V3 Class Hierarchy Restructuring Proposal

The team discussed the need to address the length of future meetings, though they agreed it would be challenging for the current session due to ongoing topics like new hips and pull requests on the SDK hub. Robert presented a proposal for restructuring the class hierarchy for V3, which Hendrik reviewed and provided feedback on, particularly regarding the use of protected methods in API definitions. They agreed that such methods should be reserved for implementation details and not included in the public API specification. Robert committed to revising the proposal and cleaning it up, while also planning to seek reviews from other maintainers, especially for the block node integration. Hendrik offered to schedule a follow-up meeting to discuss his comments in detail.
