## Details

### Book Node and SDK Updates

The team discussed recent work on the book node and SDKs over the past two weeks. They addressed issues with SO, fixed flaky tests, and improved the maintainability of the execute function in JavaScript. Mario created a swag bot that runs SDK tests and sends results to a SWAC channel to streamline the release process. The Go SDK had a problem with Lambda hooks, which was resolved in a patch release. The team also addressed a user's concern about a security fix, with Vander responding professionally to address the user's concerns.

### Security Issue and Bug Fixes

Ivaylo explained a security issue found by a Bug Bounty user that allowed malicious transactions to be signed without user knowledge. The team fixed this by implementing error checks, but CentX reported it as a breaking change. Ivaylo noted they haven't made any significant code changes and are waiting for more information from Rob regarding the breaking change claim. The team is also working on a PR in the Rust SDK and reviewing markdowns related to good first issues.

### V3 Developer Experience Improvement Proposal

Robert presented a new PR focused on improving the developer experience for V3 transactions by making transaction receipts and records more intuitive. He explained that the current V2 system presents all fields in transaction receipts, including irrelevant ones for specific transactions like account creation. The proposed solution involves creating typed receipts to show only relevant data while maintaining forward compatibility. Robert acknowledged potential concerns about breaking changes if new fields are added to transaction records in the future, but noted that this hasn't been an issue in the network's history.

### Receipt Transaction Record Architecture Discussion

Robert and Keith discussed a proposed new receipt transaction record architecture aimed at improving developer experience by only showing relevant fields based on the transaction type. Keith raised concerns about data consistency across different systems (SDK, Mirror node, and Hedera APIs), arguing that showing different data formats could create inconsistencies. Robert clarified that this is a proof of concept (POC) that would only show pertinent data to developers, and suggested that Keith could provide feedback by reviewing the PR.

### Genesis SDK Development Progress Review

The team discussed feedback from a user building an end-to-end dApp using the Genesis SDK, noting some documentation comments but no significant issues with the SDK itself. Ivaylo proposed updating issue templates to include requirements for running task build and task lint commands, as well as ensuring no unnecessary formatting changes are made in pull requests. Robert mentioned plans to implement initial security checks followed by automated workflow runs to catch build and linting errors more quickly. The team also noted they are waiting for Hendrik's Rust implementation and Nana's review of block node signatures, with a target implementation timeline of mid to late May.
