## Overview

The team reviewed progress on various SDK development work including Hiero hooks and transfer transactions across different language implementations. They discussed a new fee estimate query feature proposal and addressed concerns about team resources, particularly for the Python team, while also agreeing to improve meeting structures and documentation processes. The team explored upcoming changes to NPM token authentication requirements and discussed the implications of switching to GitHub-hosted runners, including potential costs and performance impacts.

## Details

### Hiero Hooks and Fee Proposal

The team discussed ongoing work on Hiero hooks, which are nearly complete but require testing and further work on transfer transactions. The Java SDK is nearly finished with its work, while the JS SDK needs changes to transfer transaction hooks that are currently under review. The team also reviewed a new proposal for a fee estimate query feature, which has been a long-standing community request, and Ivaylo presented a design document that is currently under review by Simi, Rob, and Ivanko.

### Team Challenges and Support Plans

Keith and Ivan discussed issues with Hiero hooks and agreed to follow up offline and through the client SDK team chat. Jessica raised concerns about the Python team needing more support and contributors, which Keith said he would follow up on with Simi and Hendrik. The team also discussed the need for a more structured meeting format with an agenda, and Jessica suggested creating a central location for agendas, which she had already proposed in an issue.

### Meeting Minutes Centralization Discussion

The team discussed centralizing meeting minutes and agendas, with Hendrik suggesting that TSC meeting minutes should be included in the governance repo to facilitate easier linking and rendering on the webpage. Jessica proposed creating a new repo specifically for agendas but expressed concerns about maintaining additional work. Hendrik proposed restructuring the governance repo to include a dedicated folder for meeting minutes and suggested using code ownership to manage access rights effectively. Keith raised a concern about granting write access to many people, and Hendrik explained that code ownership could be a solution to this issue.

### API Guidelines and SDK Standardization

Hendrik presented a pull request for API guidelines in the SDK collaboration hub, which aims to standardize API syntax across different languages. Ivaylo raised concerns about naming conventions differences between languages, particularly for getters in JavaScript. Hendrik explained his plan to create separate implementation guidelines for each SDK language after the main API guidelines are approved. He also shared the success of the Python SDK in attracting new contributors through Hacktoberfest and good first issue candidates, encouraging other SDKs to create similar opportunities.

### NPM Token Authentication Migration

Jessica and Hendrik discussed the upcoming changes to NPM token authentication, where regular tokens will be disabled and migration to trusted publishers is required. Jessica explained that this change, which will be implemented within a year, affects four repositories: DID SDKJS, local node, SDKJS, and Solo, as well as any other repositories planning NPM publications. The migration requires upgrading to NPM version 11.5.1 or later, though there were concerns raised about self-hosted runners' compatibility with trusted publishers, which Jessica needs to clarify.

### Self-Hosted Runners for NPM Publishing

The team discussed the need for self-hosted runners for publishing artifacts to NPM, with Hendrik questioning the necessity of these runners for SDK publishing. Jessica mentioned that some projects are still releasing under the Hashgraph name, which may be related to the use of self-hosted runners. The team agreed to have a conversation with Nathan's team and Roger about the need for self-hosted runners. They also discussed the potential cost implications of switching to GitHub-hosted runners, with Jessica suggesting they investigate this further with Y. Ivaylo raised concerns about the potential impact on CI speed if SOL runs were moved to GitHub-hosted runners. The team decided to explore the possibility of splitting up workflows to optimize resource usage.
