## Overview

The meeting focused on SDK updates and discussions around V3 development. Robert and Hendrik discussed the need for a meta-language specification to standardize APIs across different SDKs, aiming to improve developer experience and consistency. ## Details

### SDK Updates and Testing Progress

The team discussed SDK updates and collaboration hub PRs. Ivaylo reported progress on high-volume transaction testing for HIP1313, with plans to create custom tests if the Solo team cannot modify their framework. Keith suggested reporting test results in the HIP1313 Slack channel. The team also addressed issues with the playground examples, with Robert reaching out to Ed about broken examples. Keith offered to add Robert and Ivan to the dedicated Slack channel for Playground. For C++ and Swift, Robert updated hooks with new names and is working on automation improvements. The team will discuss the path forward for single maintainer repos at the TSC meeting tomorrow.

### SDK Maintenance and Progress Updates

The team discussed maintenance challenges across different SDKs, particularly for the Swift SDK where Robert is the only maintainer and Simi is looking to step down. Robert and Jessica plan to discuss this further and present a solution to the TSC meeting. Updates were shared on Java, Go, and Rust SDKs, with Ivaylo noting that receipt and record mechanisms were merged in Java and Go, and Dosi reporting progress on heap implementation and addressing a book query issue. Sophie reported on the Python SDK, mentioning the merging of the TCK server and efforts to improve review processes through automated labeling and spam guards, while also noting the need to address issues in base files and work on backwards compatibility.

### API Implementation and Error Prevention

Sophie and Robert discussed the implementation of a new API and the importance of ensuring that API names and types match the protobuf specifications to prevent errors. They also talked about issues with transaction records and the need to double-check core files for inconsistencies. Robert suggested that once the TCK server is implemented, it would help catch these inconsistencies. Sophie mentioned a pull request for fuzzing, which has already identified some problems with large H-bar values. Robert offered to give a TCK walkthrough in the upcoming Python community call on Wednesday, which Sophie welcomed.

### SDK Development and Community Updates

Robert and Sophie discussed the C++ and Python SDKs, with Robert offering to provide an overview of the SDK hub and its features. Hendrik presented PRs related to the version 3 SDK, focusing on namespace specifications and a proposed API for mirror node clients in Rust. The team discussed the need for more community awareness of the SDK hub and the ongoing work on the Hiero bounty for a Rust-based SDK.

### SDK Design and Implementation Review

Robert and Hendrik discussed the design and implementation of SDKs for V3, including a review of Mirror Node's OpenAPI implementation. Hendrik shared that he had created a pull request for improving the public API generated by the OpenAPI Code Generator. Robert mentioned his interest in restructuring the executable class hierarchy to better accommodate the various types of queries in V3. They also discussed HIP-1137, which aims to register non-consensus nodes on the network, and Robert expressed a desire to get it merged soon to allow for SDK development in the upcoming sprint.

### Empty Classes and Factory Methods

Robert and Hendrik discussed the implementation of empty classes and factory methods for handling different endpoint types in their software. They agreed that while the current solution might not be ideal, it would work for now and could be improved in the future with the release of V3. Hendrik suggested using static methods with default parameters or factory methods to create empty objects, which Robert found acceptable. They decided to merge the current changes and continue discussing language-specific solutions and documentation for future improvements.

### V3 POC and SDK Development

The team discussed the progression of V3, with Robert clarifying that it remains a POC for now, while Hendrik outlined efforts to create best practices for SDK public APIs. Keith emphasized the need for a check-in to ensure V3 aligns with 2026 goals and addresses user pain points, such as the "freeze" issue, which Hendrik explained V3 would address by preventing execution without prior freezing. The team agreed on the importance of aligning V3 efforts with improving the developer experience and user satisfaction.

### API Standardization for Developer Experience

Keith and Hendrik discussed the prioritization and benefits of the V3 work, focusing on creating consistent and better-looking APIs across SDKs to enhance the developer experience. Hendrik emphasized that the ultimate goal is to provide users with direct benefits through standardized, robust, and easy-to-use public APIs. Keith expressed uncertainty about how these efforts align with users' day-to-day experiences, but Hendrik clarified that the work aims to align with best practices for each language while ensuring consistency.

### Enhancing Hiero SDK Developer Experience

The team discussed the developer experience improvements in V3 of the Hiero SDK, focusing on making code more readable and simplifying common tasks like token minting. Hendrik explained that while V3 would create more work for SDK developers by requiring readable string representations, it would improve the user experience by making code more understandable. The team agreed on the importance of having a solid foundation in the core SDK before building additional layers, and Keith raised concerns about finite resources and the need to prioritize between V3 development and other initiatives like the enterprise SDK project.
