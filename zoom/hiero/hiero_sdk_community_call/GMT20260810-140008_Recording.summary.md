## Details

### Account Balance Query Deprecation Discussion

Keith led a discussion on the deprecation of account balance query functionality, scheduled for completion in September, and outlined two related SDK proposals: replacing ping functionality and introducing a new mirror node account balance query. Sophie confirmed she had created an issue for the Python SDK implementation and asked for clarification on following the proposal document, to which Keith confirmed it contained all necessary information. The team was reminded of the urgency of these changes due to downstream dependencies and the removal of the code from consensus nodes by November.

### TCK Code Implementation Discussion

Sophie discussed her recent exploration of the TCK code and sought clarification on its functionality, particularly regarding test flags and implementation across different SDKs. Mustafa explained that the TCK table flags indicate whether specific scenarios are implemented and that the TCK works in conjunction with SDKs to validate operations and catch regressions. The discussion covered the current implementation status across JavaScript, Java, and Go SDKs, with suggestions to expand TCK support to Python, Swift, and Rust. Sophie also raised questions about tracking HIPs using TCK tests and proposed creating issues to address these concerns, highlighting potential opportunities for community contributions to the TCK repository.

### HIP Tracking Across SDKs Discussion

The team discussed HIP (Hyperledger Improvement Proposal) tracking across SDKs, with Angelina presenting her manual board tracking system and PR for automating HIP status across different repositories. Keith mentioned an existing similar board created by Deanna that he would search for and share. Sophie suggested that while Angelina's PR was well done given current data structures, there could be opportunities for efficiency improvements if scope allowed for changes to data structures and test implementation. Keith proposed using the JavaScript SDK as a reference for cross-SDK feature analysis, suggesting AI tools could help automatically compare implementation status across different SDKs.

### HIP Implementation Tracking Challenges

Keith and Sophie discussed challenges with tracking HIP (High Importance Project) implementation status across multiple repositories. Sophie explained that while they don't have budget for AI tokens, they could potentially implement automated tasks using small data structure changes in the TCK to provide regular insights without manual AI interpretation. They also discussed the need to track not just HIP approval status but also implementation progress across different components like consensus node, mirror node, and SDKs, with Keith noting that even tentative release dates are difficult to maintain due to frequent delays.

### Hedera Integration for E-commerce System

Evan explored solutions for integrating Hedera into a digital twin e-commerce system, focusing on transaction speed and social commerce governance. Keith explained Hedera Consensus Service (HCS) as a potential solution for storing certificates of authenticity and discussed its capabilities, including handling quantum-resistant signatures within the 1024-byte payload limit. The team also discussed ongoing SDK development work across different languages, with updates provided on deprecation of account balance queries and TCK test completion for the Python implementation.
