## Overview

The meeting focused on discussing the development of version 3 of the SDKs, with a particular emphasis on REST API support and protobuf management. Robert, Hendrik, and Ivaylo debated the merits of providing both gRPC and REST API support for Mirror Node, ultimately deciding that gRPC should be the primary focus while maintaining existing REST API functionality. The team also explored the possibility of consolidating protobuf dependencies into a single repository, though concerns were raised about versioning and file organization. Sophie presented a proposal for expanding the Good First Issue program, suggesting the creation of a cross-SDK committee to help manage and create these entry-level contributions. ## Details

### REST vs gRPC API Decision

The team discussed REST API support for Mirror Node in V3, with Hendrik suggesting focusing on gRPC rather than REST due to compatibility concerns across different languages and frameworks. They agreed to keep the Consensus and Mirror Node SDKs separate initially, with Hendrik proposing to provide documentation and teaching materials about using existing tools like Swagger Code Gen rather than creating their own API. Robert noted that some Mirror Node functionality is already integrated into the Consensus Node SDK, particularly for address book queries and invalid node account handling.

### gRPC Focus for Mirror Node

The team discussed the decision to focus on gRPC rather than REST APIs for the Mirror node endpoints, following previous discussions where REST support was deemed unnecessary. They explored the possibility of modularizing the SDK to separate consensus node and mirror node functionality, with Hendrik emphasizing the need to understand version compatibility between different node types. The team agreed to gather more information about the interdependencies between Mirror node, consensus node, and block node, particularly regarding versioning and protocol buffer compatibility.

### Centralizing Protobuf Repository Structure

Robert and Hendrik discussed the need to clarify the structure and usage of Protobufs across different repositories, particularly for SDKs. They agreed to create a centralized Protobuf repository that would include necessary files from Consensus Node and Mirror Node, while potentially removing unused or redundant files. Hendrik emphasized the importance of documenting folder structures and creating clear guidelines for SDKs to access Protobufs. They also discussed the need to align versioning across different components and to verify the actual usage of certain Protobuf files.

### Cross-SDK Good First Issue Committee

Sophie proposed creating a cross-SDK Good First Issue Committee to help offset maintainer workload and improve the process of creating and assigning these issues. The committee would have four key responsibilities: setting up good first issues, creating candidates based on specific SDK requirements, handling assignments, and providing soft approvals. Hendrik and Robert agreed with the initiative but emphasized the importance of having committee members with language-specific knowledge, though not necessarily as maintainers. They discussed starting with a few SDKs that are interested in participating, with Robert planning to reach out to maintainers and invite them to a meeting the following day.
