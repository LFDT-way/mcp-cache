## Overview

The Hiero Identity Community Call focused on addressing challenges with AI-generated pull requests and contributor verification in open source projects. The group discussed solutions for preventing spam from AI agents while maintaining an inclusive environment for new contributors. Alex presented a proposal for a Hiero onboarding process that would require contributors to prove ownership of a GPG key and link it to their GitHub identity. The community explored various approaches, including reputation systems and tying identities to DNS records, but agreed that immediate solutions needed to be practical and implementable without relying on future infrastructure. The discussion concluded with plans to share the onboarding proposal with the Linux Foundation mentorship program and the Hashgraph AI working group.

## Details

### Hedera DID Method Updates

The meeting was the monthly Hiero Identity Community Call, where participants discussed various identity initiatives on the Hedera platform. Keith explained that the call's purpose was to discuss different community initiatives, and he shared updates on the DID Hedera method. He mentioned that the Decentralized Identity Foundation (DIF) had a working group called the DID Methods Working Group, which evaluates and provides approval for certain DID methods. Alex was working on submitting DID Hedera to this process, which involves meeting specific criteria and running tests.

### Hedera DID Method Standardization Update

Alexander provided an overview of recent contributions to W3C repositories, including submissions to the DID Methods Registry and passing the Decentralized Identity (DID) Document Elective Test Suite. He also submitted a proposal for standardizing the Hedera DID method, which is currently under review by the working group. Keith explained that the goal of this effort is to achieve a DID-recommended method, providing a seal of approval for the community to trust Hedera's DID implementation. The discussion highlighted the challenges in the decentralized identity space due to multiple competing standards from different organizations.

### A2A Agent Integration Demo Update

Alexander presented updates on a new demo folder showcasing an integration between A2A agent-to-agent protocol and OpenID for VP for in-task authentication/authorization. The demo, hosted under the DSR GitHub organization, features a simple A2A agent implementation that works with OpenAI and allows agents to request identity verification through a mobile app using the Hacker Wallet and DIDCOM protocol. Keith noted that this ties into broader discussions about implementing identity infrastructure for specific workflows, particularly in AI, and mentioned challenges with AI-generated PRs affecting projects like Hiero and the Linux Foundation's efforts to address this issue.

### Identity Verification for Tokenized Assets

The group discussed identity requirements for projects like stablecoins and real-world tokenized assets, with Keith noting the community's awareness of the need for identity rails but limited ideas on implementation. Alexander shared plans to submit a proposal for the LF mentorship program to build a prototype of a contributor verification mechanism using Hacker, which would verify contributors' GPG keys bound to verifiable credentials. The discussion touched on challenges in preventing AI agents from using human identities, with Ty suggesting a focus on deterministic identity and reputation rather than just proof of personhood. Keith proposed using biometric processes on existing phone security features as a technological solution to enhance identity verification for PR submissions.

### AI Contribution Verification Strategy

The group discussed challenges with AI-generated contributions in open source repositories, particularly focusing on how to handle spam PRs and maintain repository quality. They aligned on implementing a practical solution involving GPG key verification and a Hiero onboarding process as a starting point, which could be tested through the Linux Foundation mentorship program. The discussion explored various approaches including reputation systems and DNS-based identity verification, but concluded that the proposed GPG-based solution was implementable soon without requiring additional infrastructure. Alexander agreed to submit a proposal for the mentorship program and share it with the group for further discussion.
