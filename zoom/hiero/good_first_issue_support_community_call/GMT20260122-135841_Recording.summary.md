## Details

### Waiting for Sophia's Return

The team discussed the need to wait for Sophia's return to participate in a discussion, with concerns raised about meeting deadlines, particularly regarding Google's strict adherence to dates. Robert and Angelina agreed to hold off on sharing templates until after consulting with the JavaScript community about the GFI pipeline, with Angelina having already created a temporary version for review. ### Discord Issue Submission Process Debate

Robert and Angelina discussed the use of Discord channels and templates for issue submission. They debated the merits of using candidate templates for different issue levels versus having a single community issue template that requires maintainer triage. Robert expressed concern about community members incorrectly using advanced templates and proposed having a streamlined process where all community-submitted issues are initially labeled as "pending triage" before being reviewed and assigned by a maintainer.

### Streamlining Community Issue Submissions

Angelina proposed three ideas for managing issue submissions: restricting submissions to GFI team members and maintainers, implementing templates for different issue categories, or creating generic templates for community members to forward to maintainers. Robert preferred the third option, which would allow community members to submit issues using standardized templates, while giving maintainers the final say on issue classification. They discussed the potential workload for maintainers and agreed that while community submissions are valuable, the process needs to be streamlined to ensure efficient triage and classification of issues.

### Website Issue Classification Strategy

Angelina and Robert discussed increasing the visibility and engagement of the website and Python SDK repositories. They explored ways to make community members more comfortable submitting issues, including potentially adding bug and feature candidate templates and having the GFI support team help classify issues. Robert suggested renaming the team to "Issue Support Team" if they allow the support team to classify non-GFI issues. They also considered how to handle community-submitted issues that need reclassification, with Angelina proposing to leave the original description while encouraging additions or clarifications.

### Bot-Driven Issue Template Standardization

Angelina and Robert discussed implementing a bot to streamline the process of converting candidate issues into proper issue templates. They proposed that once a maintainer approves a candidate issue, the bot would automatically update its label and post it publicly. Robert suggested using existing templates and labels to standardize the process, with the bot triggering after specific labels are added. They agreed that the initial templates should be similar across different issue levels, with the bot potentially adding comments to clarify the issue's level and required skills.

### Bot Workflow for Issue Classification

Robert and Angelina discussed implementing a bot workflow for issue classification in a code repository. They agreed that the bot would use existing templates for intermediate and advanced issues, and that the classification of issues as ready-to-work-on would require human intervention to trigger the bot's message. They decided that either GFI team members or maintainers could be responsible for classifying issues, with the important consideration that classifiers should have domain-specific knowledge for accurate classification. They concluded that they would create a draft example template and write-up of the proposed workflow for team feedback.

### Bug Report Template Refinement

Angelina and Robert discussed refining a bug report template, focusing on essential elements like acceptance criteria and steps to reproduce. They decided to create separate templates for bug reports and feature requests, with the bug report template requiring a clear description and steps to reproduce. Angelina encountered syntax errors while editing the template and received help from Aditya to resolve them. They agreed to leave the top section of the template as "in progress" for future refinement.

### Issue Report Template Design Discussion

Angelina and Robert discussed the design of an issue report template. They agreed that while labels are not strictly necessary, they should be included in the YAML file for the template to automatically apply the "needs triage" label when an issue is submitted. Robert suggested that this would help maintainers easily identify which issues require attention. They also discussed whether a proposed solution should be required for issue reports, with Angelina suggesting it could be optional for more complex issues.

### Issue Template Access Policy Update

Angelina and Robert discussed changes to issue templates and permissions. They agreed to keep the good first issue and beginner templates available for maintainers and the support team, while allowing community members to submit any type of issue. Robert suggested exploring permissions for templates, ideally limiting community members to feature requests and bug reports. They decided to allow community members to submit any issue, with maintainers determining the difficulty level and appropriate labels after triage.

### Issue Triage Workflow Automation

Robert and Angelina discussed a new workflow for issue classification and triage. Robert explained how community members would submit issues with templates that add a "needs triage" label. The maintainers would review these issues, request missing information, and classify them as beginner, intermediate, or advanced. Once classified, a bot would update the issue title and add appropriate labels. Angelina expressed confusion about how this would work for different difficulty levels, but Robert clarified that the process would be similar for all levels. They discussed the role of the bot in automating certain tasks and the need for maintainers to manually add certain labels.

### Template Permissions and Issue Classification

Robert and Angelina discussed template permissions and issue classification for their project. They agreed to create three templates for community members: one for bugs, one for features, and one for tasks. Robert suggested using GitHub's issue types to classify different types of submissions. They decided to present their ideas to Hendrik, Sophie, and other maintainers for feedback. Angelina offered to add Robert as a contributor to the repository so he could make tweaks to the issue report template. They planned to continue their discussion in Discord.
