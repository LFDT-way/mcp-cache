The team discussed implementing a limit of 5 good first issues (GFIs) per contributor in the C++ SDK repository to encourage contributors to progress to more challenging issues. They explored the possibility of using CodeRabbit or other AI tools to automatically generate GFIs from PR reviews, but Daniel reported that CodeRabbit's current limitations make it unsuitable for their needs. ## Details

### SDK Development Status Discussion

Robert discussed the status of the Go and Rust SDKs, noting that they appear to be progressing independently. He proposed implementing a limit of five good first issues for specific repositories, as some contributors have mastered the workflow and may not need to continue taking beginner issues. No objections were raised to the proposed limit during the discussion.

### Contributor Issue Limit Implementation

The group discussed implementing a limit of five good first issues for contributors before advancing to more complex tasks. Angelina noted that while this limit seemed reasonable, it could impact new contributors without university backgrounds who might need more practice. Daniel agreed with the limit, suggesting that after completing five good first issues, contributors would be better equipped to handle more complex tasks and would be redirected to beginner issues for any remaining workflow questions.

### Good First Issues vs Beginner Issues

Robert discussed the distinction between good first issues and beginner issues in contributing to a project. He explained that good first issues encourage exploration of the codebase and learning workflows, while beginner issues involve more direct guidance. Robert emphasized that providing exact instructions in beginner issues might not help contributors develop the skills needed for long-term contributions.

### Good First Issues Limit Implementation

Angelina and Robert discussed implementing a limit of 5 good first issues across multiple repositories including C++, Swift, Java, and JavaScript. Robert agreed to start with implementing this feature in C++ first, as that's where he noticed the issue occurring. They also briefly touched on a previous discussion about using CodeRabbit for good first issues, though the specific details and ownership of that idea were unclear from the transcript.

### Bot Investigation for Issue Creation

Daniel explained that he investigated the possibility of using a bot to automatically create good first issues and then manually create beginner, intermediate, and advanced issues. He discovered that QuadraBit, the tool being considered, has limitations including the inability to gather a complete diff of the repository and requires the CodeRabbit client to be installed on the organization. As a result, while some automated issue creation based on PR reviews is possible with QuadraBit, creating comprehensive good first issues across the entire repository is not feasible with the current tool version.

### AI Review Process Discussion

Daniel explained that using a different LLM for AI reviews is possible, as there are other organizations that use GPT for tokenization. Robert shared his approach of using AI to help with PR reviews by converting non-blocking comments into good first issues for minor changes that don't block merging.

### AI-Generated PR Issue Automation

Angelina proposed an idea to have AI automatically create issues from unaddressed concerns in merged PRs, which Daniel confirmed was possible with Kodravit. Angelina expressed her goal to make the process as automatic as possible to decrease the workload on the team, allowing them to focus more on beginner, intermediate, and advanced issues.

### File Inconsistency Script Demonstration

Daniel demonstrated a script for checking file inconsistencies but noted that it lacked AI capabilities and would need automation and intelligence to be more effective. Angelina suggested researching alternative solutions, potentially involving Co-Pilot or finding additional team members interested in exploring options outside of Code Rabbit.

### Bot Implementation Discussion Meeting

The team discussed implementing a bot similar to Copilot, with Priyanshu suggesting they explore CodeRabbit as an alternative since it provides a diagram of changes and allows for prompting code directly in the main repository. Angelina proposed conducting research on how other repositories use similar tools, with the team planning to reconvene next week to share findings and discuss potential implementation approaches. Robert noted that while CodeRabbit has a client-side version without limitations, further testing would be needed to assess its feasibility, and Daniel suggested Copilot as the most viable substitute if CodeRabbit doesn't work out.
