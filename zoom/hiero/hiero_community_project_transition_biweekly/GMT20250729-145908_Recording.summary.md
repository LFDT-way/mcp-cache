The meeting focused on transitioning projects to Hiero, including the presentation of two new project proposals and a pre-release version of the Direct Light CLI tool for environment management. ## Details

### Hiero Project Transition Discussion

The meeting discussed the transition of projects to Hiero, with Hendrik introducing two new project proposals: the Hedera CLI and a Docker environment project. Michiel was set to present on transitioning the Hedera CLI to Hiero, but the meeting was running long due to the TSC meeting, which had been ongoing for over an hour. The group acknowledged that these projects had not yet been moved to the TSC and presented there, but were expected to be considered in the near future.

### Direct Light CLI Tool Introduction

Michiel presented a pre-release version of the Direct Light CLI tool, which simplifies environment management for Hedera projects by automating repetitive tasks and streamlining testing environments. The tool supports account and token management, smart contract integration, and script blocks for chaining commands and storing variables. Michiel explained that the tool is being explored for integration into the getting started documentation and plans to onboard a dev shop to enhance its features and production readiness.

### Tool Voting and TSC Approval

The team discussed voting on a tool, which needs to be sent to the TSC for approval. Hendrik will add the voting process to next week's agenda, which is scheduled for Tuesday at 4 PM. Michiel noted that a delay of one or two weeks for early marketing is not a big issue. Hendrik confirmed he has added both project proposals to the agenda for next week, and Jessica had no immediate questions about releases and deployments.

### Charter Governance File Review

Jessica and Hendrik discussed the changes made to the governance file for the charter, which had different formatting from the original version in the Hiero repo. They clarified that the content was the same but needed to be reviewed for any discrepancies. Roger provided a tip on how to compare the versions more easily. They agreed to review the changes after the meeting and then forward the correct version to the TSC for approval.

### Java Project Migration to Hiera

Hendrik discussed migrating a Java project to Hiera and the challenges of managing release processes, including the use of JReleaser and Maven Central publishing. Nathan and Roger emphasized the need for a fully automated release workflow before the project can be transferred to Hiera, highlighting the importance of using Gradle and GitHub Actions. They clarified that community projects must meet specific requirements, including having workflows in place, and that support from Roger's team will be limited to assisting with credentials and organizational-level configurations.

### Solo Docker Project Discussion

The team discussed a solo docker environment project, with Roger expressing concerns about it competing with the Solar Roadmap and suggesting it should be shut down. Hendrik defended the project, citing its potential benefits for enterprise application testing. Nathan and Jeromy explained that solo already supports test containers through a quick start command, with plans to incorporate test containers into solo's end-to-end testing in the future. The team agreed to continue the discussion in person next week, with Hendrik and Jessica planning to move the project to Hiro.

### Project Alignment and Communication Challenges

The meeting focused on a conflict between Hendrik and the Solo team regarding a project implementation. Hendrik expressed frustration that his work was being dismissed without proper communication, while Nathan and Roger emphasized the need to align with the Solo roadmap and integrate directly into the Solo project. The group discussed the potential for better collaboration and communication, with Roger suggesting a need for more engagement through community calls and internal discussions. The conversation ended with an agreement to continue the conversation elsewhere, as the current project proposal was deemed inappropriate in its current form.
