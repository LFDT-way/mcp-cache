## Agenda

Discussion, questions and concerns on community driven project's transition into hiero-ledger

## Overview

The team reviewed various repository transfer issues and discussed the status of multiple projects including Hedera cryptography and Hashgraph transfers. They addressed documentation improvements for contributor roles and maintainership processes, particularly focusing on clarifying terminology and updating README files. The team also explored GitHub review processes and discussed ways to improve documentation to help external users better understand the approval and contribution workflows.

## Details

### Repository Transfer and Legal Review

Jessica and Hendrik discussed the status of several repository transfer issues, noting that many old issues marked as Hashgraph transfers could be closed. They reviewed the Hedera cryptography repo, which was approved but pending legal review by Truligal. Jessica agreed to follow up with Miguel regarding the Hedera CLI project, while Hendrik confirmed there were no blocking issues. They also discussed the Hashgraph online standards SDK, which was awaiting input from Michael. Keith joined briefly to mention that he would need to transition Hedera repos from Hashgraph to Hiero at some point, though the specifics of the transition were still to be determined.

### Improving Maintainer Documentation Process

Keith and Jessica discussed the process of becoming a maintainer in Hiero, which involves making contributions to the project and being elected by current maintainers. Jessica explained that the information is documented in the "roles and groups" file, but Keith found it difficult to locate. They agreed to simplify and improve the documentation by adding an index or more intuitive naming to make it easier for new contributors to find the information.

### Updating README for Governance

Jessica and Keith discussed the need to add a "Contributing" section to the README file for the HIPs repository, as it currently lacks information on how to become a maintainer. Jessica offered to open a pull request to propose the addition of this section, and Keith agreed that the README should be updated to include governance information similar to other repositories. They also noted that the file name might not be intuitive enough and suggested updating it for clarity.

### GitHub Permissions and Role Clarification

The team discussed terminology confusion around contributors, committers, and maintainers in YAML files and GitHub permissions. Andrew clarified that while the YAML file uses different terms (members and maintainers) for CLO Warden's automatic team updates, the key distinction is between contributors (who have read access) and maintainers (who have additional permissions to influence repository direction). Jessica suggested that project roles can be explored through a test project's team building feature to better understand the different permission levels.

### GitHub Review Process Improvements

The team discussed GitHub review processes, particularly for the governance repo. Keith raised concerns about how confusing the approval process might be for external users, noting that even with explanations, it could be difficult for newcomers to understand who to contact for approvals. Andrew explained the code owners file system and review requirements, while Jessica suggested working on publishing more documentation to help users understand these processes. The team agreed to continue this discussion in their next docs call or through direct communication on Discord.
