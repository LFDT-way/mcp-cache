## Details

### Hedera Network Transition Plan

The meeting focused on transitioning from Hedera network's current record streams through buckets to mirror nodes to a new system using block streams and block nodes feeding mirror nodes with data. Keith explained that this represents a significant shift and emphasized the importance of clear communication to the mirror node operator community. Mark, the PM for block nodes and block streams, was set to provide an overview of the changes and their implications for mirror node operators during the session.

### Block Stream Technology Presentation

Mark presented a new block stream technology comprised of three HIPs aimed at improving the current system where mirror nodes access network output through public cloud buckets. The new system addresses several issues including reducing end-to-end delays from 2-second buffering, consolidating multiple streams into one unified output, and offloading state-based services from consensus nodes to block nodes. Mark explained that the block stream technology sends block items in real-time as transactions are processed, eliminates duplication across previous streams, and allows for more efficient data processing while maintaining a state database similar to consensus nodes.

### Cryptography Stack Implementation Overview

Mark explained the new cryptography stack being implemented, which includes aggregated threshold proofs (TSP) that replace individual RSA signatures from each node, allowing for a single network-wide signature that can be verified more efficiently. He detailed three components of the system: BLS (used for signature aggregation), HINTS (which provides weighted shares based on consensus weight), and recursive SNARK proofs (RAPS) for address book authorization. The process works by verifying the RAPS proof first to confirm the current address book, then generating a BLS-HINTS block proof where nodes with weighted signatures must reach a threshold before a block is considered valid.

### HINTS and RAPS Verification Process

Mark explained the verification process for HINTS and RAPS proofs, highlighting that it is complex but involves low-cost verification due to upfront work done by nodes. He detailed the new Block Streams data format, which allows for self-contained, independently verifiable blocks and optimized data consolidation, including event and state data. Mark described the structure of block items, such as headers and transactions, and explained how blocks are linked cryptographically and can include state proofs with low verification costs. He also introduced a new node type, the block node, and defined Tier 1 and Tier 2 block nodes, emphasizing the critical role of Tier 1 nodes in maintaining network health.

### Block Nodes Implementation Strategy

Mark explained the implementation of block nodes, describing two tiers: tier one block nodes handle primary ingestion and consensus processing, while tier two block nodes receive data from tier ones and distribute it to mirror nodes and applications. He outlined the benefits for mirror node operators, including reduced costs due to integrated sidecar information and elimination of egress fees on bare metal machines. Mark detailed the current deployment progress, noting that version 76 will be released on August 19th to begin publishing block nodes, with version 77 scheduled for September to include TSA credentials.

### Record Streams to Block Streams Upgrade

Mark explained the upcoming upgrade from record streams to block streams, scheduled for completion by the end of the year. He outlined the requirements for mirror node operators, including upgrading to version 163.0 and configuring pre-grant read access to new backup buckets. Mark recommended continuing to upgrade to newer versions as they are released and encouraged testing in PreviewNet and TestNet environments. The cutover process was designed to be seamless for node operators, with confirmation available through the API once the transition is complete.
