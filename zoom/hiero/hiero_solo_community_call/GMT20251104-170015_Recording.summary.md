## Details

### Software Stability and Integration Testing

Alex and Jeromy discussed the stability issues with a software version and the benefits of using Cube Control for certain functions. They agreed to continue testing the latest version, 48, and to investigate potential issues in their pipelines that may be related to the integration of block nodes with MirrorNode.

### Performance Test Implementation Discussion

Jeromy and Alex discussed a unique use case for a performance test that was previously implemented but has since been removed from Solo. They addressed a community member's inquiry about running performance tests and emphasized the need to clarify that the example was specific to their scenario. Jeromy explained their process for compiling and building Docker containers locally for block nodes, which involves sideloading the container into Kind and potentially overriding values files. Alex acknowledged this approach and mentioned a new team member, Angelina Campolini, joining the club.

### SDK Progress and Development Updates

Alex and Jeromy discussed the progress of various projects, including the Python SDK, where Angelina is working on fixing the node account ID feature. They noted that the Python SDK is catching up with other SDKs, thanks to contributions from new and experienced developers. Jeromy mentioned that the team is working on the Network Load Generator and aims to complete it by the end of the year. They also highlighted the success of version 48, which reduced the memory footprint and improved compatibility with GitHub-hosted runners.

### Solo Deployment Automation Feature Demo

Jeromy demonstrated the one-shot deployment feature of Solo, which automates the setup of a fully deployed environment with a consensus node, relay, mirror node, and explorer. He explained that Solo can detect and install necessary tools like Kind, Podman, and KubeControl, and pre-generates consistent accounts similar to LocalNode. Jeromy also showed how to use the Hardhat example in Solo deployment and mentioned plans to add hyperlinks and integrate LocalNode fully into the system.

### Streamlining Advanced Deployment Tools

Jeromy and Angelina discussed the implementation of advanced functionality for developers without overwhelming the flag list. They introduced a new tool called "one-shot Falcon" that simplifies complex deployment processes by allowing configurations to be set in a values file, reducing the need for multiple command-line flags. Jeromy explained that this tool is not yet fully ready but provides a more streamlined approach to managing advanced deployments. Angelina mentioned that the team is not currently using "one-shot" and will bring this up with Sophie Bullock, who has been helpful in maintaining and reviewing the work.

### Project Migration and Testing Strategy

Jeromy discussed the potential benefits of switching to Falcon and building a values file to simplify a project, but raised concerns about maintaining old code and the need to eventually stop supporting older versions. He also mentioned that the code might be better suited for its own shell file for better syntax completion and editing. Jeromy expressed uncertainty about the future ownership of the project and the GitHub solo action, which was initially developed by his team but later moved to a side project. He concluded by discussing the order of running unit and integration tests for solo deployments, suggesting that unit tests should be run first for faster feedback.

### Solo Memory Optimization Planning

Jeromy discussed plans for reducing Solo's memory footprint, aiming to lower it to levels that would allow it to run on systems with 16GB of RAM, such as GitHub self-hosted runners. He mentioned ongoing work to integrate TSS (Transaction Signing System) and block node, as well as plans to refactor the codebase to improve development and potentially reduce bugs. Angelina expressed interest in contributing to addressing the existing issues in the repository, and Jeromy encouraged her to review the tickets and provide clarity where needed.
