### Hiero Subproject Naming Guidelines

David presented guidelines for subproject naming within Hiero, emphasizing the importance of using "Hiero" as a prefix to ensure trademark protection. He explained that while this practice has been informally followed, it is now being documented to provide clarity and guidance for future subprojects. David noted that while the full name should be used initially (e.g., "Hiero Heka"), subsequent references can use the short version ("Heka").

### Trademark Protection for Sub-Project Names

David explained the limitations of using trademark protection with sub-project names, emphasizing the need for due diligence to avoid obvious conflicts. He mentioned that while using "Hiero" in a sub-project name provides some protection, it's important to check for existing uses in similar spaces. David also noted that this information has been documented on the wiki for reference and encouraged anyone with questions to reach out to him or Jessica for advice. Hendrik asked about the use of spaces in naming conventions, specifically questioning the use of product names like "Hicke identity platform" and "solo" instead of technical descriptions in GitHub repositories.

### Sub-Project Prefix Guidelines Discussion

David and Hendrik discussed the use of prefixes for sub-projects, clarifying that not all items require the prefix, especially for documentation like roadmaps. They agreed that for new repositories, the prefix should be included, but existing repositories might be grandfathered without changes to avoid disruption. David suggested updating the title of the Hiero Heka Identity Platform page to reflect the full name.
