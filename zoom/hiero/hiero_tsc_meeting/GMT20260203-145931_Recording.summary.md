### HIP Proposals Node Registry Review

The meeting focused on reviewing two HIPs (Hierarchical Identity Protocol proposals) that are ready for presentation. Joseph presented HIP 1137, which aims to create a node registry on-chain for non-consensus nodes like mirror and relay nodes, allowing users to discover and connect to registered nodes through exposed endpoints. Nana was scheduled to present HIP 1357, though the transcript ended before her presentation began. Michael Kantor asked about node discovery methods, but the discussion was cut off.

### Protocol Structure and Reward System

Joseph presented on the structure of the protocol and mentioned the addition of mirror node endpoints for querying information, along with block nodes and RPC relays. Michael suggested considering using the Hiero consensus service for registries, but Joseph noted that HCS data is not stored in state, making a native network solution more suitable. Nana explained HIP 1357, which extends the reward system for consensus nodes to include block nodes, ensuring that node operators are compensated for their service.

### Consensus Node Reward Prioritization

Nana explained that consensus node rewards take priority over block node rewards, and operators must be eligible for consensus node rewards to receive block node rewards. She clarified that the account balance for consensus node rewards should always be sufficient to cover payments. Alex raised concerns about the operational aspects of reward distribution, particularly in networks like Hedera where there may not be enough revenue to cover both consensus and block node rewards. Nana acknowledged the question and noted the difference between the specification and operational aspects, promising to think further on the matter.

### TSC Approves Hiero Identity Platform

The TSC discussed several key topics including block node and consensus node incentives, with Nana agreeing to explore configuration options for incentivizing consensus nodes at a higher rate than block nodes. The team approved a new Hiero Identity Platform project proposal with a 7-0 vote, though the naming convention still needs to be determined. The group also discussed merging language-specific SDK maintainer and committer groups into broader teams, with Robert and Sophie raising concerns about code review capabilities across different SDKs. Sophie proposed creating junior committer calls to support new contributors, particularly for the Python SDK where there is a 6-month lead time for training committers and maintainers.
