## Details

### Hiero Project TSC Meeting

Hendrik opened the TSC call for the Hiero Project and welcomed attendees, explaining that the calls are public and recorded. He mentioned that the next topics would include updates on TSC elections and HIP-1, which aims to make the Hiero improvement proposal more vendor-neutral. Hendrik also requested Alex's Discord handle to add them to the TSC group.

### TSC Election and HIP1 Updates

Jessica announced that nominations for the upcoming TSC election started on August 25th and will close on September 8th, with three nominations received so far. She outlined the voting schedule: the first round will take place from September 9th to September 20th for all eligible maintainers, followed by a second round from September 21st to October 2nd for non-voted candidates, with results announced on October 6th. The meeting then transitioned to discussing HIP1 changes, with Hendrik noting that the TSC and others were given a week to review the proposal, which was scheduled for voting that day.

### HIRO Governance and Licensing Discussion

Alex raised a question about whether changes made by network operators outside the HIRO governance process would still need to be contributed back under Apache2 license terms. Leemon clarified that while Apache licenses cannot require contributions back, the project would use build flags to maintain a single branch while allowing different configurations for features approved by different organizations like Hedera and HIRO. The discussion focused on preventing code forking while allowing organizations to implement and use different features through build configuration rather than separate repositories.

### Modular Consensus Node Approach

Hendrik proposed a modular approach for the Consensus Node that allows network operators like Hedera to implement custom services while maintaining flexibility through feature flags and build configurations. Leemon clarified that both feature flags and build flags would be available to control which code is included in the compiled jar files, with different configurations for different organizations. Alex confirmed that this approach addresses his concerns about code integration, and Hendrik indicated they would proceed with voting on the proposal.

### HIP 1535 Clipper Protocol Approval

The team discussed and voted to approve HIP 1535, which implements the Clipper communication protocol for Hiero. Richard presented the detailed specification and technical implementation, explaining how Clipper enables direct communication between ledgers using state proofs and connector entities to handle payment for message transmission. The group clarified that while the initial implementation is being added to Hiero, the protocol specification, smart contracts, and ledger-independent components will eventually be moved to an LFDT lab to maintain industry neutrality. Diane requested more clarity on the separation between the industry-neutral protocol and the Hiero-specific implementation, and the team agreed to continue discussions online with plans for a potential vote on the HIP in the next meeting.
