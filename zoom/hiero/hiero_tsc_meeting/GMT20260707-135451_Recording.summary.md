### Hedera Improvement Proposal Process Overview

Michael Garber presented an overview of HIP (Hedera Improvement Proposal) process and types. He explained that HIPs are design documents for submitting ideas about standards or code changes to affect how the Hedera network operates or how people build on it. The presentation covered different types of HIPs including standard track (core, service, mirror/block node, and application), informational, and process HIPs, with the key distinction that only standard track HIPs that touch the code base require community votes. Michael outlined the process starting with an idea, checking for duplicates, submitting as a draft, undergoing review and iteration, and potentially going through approval phases both in HyroTSC and TechCom before implementation.

### HIP Approval Process Discussion

Michael Garber explained that while HIP approval typically takes 6-9 months from acceptance to implementation, the new open source community effort may potentially speed up the process. He clarified that while technically anyone could contribute engineering effort to HIPs, including consensus layer changes, Hedera maintains a decision matrix to determine which features get activated on the main network. Hendrik and Sophie raised concerns about security and review processes for consensus layer contributions, with Hendrik suggesting that requiring multiple reviewers from the community maintainer group might be necessary to ensure security while enabling more community contributions.
