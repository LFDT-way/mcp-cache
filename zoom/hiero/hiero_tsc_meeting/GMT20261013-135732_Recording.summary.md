## Details

### TSC Elections and OpenVTC Demo

The meeting covered two main topics: TSC elections results and a demonstration of the OpenVTC project for project security. Jessica announced that Hendrik and Richard were elected as new TSC maintainers, and the TSC will now vote on selecting a third candidate from among Piotr, Suetzi, Sophie Bullock, and Stoyan Panayiotov. Hart Montgomery and the team demonstrated the OpenVTC project, which provides a decentralized trust model to replace the current PGP Web of Trust system used by the Linux kernel. The demonstration showed how developers can join verifiable trust communities, manage digital identities, and access repositories through a CLI tool and mobile keyring application.

### Keyring Community Onboarding Demo

Brendan and Alberto demonstrated Keyring, a React native app for iOS and Android that facilitates community onboarding through open standards and open source technology. The demo showed the vetting flow where a community member (Bob) can invite someone new (Alice) to join by verifying their identity in person through QR code scanning. The process includes creating different personas for different communities and granting vetting rights to approved members who can then invite others to join.

### Real-Time Verification System Demonstration

Alberto and Hendrik demonstrated a real-time verification process using Keyring and confirmed that Hendrik's code matched correctly. Alberto then showed how the system would work in person, including checking IDs and verifying locality through Bluetooth communication. Glenn presented upcoming features including data rooms, AI memory for communities, and secure messaging capabilities that would allow community members to use trust tasks, access data rooms, and communicate through an integrated chat interface.

### VTC Community Information Sharing Protocol

The meeting focused on clarifying how information is shared within the VTC community using persona DIDs and the Keyring app. Glenn explained that in the current demo setup, only basic information like the legal name is shared during the vetting process, and no additional details are visible to community members unless specifically requested through consent records. Diane and Hendrik asked about organization affiliations and GitHub profiles, with Glenn confirming that while these can be linked to DIDs, they are not automatically shared with the community unless explicitly required for access to specific repositories or communities with more stringent verification requirements.

### GitHub-VTC System Integration Demo

Glenn demonstrated how to link a GitHub account to the VTC system, showing it could be done easily through the tool interface. Keith raised concerns about governance requirements, asking about policies needed for implementation from scratch, to which Glenn responded that while initial setup would be required, the system offers customizable configurations and ceremonies to handle various verification processes. Glenn also confirmed that additional policies could be implemented for role changes and other requirements through the system's flexible policy engine.

### On-Chain Verification Tools Implementation

The team discussed implementing on-chain verification tools, with Hart proposing to explore running an on-chain VTC using a blockchain as the community's root of trust. Diane expressed interest in having Hiero participate as a smaller pilot project, particularly noting the need for GitHub Connect and Discord Connect for maintainers features. Hendrik indicated the current tools were sufficient for a testing phase, and Glenn offered support for customization based on Hiero's specific requirements. The discussion concluded with Diane expressing interest in having the TSC consider this as a potential pilot project.
