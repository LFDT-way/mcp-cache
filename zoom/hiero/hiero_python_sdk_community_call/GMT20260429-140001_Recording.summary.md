## Details

### Python SDK Updates Meeting

Angelina led a meeting to discuss updates on the Python SDK, including the removal of the changelog and the introduction of a new quarterly goals roadmap document. She also addressed an issue with the continuous runner, which was caused by an accidental edit involving an array of runners. The issue has been corrected, and a PR is expected by the end of the day. Angelina encouraged attendees to review the new roadmap document and assist with welcoming new members in the Discord chat.

### Project Updates and Progress Review

The team discussed several ongoing projects and updates. Manish reported reviewing a large protobuf PR for serialization and confirmed it didn't need to be split into smaller chunks. He also provided an update on Mirror Node version 0.153, which now includes endpoint support for querying registry node addresses, allowing Daniel to proceed with implementing the REST API for HIP1137. Angelina mentioned that HIP1261 is nearly complete with only one test remaining, expected to be finished by week's end.

### Fuzzing Support PR Discussion

Daniel discussed his PR for fuzzing support, which is ready for review, though Sophie indicated she needs more time to understand the complexity of the work. Sophie noted that their signed releases feature is working well and being recognized by OpenSSF, putting them ahead of competitors in the Hiero ecosystem. Daniel explained that the fuzzing tool, similar to a penetration testing tool but automated, simulates workflows to find bugs in the codebase, with successful testing on custom runners and Python-based practices.

### Bandit Security Scanning Implementation

The team discussed implementing bandit security scanning with a pre-commit hook. Manish sought guidance on where to store the configuration, and after discussion with Angelina and Sophie, they agreed to use the .bandit file for better flexibility. Daniel then presented his work on using a lightweight fuzzing engine with Docker and PyInstaller to identify high-risk areas in the SDK, focusing on entity ID passing, key passing, and contract parameters.

### Project Review Process Discussion

The team discussed reviewing a shared document, with Angelina indicating they would take a few days to understand it better. Daniel mentioned the project's BSS score is currently 8.8, which Sophie noted would likely increase again after pausing. The main discussion centered on whether to continue with two reviews, with Sophie raising concerns about potential issues if they stopped using two reviews, including lower open assessor scores.

### Code Review Process Discussion

The team discussed continuing their current review process despite some challenges with implementation. Sophie highlighted the main issue as figuring out the review process, including the use of step labels and code owners, but noted progress has been made. Angelina suggested continuing with the current process for now and proposed exploring ways to streamline the review process in future discussions. The team agreed to add this topic to the agenda for upcoming meetings.
