### Python SDK Release Strategy Discussion

Nadine discussed the need for a consistent release cadence for the Python SDK, emphasizing the importance of providing the latest features to users. She highlighted the necessity of properly communicating breaking changes and deprecations, especially as more projects adopt the SDK. Sophie raised questions about the policy for deprecating methods and the time period before removing them, noting the challenges of maintaining backward compatibility. Hendrik mentioned he would provide more information on the deprecation policy and time frame.

### Python SDK Backward Compatibility Discussion

Hendrik emphasized the importance of transparency and informative communication regarding breaking changes in the new Python SDK, which is still under development. Sophie acknowledged the benefits of learning about backward compatibility while agreeing that the primary focus should be on building and expanding the user base. Hendrik shared a discussion from the TSC about backward compatibility guidelines for Hiero, which includes maintaining previous SDK versions for a minimum period of 6 months for functionality enhancements and one year for major bug fixes and critical security fixes.

### SDK Development and Compatibility Discussion

Nadine and Hendrik discussed the importance of backward compatibility in SDK development, emphasizing the need to consider potential impacts on users when making changes. They agreed that projects in incubation mode should be allowed to make breaking changes, while graduated projects should maintain stability. Sophie presented updates on style changes and linting improvements, proposing to integrate pilot and mypy tools to catch issues early. Nadine agreed to investigate adding these tools to the CI pipeline. Sophie also inquired about the progress of file service and smart contract transactions, with Dosi reporting that the creation of files and smart contracts was progressing well, but further work was needed on improving the code's readability.
