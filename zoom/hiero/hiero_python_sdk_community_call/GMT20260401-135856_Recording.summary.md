The team discussed progress on implementing heap functionality, with Manish noting documentation discrepancies between the SDK Collaboration Hub and official heap repository. Dosi confirmed they are waiting for the Mirror Node team to expose the required endpoint, with updates to be provided through Musito. Sophie explained new stricter requirements for advanced pull requests, including stronger warnings about time expectations and more rigorous code quality standards, as the team has been experiencing issues with incomplete or poorly researched submissions that require extensive review time.

Aditya raised a concern about GitHub workflows sending notifications to maintainers when pull requests are created, even when they are incomplete or in draft mode. Sophie and Daniel discussed the possibility of using draft mode as a solution, with Sophie confirming that pull requests opened in draft mode should not automatically notify maintainers for review. The conversation ended with Aditya suggesting they could implement the TCK in a similar way to the JS SDK, which contains params, handlers, and response files.

### TCK Code Implementation Discussion

The team discussed the implementation of TCK (Test Compatibility Kit) code, with Aditya working on converting it to Python and Manish explaining that the current TCK implementation takes inspiration from multiple SDKs including JavaScript, Go, and C++. Manish clarified that while the implementation is inspired by JS SDK, it's not directly copied from it, and noted that complex responses like account info queries require additional mapping between JSON responses and response classes. The discussion concluded with Sophie asking about the research behind using JavaScript as the most reliable option, though this question remained partially answered.
