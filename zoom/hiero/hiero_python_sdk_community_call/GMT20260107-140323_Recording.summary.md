The Python SDK community call discussed the current state and future direction of the SDK. The team is considering whether to release the new version as 0.1.11 or 0.2, with Sophie leaning towards a major release. The team agreed to discuss their suggestions for the Python SDK's future direction in a round-robin format.

### Python SDK Blockchain Integration Planning

The team discussed future improvements for the Python SDK in 2026, with a focus on adding blockchain and DLT capabilities to align with other SDKs. Angelina emphasized the need to standardize SDK functionalities across languages and improve training and documentation for new starters, particularly for protobuf. Sophie clarified that committers and maintainers have merge capabilities, and the team agreed on the importance of building confidence in merging changes over time. Akshat joined the call and was invited to contribute ideas for the Python SDK's development, with a particular emphasis on blockchain coding.

### Blockchain SDK Integration Review

Manish and Sophie discussed the process of identifying and creating blockchain issues, focusing on the Python SDK and its alignment with the Java and JS SDKs. Manish explained his method of identifying missing fields or classes by comparing the Python SDK with the Java SDK and validating them against the protobuf files. Sophie suggested forming a regular meeting to review files in the Python SDK, such as token associate and dissociate, and to discuss completeness and deprecated elements. Manish agreed to take the initiative for organizing these meetings, which would help build skills in identifying missing functionalities.

### Strategies for Blockchain Issue Identification

The team discussed scheduling an intermediate issue identification meeting, with Sophie proposing Tuesday 2PM UTC and suggesting it be posted as a discussion in the Python SDK to gather feedback. They explored strategies to increase blockchain issues, including building relationships with AI teams and other SDK users, finding flaws in the SDK, and improving test coverage. Manish and Sophie agreed to focus on these four approaches simultaneously in 2026 to generate more blockchain issues and identify missing ones.

### Python SDK Specialization and Enhancement

Sophie discussed the need for team members to specialize in different areas of the Python SDK, such as improving tests and training, or identifying bugs. She suggested comparing the Python SDK with other established SDKs like Java and JavaScript to identify missing features and areas for improvement. Sophie emphasized the importance of collaboration and learning from each other to enhance the SDK's functionality. The team agreed to schedule regular meetings to work on these goals together.

### Python SDK Team Expansion Discussion

Sophie proposed expanding the Python SDK team by creating additional Triage members and growing the number of committers and maintainers. She emphasized the importance of diverse opinions and debate within the team. Angelina agreed that more maintainers would be beneficial to help progress the project.

### Improving Contributor Roles and Efficiency

The team discussed the need to grow their maintainer and triage member roles to improve pull request review efficiency and build contributor confidence. Sophie explained the eligibility criteria for different roles, including a 3-6 month minimum commitment period and requirements for code testing and review skills. The team agreed to discuss implementing a two-level safeguard system, where committers merge to a developer branch and maintainers merge to main, in the next community call. Sophie also announced plans to investigate Linux Foundation mentorships and encouraged team members to express interest in either mentoring or being mentored.
