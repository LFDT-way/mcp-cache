### Role Progression and Governance Planning

Sophie discussed the need to grow junior committers, committers, and maintainers across Hiero Ledger and Hiero Hackers repositories, using the analytics repo as an example where pull requests are piling up due to limited reviewer capacity. She outlined the role progression from junior committer (beginner to intermediate level with 1-2 months project experience) to committer (higher responsibility including formal approval rights) to maintainer (project steward responsibilities). Sophie mentioned that documentation is being developed in the governance repo to clarify these roles and expectations, with a pull request in progress to define concrete requirements for different contribution levels.

### Junior Committer Qualification Criteria Discussion

Sophie discussed the need for more junior committers and introduced a draft document defining qualification pillars for different roles, including junior committer requirements around authoring and reviewing pull requests, triaging issues, and community involvement. Jessica agreed that more junior committers are needed, particularly around core components, and emphasized the importance of current maintainers guiding new contributors. Sophie sought feedback on the draft document, which aims to establish consistent qualification criteria while allowing repositories to adjust thresholds based on their specific needs.

### GitHub Roles and Permissions Discussion

The team discussed the differences between junior committers, committers, and maintainers in GitHub repositories. Sophie explained that while junior committers can review and triage issues, their reviews don't count toward merging PRs, and they have limited repository management permissions compared to committers and maintainers. Jessica clarified that maintainers have additional administrative capabilities beyond committers, including eligibility to vote in TSE elections, and that malicious actors would need admin permissions to access security settings. The discussion revealed that while malicious maintainers could approve PRs and modify workflows, junior committers have minimal security-related capabilities beyond basic commenting and issue labeling.

### GitHub Permissions and Security Discussion

The team discussed GitHub permissions and roles, with Keith seeking clarification on the differences between committers and maintainers. Sophie and Jessica explained that while committers and maintainers have similar permissions, maintainers can access repository settings and security tabs, and they have additional responsibilities as stewards of the codebase. The discussion highlighted concerns about security risks, particularly in SDK repositories that only require one approval for merges, and the team agreed to propose solutions including implementing two approvals, using CodeRabbit for automated security reviews, and potentially creating a more restricted committer role with custom GitHub permissions. Keith plans to bring these security discussions to an upcoming TSC meeting, and the team also reviewed the Hiero Hackers initiative, which provides a simpler process for community members to experiment with new features compared to the formal Hiero Ledger repository creation process.
