## Agenda

Goal: To define a set of best practices, templates, and guidance for establishing and evolving contributor ladders across LF Decentralized Trust (LF/DT) projects. This work will support community growth, contributor onboarding, and sustainable project governance.

## Overview

The team reviewed website updates and discussed documentation progress, including formatting improvements and the need for consistent templates and links. They explored contributor role definitions and onboarding processes, with a focus on transitioning new developers into committed roles and establishing clear mentorship guidelines. The group also discussed project lifecycle management, reporting guidelines, and the challenges of measuring diversity in open-source projects, while considering various tools and dashboards for tracking community health metrics and improving quarterly reports.

### Maintainer Onboarding Guide Development

Diane discussed her work on drafts and the need to publicize certain content, particularly at the Maintainer Days Summit. She mentioned creating a new maintainer onboarding guide and a project onboarding piece, which she is unsure about keeping separate. Diane expressed openness to having others rewrite or add to the onboarding guide, which currently contains a bulleted list of expectations and tasks for new maintainers.

### Developer Role Progression Framework

Sophie discussed the need for a structured approach to help developers progress from contributors to committers and eventually maintainers, particularly in the Python SDK where they have onboarded 70 users. Diane shared a draft of documentation for contributor roles and governance, which Sophie found useful and expressed interest in contributing to. They discussed incorporating good first issues and improving documentation to match LFDT standards. Ry and David clarified the distinctions between contributor, committer, and maintainer roles, noting that these terms can vary by project. Sophie inquired about mentorship guidelines for specific roles, and David mentioned the existence of a wiki on mentorship under LFDT, though he noted that mentoring should ideally be ongoing for all levels of involvement.

### Formalizing Developer Role Transitions

Sophie and Diane discussed the challenges of transitioning new developers into committed roles in open-source projects, particularly for those still in university. They explored the idea of creating a structured, formal process to build confidence and define roles, such as a "junior committer" status. Ry mentioned the current system's lack of clear documentation for roles like contributors and committers, and David suggested that projects can define as many roles as needed to help new contributors transition. David also invited Diane and Sophie to join the upcoming TAT call to review and discuss the Maintainer Days agenda, including a planned working session on the contributor site.

### Event Contributor Process Improvements

The team discussed the schedule for an upcoming event, with David confirming a breakout session on contributor site improvements for day two, though they agreed it could be moved if needed. Diane suggested adding information about contributor roles and the progression ladder to the event's materials, and proposed creating a template for contributor ladders that projects could use as an example. The group also discussed the need to improve the process for collecting feedback from event participants, with Rai tasked with finding a way to direct people back to GitHub to log issues, which would help track their contributions and provide more detailed feedback.

### Project Lifecycle Metrics Standardization

The team discussed project lifecycle management and reporting guidelines. Diane and Jessica raised concerns about the lack of standardized metrics for TAC reports, with Diane suggesting the need for guidance on creating comparable metrics across projects. Ry mentioned that GitHub activity is a key criterion for assessing project status, citing the example of Bevel, which was archived despite claims of activity. The team agreed that project lifecycle information should be housed in the main documentation section rather than duplicate content in contributor guidelines, with links to relevant lifecycle stages like graduated, dormant, and archived.

### Improving Diversity Measurement Tools

The group discussed challenges with measuring diversity in open source projects, particularly issues with the accuracy of LFX Insights tool and GitHub self-reporting. Diane explained that while LFX Insights is unreliable due to its inability to update profile information, they have access to a paid tool called Biturgia dashboard which provides more accurate metrics. The team agreed that measuring diversity accurately will be a focus for 2026, as they need better tools to assess annual reports and maintain standards.

### Open Source Insights and HIRO

The team discussed open-source code for Insights and its potential use for tracking community health metrics. Diane explained that while LF Insights is being updated for an April company All Hands meeting, there are existing tools and dashboards for HIRO that could be adapted for other projects. Sophie suggested creating a repository for data analytics of HIRO activity, which Diane agreed was feasible for HIRO but noted that TAC projects would need no-cost solutions supported by LFX. The team also discussed the need to improve quarterly report templates and contribution guidelines, with Diane mentioning that these would be addressed after receiving feedback from the TSC meeting.
