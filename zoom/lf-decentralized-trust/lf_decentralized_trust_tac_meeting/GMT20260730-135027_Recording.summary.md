## Overview

The Linux Foundation Decentralized Trust Technical Advisory Council (TAC) meeting covered several project updates and governance discussions. Sean and Ry discussed the onboarding of new projects like Thunder ID and Kapoon SDK, while Ry mentioned working on setting up OpenIDS and Open Verification. Marcus presented an analysis of project health using AI-generated checklists and identified gaps in guidelines around pull request processes. ## Details

The meeting began with Arun chairing the Linux Foundation Decentralized Trust Technical Advisory Council meeting on July 30th, 2026. The meeting also confirmed that Agent Authority Conformance had been previously approved, with Ry mentioning he would address related edits on Monday.

### Government Document Analysis Guidelines

Marcus presented an analysis of government documents using an AI agent to check against GitHub organization standards, identifying gaps in Git flow recommendations such as PR review processes and issue discussions. Marcus agreed to draft initial guidelines addressing these gaps for discussion in the next meeting. Arun outlined plans for receiving and reviewing meteor reports from project teams, with TAC members conducting offline reviews and addressing major concerns in the meeting if needed.

### CATEC Report Extension Discussion

Rama requested a two-week extension for the CATEC team to submit their report due to ongoing work on code cleanups and a release. Arun approved the extension. The team discussed an open pull request on agent authority conformance, which was clarified to focus on moving conformance tests to a new lab project rather than affecting the entire community. Arun encouraged the team to increase participation and bring in a peer group for acceptance. The discussion concluded with details about the upcoming TAC election process for 2027, which will follow similar procedures to last year but with potential date changes.

### Project Updates and Governance Discussion

The meeting covered two main topics. First, Ray updated the group that dates had changed for an unnamed project, and the pull request already had two approvals, so he would merge it. Second, Arun initiated a discussion about sub-project maturity levels and governance, but Marcus suggested postponing this topic to a meeting with more TAC members present. The conversation ended with plans to review a pull request on AI governance and follow up on recent comments from Attila.

### AI Tool Review Process Discussion

The team discussed feedback from Attila regarding AI tool usage in the development process, which contradicted earlier discussions about not requiring AI tool attribution. Attila's comments emphasized the need for human involvement in the review process, particularly for pull requests, where reviewers should ensure code quality and flag when AI tools were heavily used. The discussion highlighted a tension between previous proposals for AI tool disclosure versus the current need for more explicit accountability measures, including reviewer responsibility and submitter notes about AI assistance.

### TAC Proposal Review Discussion

The TAC meeting discussed reviewing and potentially accepting a proposal with comments that required further consideration. Since quorum was not present, the group decided to postpone the GitHub voting process and instead agreed to invite Rafael to review the comments and potentially incorporate them into the proposal. Arun committed to following up personally with Rafael to address the comments and schedule a meeting to discuss the proposal further.
