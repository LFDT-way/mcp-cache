## Overview

The Linux Foundation Decentralized Trust Technical Advisory Council meeting focused on Angelo's presentation of the Hyperledger Token SDK project, which aims to provide tokenization capabilities for permissioned blockchains with emphasis on privacy, compliance, and performance. Angelo explained that the project started as Fabric Token SDK and has been used in deployments by central banks including Bank of France, featuring UTXO model design with customizable privacy levels and support for multiple blockchain networks including Hyperledger Fabric and upcoming EVM-based DLTs. The project has 117 stars on GitHub with over 80% test coverage, active contributors from IBM Research, Sign Global, and Chainlabs, and has been accepted into two mentorship programs. During the Q&A session, participants asked about the project's name (which will change from "Hyperledger Token SDK" to something less generic), community-driven network drivers for EVM-based blockchains, interoperability concerns, and the project's positioning as a toolkit versus a complete solution for token operations.

### Hyperledger Token SDK Presentation

Angelo presented the Hyperledger Token SDK project, a framework for tokenization on permissioned blockchains designed with three core principles: privacy, compliance, and performance. The project has been used in deployments by central banks including Bank of France and Bank of Canada, and has received support from various organizations including IBM Research, Sign Global, and Chainlabs. The Token SDK is network agnostic and supports Hyperledger Fabric and Fabric X, with plans to add support for EVM-based networks in the future. The project is currently in development toward version 1.0, with plans for external security audits and automated release processes.

### Hyperledger Token SDK Architecture Discussion

Angelo clarified that the project name "Hyperledger Token SDK" will change as they are working with lawyers to confirm availability of better options. He confirmed that the EVM compatibility driver will be integrated directly into the token SDK repository as a core element. The team discussed the project's architecture, with Angelo explaining that while it started with permission networks, the design is flexible enough to work with public mainnets like Ethereum and could even integrate with databases. The discussion covered interoperability concerns, with Angelo stating that the token SDK should absorb community-developed protocols for cross-chain operations rather than dictating them.
