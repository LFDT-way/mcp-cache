### POC Inclusion in Adopters File

The team discussed how to handle proof of concepts (POCs) and pilots in the adopters file. They agreed to leave the decision to include POCs and pilots at the maintainers' discretion, rather than establishing a strict policy. Tracy noted that the common repository structure already allows for maintainers to update the adopters file with publicly verifiable references. Ramakrishna shared an example of a notable POC by the Bank of France, which demonstrates the potential value of including significant POCs in the adopters list.

### Adopter Management Strategy Discussion

The team discussed how to handle adopters who are no longer using a project. They agreed to keep the current adopters list simple and allow adopters to remove themselves from the file if they stop using the project. Diane suggested checking the adopters file for freshness during quarterly reports. The group debated whether to create a separate section for defunct adopters, but decided against it due to the complexity of tracking which versions of the project were used. They concluded that the maintainers should have the right to remove their name from the adopters file if needed.
