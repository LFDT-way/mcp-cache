## Details

### Virtual Private Knowledge Working Group

Reza opened the third meeting of the Virtual Private Knowledge Working Group and welcomed attendees, including new faces. He explained the group's focus on securing data sent to AI services like ChatGPT and Anthropic, particularly during the retrieval phase of Retrieval Augmented Generation (RAG). Reza introduced the agenda, which included updates from task force chairs on two immediately startable groups: the VPK protocol task force, chaired by Darren Warner, and the personal embedder task force, headed by Mitchell Travers. The conversation ended with Reza preparing to hand over to Darren for a discussion on the VPK protocol and its specification and standardization.

### VPK Protocol Task Force Planning

Darren outlined the main objectives of the protocol task force, which will focus on creating and maintaining specification documents for VPK, including decisions on workflow, format, and versioning. He emphasized the importance of balancing standardization with development speed and discussed potential technical choices like using gRPC and Protobuf. Reza provided context on the protocol's role in securing data flow between Bob and Sam, highlighting the complexity involved in vector embedding, sharding, and querying within VPK.

### VPK Protocol and Sharding Discussion

Reza explained that the existing code implementation could serve as a starting point for a reference implementation, suggesting it be transferred to the Linux Foundation's GitHub. The discussion addressed why the VPK protocol would need to know about sharding, with Tom questioning the necessity and Mitchell suggesting it might only matter if sharding is based on trust rather than random distribution. Mitchell then presented visualizations of a lattice-based embedding system for node relationships, demonstrating how values could be encoded using a six-category system and showing geometric transformations between different network representations including globe, chain, and star configurations.

### Community Trust Graph Key Concept

Mitchell explained his concept of using a community trust graph as a personal key for accessing data, where the key changes over time based on network state while maintaining consistency through fixed reference points. Reza clarified the difference between Mitchell's approach and traditional text embedding, suggesting that Mitchell's method could be applied to text embedding in a separate meeting. The discussion concluded with agreement that the trust graph approach offers benefits for verifiable AI and could potentially combine embedding and scrambling functions for improved security.

### Travel AI Data Privacy Protocols

Neil Thompson, co-chair of the Data Modeling and Representation Working Group, discussed building traveler profiles using AI for travel arrangements, highlighting concerns about personal data privacy based on a UK survey showing 62% of people are concerned about personal data in travel AI systems. Reza explained how VPK could secure personal information in travel use cases by allowing querying of scrambled data without exposing clear text to untrusted hosts, and Drummond suggested integrating VPK into the TrustRMP Layer 3 Trust Has protocol stack for decentralized trust communications. The group discussed the need for a protocol to enable interoperability between different systems, with Darren and Reza explaining that even undocumented protocols are still necessary for standard communication between systems.
