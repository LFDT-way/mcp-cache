## Overview

The meeting focused on discussing the VPK protocol and its role in securing knowledge bases within RAG (Retrieval-Augmented Generation) systems. Reza explained that VPK acts as a firewall between the data owner (Bob) and the service provider (Sam), securing the query and retrieval phases while allowing the chat completion to remain unsecured. The team discussed how VPK returns only scrambled indices and similarity scores rather than actual document content, with Bob handling the local resolution of indices. Darren raised questions about whether a new protocol is needed, given the existing work on Quinet and Trust over IP (TOIP), and noted the potential need for partial homomorphic encryption components. The group also reviewed Mitch's progress on embedding technology, where he demonstrated how words can be embedded into a 6D geometric space using a "sovereignty lattice" system with six defined dimensions: protection, delegation, computation, connection, memory, and value. The conversation ended with discussions about how Mitch's embedding work could potentially address the predicate collapse problem they are facing.

### VPK Firewall Implementation Discussion

Reza and Darren discussed the implementation of VPK as a firewall between the document ingest phase and the query phase of a RAG system, clarifying that VPK does not sit between the chat completion phase. They explained that VPK protects the knowledge base during retrieval but not the entire process, and discussed potential security measures for sensitive data. The team also addressed the need for team members to sign into the Linux Foundation Confluence for access.

### Trust over IP Protocol Discussion

Reza discussed the boundary placement for data processes, addressing Tom's question about the need for a new protocol. Reza explained that Trust over IP focuses on identity and trust establishment between parties like Bob and Sam Altman, rather than just identity verification. Darren clarified that while VPK builds on existing work like Quinet and uses protocols like gRPC and Protobuf, Trust over IP includes a specific product called TSP that serves as a transport layer with a broker for establishing trust relationships.

### Partial Homomorphic Encryption Implementation Discussion

The team discussed implementing partial homomorphic encryption (PHE) in their system, with Darren suggesting that a new protocol might be needed due to potential significant changes to the existing VPK protocol. Reza proposed keeping components separate with crate-level dependencies rather than tight integration. Sulimon highlighted unique cryptographic aspects of their RAG system, particularly regarding how keys and indices are returned and encoded, which differs from regular search protocols. The discussion focused on the challenges of creating an intermediate protocol that would handle PHE functionality, noting that existing database query protocols like SQL and MongoDB are not suitable for their encrypted search requirements.

### Similarity Score Protocol Discussion

The discussion focused on a protocol for returning similarity scores and top-k indices without transmitting actual document content. Reza explained that SAM computes similarity scores and returns only indices and scores, while Bob resolves the scrambled indices locally to retrieve plaintext documents. Darren raised concerns about index resolution challenges, particularly when multiple users might write to the same knowledge base and potential conflicts with deleted documents. The team identified the need to address coordination of indices and handle conflicts in the protocol.

### AI Trust Boundary Proposal Updates

The team discussed the current state of their trust boundary proposal for AI systems, focusing on securing knowledge bases while allowing untrusted third-party queries. Darren reported progress on reviewing the TOIP architecture specification and TPS protocol, noting that while gRPC and Protobuf were initially considered, the protocol actually provides its own transport layer through a broker at teaspoon.world. Mitchell presented his work on data embedding, demonstrating how words can be encoded in a 6D geometric space using a "sovereignty lattice" with defined dimensions for protection, delegation, computation, connection, memory and value, which successfully passed 54 verification challenges. The team agreed to continue these discussions to develop documentation, with Reza planning to speak with Dave Boswell about proper organizational structure placement.
