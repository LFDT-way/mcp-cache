## Details

### EVM Integration with Hyperledger Fabric

The community call focused on updates and progress in integrating Ethereum Virtual Machine (EVM) with Hyperledger Fabric, presented by Arne. He highlighted the technical separation of the Gateway and EVM endorser, enabling the execution of Ethereum transactions on Fabric networks, with successful demonstrations using MetaMask and ERC20 tokens. Arne mentioned ongoing testing with historical Ethereum transactions and expressed optimism about EVM's compatibility with Fabric networks. Ilie inquired about the status of an RFC, which Arne confirmed was drafted but not yet posted. Arne promised to prepare a demo for the next community meeting. The discussion then shifted to updates on Fabric-X Ansible collections, with Pasquale set to continue the topic.

### Hyperledger Fabric-X TLS Update

Pasquale presented an update on the latest upgrade of the Ansible collection Hyperledger Fabric-X, moving from version 0.3 to 0.4. The main changes include transitioning crypto material generation to be performed directly on the remote node, improving security standards, and adding TLS support to various components. Pasquale explained how to enable TLS by setting component-specific flags in the inventory to true, and mentioned that full TLS support for Fabric-X is expected by the end of the month. Ilie inquired about the default behavior if no TLS flags are specified, to which Pasquale replied that the default is not TLS.

### FabricX AWS Performance Results

Yoav presented results from AWS experiments, showing that FabricX achieved over 400K TPS in four-party scenarios with 0.5-0.7 second delays, using 32-vCPU VMs and 100GB GP3 volumes. Ilie requested that the results be posted to the FabricX repository for public access. The discussion concluded with a transition to the topic of FabricX Blockchain Explorer.

### Fabric-X Blockchain Explorer Development

The team discussed the development of a Fabric-X blockchain explorer, with Farooq presenting the initial design. The explorer will be a microservice connecting to a sidecar component and using the Deliver API to fetch blocks. It will include components for fetching data, parsing, writing to a database, and querying, with plans to expose REST APIs. Farooq explained that the system will store block, transaction, and read-write set data in a relational database, with the ability to handle multiple threads for processing. The team discussed performance considerations, with Senthilnathan clarifying that the focus is on functionality rather than performance for now. Ilie mentioned that the project will be hosted in a public Azure repository once approved. The conversation ended with Ilie announcing the next topic would be a demo of Fabric meets EVM, and encouraging participants to suggest additional topics via Discord.
