## Details

### Credible Platform Development Updates

The team discussed ongoing work on the Credible platform, focusing on OID and VC features, as well as X59 certificate-related updates for MDoc support. Krishna shared plans to update the Nest.js version and work on library packaging to improve extensibility, with a phased approach to avoid disrupting ongoing development. The team decided to start with library composition before moving to service-wise extensibility, aiming to balance progress with stability.

### Session Management and OIDC Updates

The team discussed updates on platform, controller, and studio sides, including work on extensibility, monorepo implementation, and session management features. Rinkal mentioned that SSO features were released in the previous release and new session management options are being developed to allow users to view and delete their sessions across different devices and browsers. Tipu and Rinkal planned to discuss verification template-related features for OIDCVP on the platform side, including the creation of presentation requests, with further details to be covered in a subsequent discussion.

### Credential Presentation Template Options

The team discussed creating presentation templates for verifiers to easily select attributes from credentials and apply restrictions or filtrations. They proposed two options: using existing credential templates or directly using raw JSON/DCQL queries. Rinkal explained that both approaches would be stored as DCQL JSON in the database, with the system automatically generating JSON for users. Ankita clarified that the presentation templates would allow verifiers to create proof requests using either templates or raw JSON.

### Credential Template Access and Sharing

The team discussed the validation and sharing of credential templates, deciding to restrict templates to organizational level and allow read-only access for other organizations to view but not modify them. They explored compatibility with the DC API and DCQL, with Ajay noting that many verifiers prefer using DC API for OpenID VP. The discussion clarified that credential templates would be used for issuance purposes while presentation templates would reference these existing templates, providing a more efficient way for verifiers to create presentation templates by reusing attributes from existing credential templates.

### DCQL Transition and Query Format

Rinkal explained the transition from packs to DCQL for OpenID specifications and described the creation of presentation templates to build DCQL JSON. They discussed the format of DCQL queries, which can handle multiple credentials in a single request, and Rinkal shared an example from the Anemo team showcasing how different types of credentials (like MDoc and SDJOT) are structured in the query. Ajay confirmed understanding and inquired about reviewing an example format, to which Rinkal mentioned they would review templates with Tipu and shared reference examples.

### PEX and DCQL Template Updates

The team discussed the creation and updating of presentation templates for credential verification, focusing on PEX and DCQL formats. Tipu explained the current payload structure and the need to update it based on DCQL requirements, while Rinkal emphasized that changes would primarily affect field-level parameters. Ajay raised concerns about potential impacts on existing PEX users and suggested a method for notifying verifiers about changes in issuance templates. The team agreed to support both PEX and DCQL formats initially but noted that OpenID would eventually focus on DCQL. They also discussed the need for a mechanism to notify verifiers about updates to issuance templates, though this feature was not immediately implemented.
