Rinkal and Krishna discussed the status of pull requests (PRs), noting that most were from their team. They agreed to close a specific PR related to readme updates once another PR is merged. They also discussed merging a PR into the main branch, deciding to do so when a single microservice has 100% test coverage. Rinkal suggested changing the branching strategy after this release to allow direct merging of development PRs into the main branch.

### Code Merge and Testing Plans

Krishna and Rinkal discussed merging code within 2-3 days for testing with an upcoming release, noting that CI/CD implementation could follow later. Arshdeep reported progress on the insurance microservice, which is nearly complete and will be shared for review soon. Rinkal suggested writing unit test cases for new APIs in the platform, which Tipu agreed was a good idea. They also briefly touched on ongoing work for OID for VC and VP implementation.

### Credos Credential Authorization Flows

Rinkal and Tipu discussed the authorization flows for issuing credentials in Credos. They explored whether it's possible to issue credentials without authentication and found that the "none" option in the demo OpenID setup uses an undefined behavior for creating credential offers. They agreed to check how the create credential offer flow behaves when "undefined" is passed and to investigate further test cases and unit tests.

### DID Endpoint Rotation Demonstration

Tipu demonstrated a process for rotating DID endpoints in a mediator setup, showing how to migrate connections from an old service endpoint to a new one while maintaining the same database. He explained that both old and new mediators need to be running during the rotation process, and successfully demonstrated the rotation by sending messages from a holder to both mediators. Rinkal inquired about the setup for issuer to holder with the mediator, but Tipu confirmed he had only tested with issuer and holder without mediator data.

### Mediator Rotation and Communication Flow

The team discussed a mediator rotation flow where Tipu explained that a new mediator can be initiated without configuration changes on the old mediator, as version 15.5 has resolved previous issues. Krishna raised questions about message delivery during rotation, and Tipu clarified that the mediator and holder communication should be executed first, followed by issuer communication, with both mediators referencing the same database. The team agreed to test scenarios involving undelivered messages and two holders connected to different mediators, while Ankita joined briefly to mention an upcoming discussion about Polygon DID creation.

### Polygon Wallet Private Key Import

The team discussed an issue with importing private keys for Polygon wallets, where Ankita encountered errors when trying to reuse a private key to create a new wallet. Tipu explained that Polygon currently lacks an import option, though they could potentially add it to the agent and platform. The team agreed that Ankita should create a GitHub issue to address this limitation, with Sayali confirming she had not yet created the issue.

### DID Document Update Strategy Discussion

The team discussed updating DID documents when service endpoints change. They decided to research how to update the document with both old and new endpoints while maintaining history. Tipu suggested using a similar approach to HEDERA's variable structure for attributes. The team agreed to create a GitHub issue and have a follow-up discussion in the next call.
