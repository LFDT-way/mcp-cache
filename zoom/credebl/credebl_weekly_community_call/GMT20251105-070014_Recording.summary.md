### CREDO Version Updates and Incompatibilities

The team discussed recent releases, focusing on token management improvements by Sujit and OID4VC-related developments. They clarified that certain releases were marked as 2.1.2 alpha due to upcoming breaking changes in version 2.2.0, which will require new major releases due to incompatibilities with the current CREDO version. Rinkal explained that the team is using the stable CREDO version 5 for 2.1.x releases, while 2.2.0 will incorporate the alpha version 6 of CREDO.

### CREDO Controller Alpha Release Discussion

The team discussed the alpha release of CREDO controller features and Rinkal explained the implementation of dynamic trust for X509 certificates in OID4VP and VC systems. Rinkal described how verifiers fetch certificate lists from a shared URL, which acts as a schema file server for all agents within the same tenant. Tipu mentioned a related release focused on refactoring and changes for issuance and verification processes.

### Platform Updates and User Verification

The team discussed several platform issues and PRs, including a PR for upgrading TypeScript, ESLint, and Node packages, and another for GitHook changes in Studio. Rinkal raised concerns about user verification during registration and email sending, highlighting a PR by Sujit that skips email verification. The team noted previous discussions about implementing CREDIBLE features, including suggestions for admin-level APIs and exploring KeyClock support for the workflow.

### Hybrid User Verification Workflow

The team discussed user verification workflows, focusing on a hybrid approach that combines platform admin approval and email verification. They agreed to implement two levels of verification: first, requiring platform admin approval before users can join the CREDIBL platform, and second, offering optional email verification if enabled. Rohit suggested restricting certain APIs to platform admins to control user registration, and the team determined they would need to develop an API for admin token generation to support this workflow.

### Email-Free User Onboarding Solution

The team discussed onboarding users without email addresses, confirming that while email verification is currently required, users can still be onboarded through the portal if email notifications are unavailable. Rohit clarified that the UI already supports onboarding users with role assignments, and Rinkal emphasized the need to remove the hard dependency on SendGrid by allowing SMTP configurations. The team agreed to test this flexibility and explore alternative ways to inform users about invitations if email configurations are not possible.

### User Registration Workflow Updates

The team discussed user registration and authentication workflows, focusing on removing email verification while maintaining control over user access. They agreed that platform admins would need to manually approve pre-registered users by receiving their email addresses, either offline or through a dedicated platform interface. The team decided to create a high-level workflow diagram to document these scenarios, and they noted that a pending PR was blocked due to missing commit verification. Additionally, Ankita mentioned ongoing work on implementing nested schemas for CREDBL's guardianship wallet feature.
