## Overview

This was a Web3J contributor call hosted by George and Nischal to introduce and discuss updates with new mentors Saurav and Dev. The meeting focused on the current state of Web3J, which has been maintained by only two people (George and Nischal) for the past several months, making it difficult to balance full-time jobs with open source maintenance. The team discussed upcoming priorities including the Fusaka upgrade to be released within the week, followed by the Amsterdam update, and identified a critical bug in blob transactions that affects production systems used by projects like Aztec. George and Nischal agreed to schedule a debug call the following day to investigate the blob transaction signing issue, which involves discrepancies in transaction hash calculation between different code branches.

## Details

### Web2J Contributor Call Restart

George introduced the Web2J contributor call, which was the first since December, as part of the Linux Foundation initiative. He explained that Web2J has been challenging to maintain due to limited maintainers and highlighted how mentorship programs have been beneficial for both contributors gaining blockchain knowledge and the maintainers in adding new features to the codebase. The meeting was recorded and would be published on YouTube, with plans to discuss the assigned work and address any questions from the new contributors Saurav and Dev.

### Roadmap Updates Discussion

Nischal discussed the roadmap updates, mentioning that a Fusaka update will be released this week, followed by work on the Amsterdam update. George agreed to handle the roadmap updates and suggested adding a task to update the roadmap before the next contributor call. No specific decisions or action items were explicitly mentioned beyond these updates.

### Blob Transaction Bug Discussion

Nischal discussed ongoing upgrades and bug fixes, including a Fusaka upgrade and issues with blob transactions. George inquired about the relationship between the blob transaction bug and the access list, to which Nischal clarified it was related to signing the sidecar blob. Nischal requested Dev to provide more details about the specific issue with the blob transaction bug.

### Transaction Hash Calculation Issue

George and Nischal discussed an issue with transaction hash calculation where a developer named Dave encountered problems when signing and decoding transaction hashes in branch 2196. They identified potential differences between branches in how hashes are computed and discussed the need to compare their sample code with Dave's implementation to investigate the discrepancy. The team also noted that Aztec is using their business solution, though this was mentioned as a separate observation rather than related to the current issue.

### Production Transaction Issue Discussion

George and Nischal discussed an issue with a transaction that affects multiple projects in production, with both of them experiencing the same result. They agreed to prioritize addressing this issue within the next two weeks and decided to create an issue and get input from someone at Consensus before proceeding with any upgrade that could impact production projects further.

### Debug Call and Demo Planning

Nischal and George discussed scheduling a debug call for the next day and mentioned a demo related to block transactions that should be reviewed in the Web3 channel. They confirmed that Saurav was aware of the discussion and had responded in the chat. George informed the group that he would not be able to join the Friday call, but they would have a call the next day instead.
