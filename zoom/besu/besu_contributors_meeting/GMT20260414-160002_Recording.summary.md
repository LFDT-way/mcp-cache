## Overview

The April 2026 Besu Community Contributors Call focused on project updates and community matters. The team discussed the upcoming 26.4 release with an RC2 planned, deprecated features including HT Classic Mortar and click block production, and the potential for SnapSync as a server to become the default. Protocol updates covered the Glamsterdam and Hagoda hard forks, with BAL DevNet 3 currently in testing and passing 44,000 tests except for 37, with fixes pending for 35. Performance and storage optimizations were discussed, including work on migrating the EVM from a byte-based stack to a long limb stack. The GitHub org migration was reported as successful, with repositories now under the Besu ETH organization. The team discussed Twitter handle changes, with a recommendation to move from @hyperledger_besu to @lfdt_besu, though final decisions were deferred pending input from the marketing team. Java 25 was proposed for the next release, though it was noted this would prevent targeting RISC-V with Graal. The conversation ended with updates on contributor health, including the addition of new maintainer Miroslav, and a discussion about potential changes to reporting schedules from quarterly to bi-yearly.

## Details

### GitHub Transition for Documentation

Justin outlined plans to transition from using Atlassian to GitHub for managing meeting documentation, including agendas and minutes. He explained that the process would involve creating GitHub issues for agenda items, using AI transcription summaries from Zoom meetings, and then archiving the content in a wiki. Matthew expressed interest in potentially adopting a similar approach for Paladin, though noted they were still working on structuring their wiki effectively. The meeting was introduced as a more in-depth session to better engage with external contributors, with Justin noting the presence of several new participants.

### Release Updates and Protocol Changes

Justin led a meeting discussing release updates and protocol changes. The team plans to release RC2 for version 26.4 in the coming days, with Justin managing the release. SnapSync as a server is now production-ready and likely to become the default soon, though operators were invited to provide feedback. The Glamsterdam hard fork is progressing well with BAL DevNet 3 in testing, while the Hagoda hard fork specifications are still being developed, with frame transactions under consideration as a potential headliner feature.

### BFT and Enterprise Features Update

Matthew provided an update on BFT and Enterprise features, mentioning that version 26.2 is being rolled out to users after regression testing. He noted plans to update BFT chain defaults to production time from Shanghai time, though there are some users still on older versions requiring newer Solidity compilers or Open Zeppelin versions. Matthew also mentioned that Bond's Arc features have been discussed but requires follow-up with Jason regarding current progress and issues.

### Glamsterdam Hard Fork Updates

Justin informed Matthew about a pull request related to Bonsley Archive and offered to tag him as a reviewer. ahamlat discussed the upcoming Glamsterdam hard fork, focusing on scaling and EVM improvements, including opcode repricing and migration from a byte-based to a long-limb stack in Besu. The team is working on migrating opcodes one by one and incorporating GMH benchmarks to assess improvements.

### Besu Project Migration Updates

Fabio reported that they applied for the Linux Foundation mentorship program to evolve and fix the plugin API, with work planned for the second half of the year. The migration of Besu and accompanying repositories to the Besu ETH organization on GitHub was completed successfully, though some cleanup around removing the Hyperledger name remains needed. David raised questions about rebranding the Twitter account from @hyperledgerbesu to @besuproject, discussing the pros and cons of preserving the old handle versus creating a new one.

### Besu Project Technical Updates Meeting

The team discussed several topics including social media handles, code migration, and technical updates. They agreed to consult with the marketing team about the best Twitter handle format for the Besu project, with a preference for including "LFDT" in the name to establish credibility. The group decided to move forward with updating to Java 25, despite some limitations regarding RISC-V targeting. Matthew announced plans to propose a change to the reporting schedule from quarterly to bi-yearly, and the team discussed the friction caused by the DCO requirement in their code review process. They also welcomed new maintainer Miroslav (GitHub ID: MirGee) who has been contributing significantly to the BAL feature.
