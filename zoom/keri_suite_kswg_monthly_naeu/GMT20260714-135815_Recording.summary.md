## Details

The team discussed issues with DOIs and spec versions, with Henk explaining that while the process is understood, implementing it has been delayed for about six months. They agreed that Cora would handle updating the DOIs and creating version 1.1 drafts of the specs, with a central DOI system that generates related sub-DOIs. The team also identified pull requests from Daniel that need to be discussed before proceeding with the spec updates, and decided to schedule a meeting with Cora to review the workflow process.

### KERI Conference Video Updates

Henk announced that all subtitles for KERI conference videos have been updated, with each video taking 4-5 hours to process and resulting in better transcripts and multilingual versions. Samuel encouraged people to link to these videos when discussing specific topics to help build knowledge and adoption of KERI. Samuel also mentioned upcoming events including a SETI summit in November after IAW and a preliminary meeting at the IETF conference in Austria to discuss potentially including KERI specs in the November IETF meeting in San Francisco.

### KERI AI Cybersecurity Conference Plans

The team announced plans for a one-day KERI conference on November 2 or 3, the Monday before IIW in Mountain View, which will be a single-track event focused on AI and cybersecurity topics. Samuel explained that this arrangement was made possible through a mutual sponsorship deal with IIW, allowing them to use the venue while recording the sessions. The conference will feature curated presentations similar to the previous April KERI conference, though funding is still needed for sponsors, food, drinks, and audiovisual services.

### KERI Pi Updates and Improvements

The team discussed updates to KERI Pi, including the completion of upgrading Main to support version 2 of three protocols, with Samuel reporting that the default is now version two and new features like CRAM can be built on top of it. Kent announced that version 1.6.21 of Spec Up T fixed a rapid uncontrolled scroll up bug and offered to submit pull requests to update the specs. The team reviewed and approved two pull requests: one to register Ubi as a URI suffix and another to update the DigWebS repo link from TSWG to KSWG.

### RFC 3339 Specification Update

The team discussed updating the specification language to more clearly indicate that they are using RFC 3339 (a profile of ISO 8601) rather than ISO 8601 directly. Daniel clarified that while the current text is technically correct, the new wording would better reflect their specific use of the standard. The group agreed to accept the pull request, with Henk confirming that updating the specification would not affect their existing DOI number. Phil formally moved to accept the change and Kent seconded the motion, with the team voting in favor of the update.

### KERI PI Specification Enhancements

The team discussed Daniel's work on enhancing the KERI PI specification by adding detailed worked examples for registry handling and graduated disclosure processes. Daniel confirmed that corresponding pull requests have been submitted to the KERI PI repository, though some unit tests are experiencing race conditions on macOS due to temp directory management issues. The team also addressed a bug involving missing commas in quoted strings, which Daniel had already submitted a separate PR to fix. Samuel indicated approval to merge the changes if the worked examples are passing unit tests, pending a review of the specific code changes.

### KERI U Field Terminology Change

The team discussed a proposed change to describe the U field in KERI as "unique entropy" instead of "UUID" to avoid confusion. Samuel provided historical context about the field's original purpose as a salty nonce with sufficient entropy. The group agreed to review the proposal at the next meeting, either at the upcoming DID Web S and Dossier spec meeting or in a subsequent maintainer call.

### Post-Quantum KERI Support Implementation

The team discussed implementing post-quantum support for KERI, specifically focusing on supporting Falcon and potentially other schemes in version 1.1 of the specification rather than 1.0. Samuel explained that normative changes like this one can only be made to the 1.1 spec, which will be created as a new repository branch after completing the DOI work. The group agreed to proceed with post-quantum support implementation in 1.1, with Daniel planning to update the description based on recent code changes.
