## Details

### SECP256K1 Verification Status Update

The team discussed the status of SECP256K1 verification and recovery functionality in the runtime. Joseph confirmed that the ECDSA recovery function exists in utils.ts, but there is no separate verification function available yet. Kent mentioned he would document this information in the release notes, and the meeting transitioned to David's presentation when technical issues with screen sharing occurred.

### Minicrab Rust EDSL Compiler Presentation

David presented Minicrab, a vibe-coded Rust EDSL compiler that generates code for ZKIR and achieves significant optimizations, particularly in serialization and deserialization, with a notable 25x improvement in some circuits. The tool includes extensive testing and benchmarking capabilities, and while it's intended for advanced users rather than general developers, it could serve as a testing suite for Compact and provide insights for potential optimizations. Kent expressed interest in Compact's potential retargeting to generate Rust code, and Yurii introduced his team's work on porting Compact to emit Rust codebase, which they found more convenient for prototyping with the Midnight network's Rust-based codebase.

### Rust Backend Feature Proposal Process

Parisa explained the process for proposing new features, including adding a Rust backend, which requires writing a COIP that will be reviewed by the TSC team. Yurii shared a prototype for emitting Rust codebase for smart contracts and discussed potential communication channels with the team, with Parisa recommending GitHub over Discord for issue tracking. Jonathan reflected on the broader need to establish clear boundaries for different programming languages and environments interacting with Midnight, suggesting a more language-agnostic approach that would allow for flexibility in implementation while maintaining well-defined interfaces.

### Compiler Architecture and Language Support

Yurii discussed the architecture of a compact compiler and proposed supporting a Universal Description Language (UDL) to generate code for multiple languages including Kotlin, Swift, and Python. Jonathan clarified that on-chain nodes don't directly use ZKIR but work with verifier keys and proofs, explaining that while there's potential for storing intermediate representations on-chain in Ledger 9 for automatic upgrades, this isn't currently required for contract execution. Rodrigo presented a pull request related to intermediate representation language, discussing two implementation approaches and seeking feedback on next steps.

### NPS 22 Intermediate Representation Model

The team discussed Rodrigo's NPS 22 intermediate representation model, which Jonathan noted has generated significant interest as a framework for good intermediate representations. Parisa committed to adding the PR to the agenda and contacting the TSC to review it and initiate conversations around the topic. Jonathan explained that the need for language-agnostic intermediate representations becomes particularly important when working on systems of contracts and cross-contract calls, which are still several months from being ready.
