She explained that these automations have helped grow the project from a single maintainer to multiple maintainers and committers, though the current system could benefit from architectural improvements. In response to Andrey's question about implementation steps, Sophie advised starting with understanding contribution needs and creating clear guidelines for different issue difficulty levels, particularly focusing on good first issues which can help new contributors learn the workflow.

### Auto-Assignment and Contributor Engagement

Kevin and Sophie discussed the benefits of auto-assignment for issue tracking, which encourages contributors to interact with the team before submitting pull requests. Sophie highlighted an automation that reminds users to link pull requests and complete assignments, as well as a feature that recommends similar or more challenging issues after completion to maintain contributor engagement. They also noted the effectiveness of their developer-facing documentation, which is linked when checks fail and has been well-tested, though it could be more user-friendly. Kevin expressed interest in emulating these practices for the Python SDK, and Sophie offered to share the relevant automation and documentation links.

The team discussed project growth and sustainability, with Kevin emphasizing the need for new maintainers who are not paid by Shielded Technologies to demonstrate healthy growth to the LFDT TAC. Sophie shared their successful contributor progression system, which starts with good-first issues and gradually advances contributors to more complex tasks, resulting in 50% of Python SDK issues being completed at advanced or intermediate levels. The team also discussed plans to develop tools like LSP server profiling and testing tools to make the project more approachable for third-party contributors.
