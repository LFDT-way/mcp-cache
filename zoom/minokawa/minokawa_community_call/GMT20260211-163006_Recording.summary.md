### Improving Curve Point Validation

The team discussed a bug found in the proving system related to invalid curve point representations in JavaScript. Joseph proposed creating intelligent classes for curve points and field elements to catch invalid inputs earlier in the development process. The proposal includes type-safe constructors and checks at interfaces, as well as a unified API for curve arithmetic with a curve argument. Kevin raised questions about changing the on-chain runtime and supporting multiple curves, such as SECP256K1, in the future. Thomas noted that polymorphism in TypeScript and the on-chain runtime can be handled differently, as they serve different purposes.

### Type Checking Implementation Strategy

The team discussed the implementation of type checking in their system, with Kent proposing to move checks from constructors to access points for better safety, while acknowledging potential performance concerns. Kevin shared insights from his experience with Dart, suggesting that a sound type system with runtime checks is more beneficial than a gradual type system. The team agreed to create a story for moving checks to access points, with the possibility of adding a story for disabling checks if performance becomes an issue.
