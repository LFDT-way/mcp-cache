The team discussed challenges with versioning and release processes, focusing on how to handle release candidates and final releases. Joseph explained the proposed workflow where release candidates would be processed through an internal release workflow before being copied to the public release with a clean version string. ### Version Reporting Standardization Discussion

The team discussed version reporting in dev tools and compiler binaries. Kevin proposed that there should be a single source of truth for version information, suggesting that the version.txt file or commit should match both the downloaded artifact name and the reported version. Jonathan agreed that dev builds should clearly indicate they are not official builds and should include commit hashes. Parisa clarified that current release processes already tag release candidates on the release branch, with only runtime versions changing between RCs, and expressed concern about having different version reporting between CompactC and CompactDevTool.

Joseph agreed to incorporate the suggestions and add everyone as reviewers on the PR, while Jonathan recommended reviewing Rodrigo's link about Rust's versioning approach.
