## Details

### Restricting Casts and Merging Ledgers

The team discussed a proposed change to restrict casting from byte zero to fields, with Kent explaining that this would fix a bug where fields were incorrectly showing as one field long instead of zero. Kevin raised a potential concern about zero being the base case for generic function instantiation, but Kent and Kevin agreed that restricting the cast was a sensible solution. The team also discussed plans for merging composable contracts from Ledger 4 to Ledger 6, with Parisa clarifying that they should merge Ledger 6 into the composable contracts branch. Kevin noted that this would happen after merging unshielded tokens into main and then merging main Ledger 6 into composable contracts.

### Composable Contracts Feature Development

The team discussed composable contracts deliverables for Ledger 6, with Kevin emphasizing that while they should maintain the Ledger 4 to Ledger 6 branch, they should not treat it as a formal deliverable. They agreed to focus on developing a dynamic composable contracts feature as a 7-week spike, which will be implemented behind a feature flag in main. Parisa confirmed that ZKIR changes for composable contracts will be included in both main and the feature branch, and the team aligned on merging the PR containing changes for generated JavaScript, TypeScript, and runtime into the feature branch.

### Cross-Contract Calls Implementation Plan

The team discussed merging a feature branch containing domain changes into the main branch. Kent and Joseph agreed that implementing cross-contract calls sooner rather than later would be better, even if it requires updating the runtime. They decided to continue merging changes into main and use a feature flag for composable contracts. Kevin mentioned that a minimal viable product for cross-contract calls would be developed as a spike, with the goal of having it ready by the holidays.

### Composability and Token Inspection

The team discussed the implementation of composability features, focusing on runtime updates and the benefits of feature flags. Andrzej raised concerns about merging runtime changes for static composability before the path forward for dynamic composability is clear. The group agreed to sync main and feature branch updates but keep them separate for now, with plans to merge after the implementation spike. They also explored options for enabling wallets to inspect contract-based tokens, considering view circuits and self-describing state representations. Kevin suggested adopting a self-describing format for contract state, similar to the events PRD. The team acknowledged the need for further discussion on adding ciphertext to UTXO-based tokens and agreed to involve ledger architects for guidance.
