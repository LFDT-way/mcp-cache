Parisa expressed concern about committing to a timeline without capacity, while Kent and Jonathan clarified that accepting a draft would not assign specific resources but would indicate interest in the project. ### COIP-1 Amendment Discussion

The team discussed whether to create a new compact proposal or amend an existing one. Jonathan suggested amending COIP-1 to include status options for projects redirected to adjacent projects rather than creating a separate process. Parisa agreed to comment on the COIPs and ping Kevin for input on the proposed amendment.

### COIPs Status Process Discussion

The team discussed the status of COIPs (Community Implementation Proposals), noting that most are stuck in draft status despite some being implemented. Kent and Jonathan argued that COIPs should progress through intermediate statuses like submitted and accepted before implementation, rather than remaining in draft indefinitely. Parisa suggested that when features from COIPs are implemented, the status should be updated accordingly, but expressed concern about treating COIPs as specifications due to challenges in maintaining language references. Kent agreed to add this discussion to the next TSC meeting agenda for resolution.

### COIP Process Implementation Discussion

The team discussed using COIP as an initiative with the language reference serving as the source of truth for released versions. Kent raised concerns about when the process becomes immutable, noting that if it becomes immutable only after submission, updates would be problematic, but if it becomes immutable upon full implementation, updates would be manageable. The group agreed to defer further discussion on this topic until Kevin could weigh in, particularly regarding the acceptability of these practices under CAIC rules.
