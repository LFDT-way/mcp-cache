## Overview

This meeting focused on advancing the DTG (Decentralized Trust Graph) specifications through editor calls, with participants discussing process, versioning, and new credential types. The group decided to adopt Semantic Versioning (SemVer) for both specification drafts and code repositories to better align development progress, with working draft versions being sequential numbers and major.minor.patch versions for formal releases. Glenn proposed a new delegation credential type to handle authority delegation scenarios that aren't currently supported in the DTG structure, distinguishing between delegation (giving decision-making power) and authorization (allowing specific actions) credentials. The team also discussed privacy considerations around cryptographic hashing of trust tasks in witness credentials, deciding to start simply with hash-based verification until real-world use cases require more complex approaches. Brendan agreed to report out on progress at the next working group meeting, and Geoff committed to creating a new repository for the trust task specification following the established process.

## Details

### Spec Development Process Transition

The team discussed transitioning from informal spec development to a more structured process with formal working drafts. They agreed to create separate repos for the trust task specification using the same spec-up-T format as the credential specification, with Glenn and Drummond volunteering as editors. The group aligned on using Semantic Versioning (SemVer) for both spec drafts and code bases, deciding that spec versions and code versions don't need to match but should be documented. They also discussed how to handle versioning when different components need to work together, agreeing on a loose coupling approach with minimum version requirements rather than strict version matching.

### ZKP Credential Verification Implementation

The team discussed implementing ZKP (Zero-Knowledge Proofs) for credential verification, focusing on using hash functions of trust tasks to link credentials with their source data while maintaining privacy. Glenn and Brendan agreed to start with a simple hash-based approach rather than implementing selective disclosure or complex ZKP mechanisms at multiple layers, as this could lead to implementation complexity and performance issues. The group decided to prioritize the delegation discussion over new credential ceremonies, as ceremonies are still under active development.

### New Delegation Credential Type Discussion

The team discussed the need for a new delegation credential type to handle scenarios where one person acts on behalf of another, such as parents acting for children or maintainers delegating authority while on leave. Glenn explained the distinction between delegation (giving decision-making power) and authorization (allowing specific actions), noting that while both terms work conceptually, delegation better captures the intended meaning. The group agreed that Glenn would create a pull request to propose the new credential structure, which would need extensive review from both the ZKP group and wider community, particularly regarding the precise semantics and terminology.
