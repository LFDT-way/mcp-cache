### FireFly Community Call Updates

Enrique led the March 18th FireFly Community Call and discussed several key topics including an annual report submission to the LFT, upcoming 1.4 releases with significant fixes, and work on the OpenSSF scorecard. He mentioned that a series of 1.4 releases were expected soon, particularly focusing on fixes for the goal line transaction manager and EVM connector. Enrique also discussed plans to create an Adopters MD file in the main core repo to document companies using different FireFly components, and requested input from Simon regarding potential Cardano connector features for next year's goals.

### TX3 Integration and Project Updates

Simon discussed the ongoing project of integrating TX3 into the FireFly Cardano connector, noting that the team has been focused on implementing TX3 itself rather than integrating it with the Belius library. He mentioned that the Pallas libraries, including Belius, will be releasing 1.0 versions, which will provide more stable versions to build against. Enrique and Simon agreed to update the New Year's goals, potentially removing Sphere 18 and focusing on migrating to a new GitHub organization with periodic patch releases. They also discussed the LFX mentorship program, where someone proposed updating the Fabric connector and migrating to a newer version, which could be part of a summer mentorship opportunity.

### Organizational Structure Transition Planning

Enrique discussed the need to find the right niche and mentioned ongoing investments from mentors to support activities. He also addressed the transition to a new organizational structure under Hypeledger/FireFly, suggesting potential naming options like FireFly/Cardano for the repositories. The main focus was on actively engaging with the move to the new organization and finding the right time to implement it.

### Project Naming and Repository Updates

Enrique and Simon discussed project naming conventions and repository structure changes. They agreed that while some projects like Hyperledger Indy maintain the dash in their names, others like Cacti have dropped it. Enrique will consult with Ryan about naming decisions and handle the necessary updates to tooling and repository URLs when the project moves forward. Simon confirmed that their current publishing process through GitHub packages and Docker images would only require URL updates rather than major changes.
