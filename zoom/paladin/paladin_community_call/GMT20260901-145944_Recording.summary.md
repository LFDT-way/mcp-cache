## Overview

The meeting focused on updates and discussions around the Paladin SDK and upcoming version releases. Anna provided detailed performance improvements, including achieving triple-digit TPS (transactions per second) for NATO mints and transfers within a single domain instance, with optimizations around allocations, garbage collection, and lock management. The team discussed plans for version 1.1, which will likely include Zito's multi-version support and backwards compatibility with existing Zeto tokens, along with bug fixes for Noto. Future development plans were outlined, including multi-tenancy support for different users within a single Paladin instance and improvements to private smart contracts in Pente to address state change scalability issues. The group also discussed versioning strategies across different components of Paladin and how the Java SDK developed by Divyam might be integrated into future releases, potentially aligning with Paladin 1.2.

### NATO Performance Testing Updates

Matthew discussed updates on performance testing for NATO scenarios, including NATO mints and transfers, within a single domain instance. The team achieved triple-digit TPS (transactions per second) performance, which represents a significant improvement over previous Paladin code performance. Matthew mentioned that while the work is largely complete, some code is still making its way through the pipeline, and a roadmap with more details might be available next month.

### Version 1.1 Performance Optimization Updates

Matthew discussed performance improvements being implemented for version 1.1, including reducing allocations, optimizing lock usage, and improving data transfer between nodes, with the goal of establishing baselines to prevent future performance regression. He outlined that version 1.1 will likely seem light on new features due to these non-functional enhancements, with the main addition being Zito's multi-version support and backwards compatibility with existing Zeto tokens. Future considerations include multi-tenancy features for managing multiple users within a single Paladin instance and improvements to private smart contracts in Pente to address state change scalability issues.

### Domain Versioning Documentation Discussion

Matthew discussed the need for better documentation and guidance around different versions of domains and domain factories, including how they relate and the rules governing them. He mentioned the importance of clarifying current behaviors, particularly for reference domains, to ensure clear conversations about versioning. Matthew also noted the progress on the Java SDK and suggested providing an update next month. No other business was brought up.

### Java SDK Release Timing Discussion

Matthew explained that the Java SDK Divyam is working on will likely be included in Paladin 1.2 rather than launched independently. He suggested aligning the release timing with when the Java SDK is ready, considering it as a substantial contribution to Paladin and avoiding pinning Divyam's mentorship program timeline to other work. Matthew offered to discuss specific timing details offline, particularly regarding the mentorship program end date and proposed release dates.
