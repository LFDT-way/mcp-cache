## Details

### Gitmus Project Weekly Update

Ronit, the maintainer of GitMesh, hosted the Weekly Dev Call to provide updates on the project, Gitmus, which collects market signals from social media platforms and converts them into developer-friendly features. Ronit mentioned that some active contributors were unavailable due to exams, and he shared information about the project's open-source nature and its core theme. He also provided details on the Code of Conduct, noting that the project does not contain any commercial advertisements or tools, and encouraged participants to join the live weekly dev call on Wednesdays at 8 PM IST. Ronit concluded by sharing links to the privacy policies, terms of use, and the official repository for further information.

### Docker Build Process Optimization

The team discussed a significant issue with their Docker build process, which currently takes 15-20 minutes to complete and requires a full rebuild even for minor changes. Ronit emphasized that this has become a major bottleneck in their development workflow, as it creates unnecessary friction and slows down their ability to iterate on changes. The team plans to focus on addressing this problem in the coming weeks, as it has become a critical issue that needs to be resolved.

### Docker Build Process Updates

Ronit discussed recent changes to the Docker build process, which included removing Kafka and Olama dependencies. These changes have resulted in a faster build time and reduced container count. The team has updated the logs in the PNP files to reflect these changes. Users can now run Olama locally and connect it to Gitmus without needing to modify any URLs.

### Optimize Docker Build Process

Ronit discussed the slow Docker build process, which takes 15-20 minutes due to independent Docker builds for workers, cloud connectors, and creepers that reinstall the same packages multiple times. He explained that the entire application is rebuilt instead of just the changed parts when modifications are made, leading to inefficiency. Ronit emphasized the need to address this issue by removing repetitive dependencies to improve build time.

### Streamlining Docker Build Process

Ronit discussed plans to streamline the build process by removing package installations from workers and implementing a shared library system. They also aim to improve Docker build speed by using TurboPro service for parallel exchanges and making Gitmus lighter and more developer-friendly for lower resource systems. Ronit highlighted recent PRs that removed Kafka and Ulama configurations, simplifying the Docker setup. The team will continue working on these optimizations over the next two weeks.

## Next steps

- Ronit: Implement parallel Docker builds and integrate TurboPro service to enable rebuilding only of changed components
