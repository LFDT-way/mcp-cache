## Details

### GitMesh Development Progress Update

Parv led the Weekly Dev Call for GitMesh and provided updates on recent work completed over the past two weeks. ### GitMesh Architecture Updates

Parv discussed updates to the GitMesh architecture, explaining that legacy code including Docker governance, packages, GitMesh CLI, playbooks, and public components have been updated and are no longer required. He clarified that the currently active components are CLI and Docker, with the main documentation contained in a pivot document folder that will be entirely replaced in the future.

### Workspace Adapters Structure Overview

Parv explained the structure of workspace adapters, which contain fixtures and sources for testing detectors on mock repositories. He detailed two types of fixtures: full surface, which contains all detectable artifacts, and no artifacts, which should not trigger any detector responses. Parv also described how different tools like Copilot and Claude Code have specific artifacts and configurations that need to be considered in the detection process.

### Workspace Adapters Structure Overview

Parv explained the structure of workspace adapters, noting that each adapter contains three main files: detector.ts, detector.test.ts, and index.ts, with the main logic in index.ts and tests in detector.test.ts. Parv also described the role of GitMesh Doctor, which computes artifact drift and implements rules, while mentioning that normalization and drifter code has been written but normalizer fixtures are still missing.

### File Normalization and Hashing Process

Parv explained that the normalizer is used to handle files with similar content but different formatting, converting markdown into normalized blocks and then creating SHA256 hashes based on content and block types defined in types.ts.

### File Comparison System Implementation

Parv explained the implementation of a file comparison system using symlinks to handle duplicate files efficiently. The system uses a "drifter" component to compare different file versions while ignoring symlinks that point to the same content, with specific focus on comparing agents.md and cloud.md files. Parv demonstrated how the system identifies different content blocks (heading, paragraph, list blocks) and uses hash comparisons to detect differences between file versions.

### Drifter Code in GitMesh Analysis

Parv discussed the work of the drifter code in GitMesh, which compares content across different files to identify differences and shared elements. Parv explained that the drifter successfully detected that agent.md and gemini.md were not identical, identifying two common blocks between them. The drifter's functionality includes comparing pairs of content and detecting whether changes are identical or just reordering of existing content.

They offered to assign GitHub issues related to rules T1.10 to T1.15 to team members who are willing to contribute, with reference materials available in the pivot.md file. After completing the rules, the team will move on to discuss GitMesh apply, GitMesh check, and GitMesh policy in the next meeting.
