### GitMesh Pivot Strategy Meeting

The team held their weekly Dev call for GitMesh on July 15, 2026, to discuss their pivot strategy from GitMesh. Parv mentioned they would finalize the pivot strategy and conduct Q&A discussions. Ronit indicated they had reached some conclusions on the pivot task and planned to explain their work later in the meeting.

### GitMesh Pivot Strategy Update

Parv explained the pivot strategy for GitMesh, which involves narrowing the scope to focus on governance and evidence layers rather than multi-agent orchestration. The new approach will create a layered architecture with four components: read-only change evidence, shadow change policy, approval mechanisms, and budget management. GitMesh will function as a plug-and-play system that tracks historical commits, deployment history, and agent activities while working as a CI check to ensure proper provenance and policy compliance.

### Governance Policy Direction Discussion

Parv and Ronit discussed the direction of governance work, with Ronit noting that governance elements need to be added to an existing policy. Anurag provided positive feedback on the current direction and expressed confidence that the approach would be suitable. Ronit inquired about competitive products, and Parv identified ONA (acquired by OpenAI) as a similar product in the market, while also mentioning Future AGI as another relevant competitor.

### Q30VA Cryptography and Agent Platform

Ronit and Parv discussed a recent open source project called Q30VA, which focuses on cryptography, agent reliability, and guardrails around agents and hallucinations. Ronit explained that the platform aims to provide a comprehensive solution for shipping self-improving agents, including evaluation, tracing, simulations, and optimization. The conversation then shifted to potential issues with model switching and the use of different models for various tasks, with Ronit mentioning Intelligence Lab as a possible solution.

### AI Governance and Platform Management

Ronit discussed the emergence of new AI models from various countries, including India, and the trend toward using heterogeneous models with diverse hardware platforms. The conversation focused on GitMesh's current project around governance and the challenges of managing multiple development environments and UI components. Ronit proposed exploring secure execution environments and semantic routing to create a unified platform for managing agents with better governance, security, and context management across different tools like VS Code and Claude.

### Cross-Agent Context Management Planning

Ronit discussed plans to develop a product focused on managing contacts between different agents within 3-4 months. Parv inquired about the solution for managing contexts across different agents like Copilot, Codex, and Claude. Ronit clarified that while VS Code maintains its own context, the focus is on managing context across different projects and tools like Cursor or Claude, particularly regarding how to combine context between similar projects spread across different locations.

### ID Files Management Discussion

Ronit and Parv discussed managing ID files and dot files, with Ronit suggesting they could start working on combining their ideas and talking to others to identify specific problems. Ronit mentioned researching governance aspects related to YAML and permission policies, planning to add Avdad and Kanban, and create issues for Anurag and Ash. Parv pointed out a need to align their different approaches, noting that Ronit's idea involves a system or CLI tool while Parv's suggestion focuses on GitHub workflows.

### GitMesh AI Activity Monitoring

Parv explained that GitMesh would function similarly to existing GitHub workflows like CodeRabbit or CodeCov, but instead of checking code quality, it would monitor AI agent activities and provide an explainability and evidence layer for tracking agent actions. The tool would allow users to trace who made changes, when they occurred, and which agent was involved, serving as a complete history of data changes made by agents.

### Agent Identity Workflow Implementation

Ronit and Parv discussed implementing a workflow for managing identities of agents working on projects, potentially as a VS Code extension or within GitHub pull request workflows. Parv clarified that this initiative would be more aligned with CodeRabbit rather than UNA. Ronit expressed uncertainty about the execution method and emphasized the importance of ensuring good PR practices and proper merging processes in version control systems like GitHub.

### Project Explainability and Documentation

Ronit discussed the importance of project explainability, focusing on how projects progress, the pivots taken, and the trade-offs made at each step, particularly regarding technical and strategic decisions. She mentioned the evolution of projects, such as moving from monorepo to microservices, and the need to document these changes and decisions. Ronit also proposed developing open-source tooling that could act as a guardrail for project management, especially in environments with multiple people working on projects.

### Context Management Development ID Approaches

The team discussed different approaches to context management across development IDs, with Parv advocating for a single ID per feature while Anurag shared his experience of switching between different IDs based on specific needs. Ronit suggested starting with Parv's initial idea and building on it while gathering feedback from users.

Parv agreed to spend more time understanding the idea and finalizing deliverables, while Ronit committed to creating issues with milestones for the team to work on. The group agreed to focus on customer validation and making a sellable product, with plans to have customer feedback by the end of the month and to create and share issues on Discord by the next day.
