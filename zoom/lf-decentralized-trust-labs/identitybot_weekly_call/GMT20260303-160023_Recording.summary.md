## Agenda

This is a recurring call for the IdentityBot Lab. It's open to anyone interested in Identity Agents. The focus varies each week. See this week's agenda at https://github.com/LF-Decentralized-Trust-labs/identity-bot/tree/main/calls
An Identity Agent is a deterministic, private server that protects users' rights by giving them programmatic control of their digital identity. It runs as a server on a cell phone, desktop, or a private cloud server (Secure Enclave with TEE).

## Details

### Identity Agent Mobile-Server Progress

Robert reported progress on linking identity agents between mobile devices and Linux servers, successfully implementing tunneling between them. He demonstrated that the system could add contacts, though he encountered a server bug that needs to be addressed. Robert noted ongoing challenges with maintaining consistent DNS and web URLs due to the mobile nature of identity agents.

### Cloudflare and ngrok Access Challenges

Robert discussed the challenges of using Cloudflare and ngrok for mobile-friendly device access, noting that Cloudflare lacks a mobile version and ngrok requires either a paid subscription or a limited free option. He also explained the concept of OBI, a carry protocol used for secure handshakes between identity agents, and mentioned a currently working URL.

### Identity Provider Server Development

Robert created an identity provider server at grapeid.org and set it up as a provider. He is currently working on stabilizing the server, which is experiencing issues with managing connections. Robert's next step is to focus on developing a tunnel service that is compatible with both mobile and desktop platforms, as other solutions like ngrok and Cloudflare do not provide an end-to-end solution.

### IdentityBot Lab Project Progress

Robert discussed his progress on developing a profile section and working on persistence issues for the IdentityBot Lab project. He plans to address connection problems with the Grape ID tunnel provider and set up a local database, including SQLite and a vector database, as well as a data lake for storing blobs of information. Robert also mentioned the possibility of merging two codebases if time permits.
