## Agenda

This is a recurring call for the IdentityBot Lab. It's open to anyone interested in Identity Agents. The focus varies each week. See this week's agenda at https://github.com/LF-Decentralized-Trust-labs/identity-bot/tree/main/calls
An Identity Agent is a deterministic, private server that protects users' rights by giving them programmatic control of their digital identity. It runs as a server on a cell phone, desktop, or a private cloud server (Secure Enclave with TEE). 

## Overview

Robert presented progress updates on the IdentityBot application, demonstrating new UI changes and functionality including onboarding processes, key management options, and credential verification features. He showed how users can create and manage digital identities, issue and receive credentials, and use contact sharing through QR codes between desktop and mobile devices. Robert also announced a strategic decision to separate business and individual identity management features, with the core personal identity agent remaining open source while business-specific functionality would be proprietary. ## Details

### Identity Agent Installation Progress Update

Robert conducted an IdentityBot Lab meeting on March 24th and shared progress on installing the Identity Agent app on Windows. He noted that this was his first time installing the app and demonstrated the process live during the meeting. The session ended with Robert allowing a notification prompt for the installation.

### Identity Agent UI and Storage

Robert discussed recent UI changes and architecture improvements for the Identity Agent, including work on user onboarding and business versus individual usage. He presented two key storage options: storing keys on the device or using a mobile phone as a server for key management. Robert acknowledged that the concept of where to store keys still needs further clarification.

### Identity Agent Key Storage Options

Robert explained that users can store their keys either on the device where the app is installed or on a separate device, including a Windows server. He clarified that while this setup is possible, it's not the recommended approach, as the identity agent is designed to give users complete control over their identity. Robert noted that users without smartphones or who prefer not to use them can set up the Identity Agent on a desktop computer, which can be kept running 24/7 at home or work.

### Display Name Feature Demonstration

Robert demonstrated a new feature that allows users to add display names and photos, including YouTube video thumbnails. He explained the current setup uses a Windows computer for demo purposes, but noted that the recommended option would be to install it on a smartphone with keys stored locally and the brain on a remote server. Robert identified a security concern regarding the lack of a secure enclave on the current setup, which could potentially allow key access if the computer is hacked.

### Desktop Dashboard Identity Verification Demo

Robert demonstrated a desktop version of a dashboard featuring identity verification, alerts, tasks, and activity sections. He explained that fingerprint and face scan verification options are not available on desktop unless specific device support exists. Robert also showed a QR code feature for adding contacts, though he noted this functionality had not been fully tested since recent updates.

### Mobile Device Onboarding Process Demo

Robert demonstrated the mobile device onboarding process and tested the QR code scanning functionality, which worked successfully. He identified that setting up OOBI was required and needed to be added to the onboarding sequence. Robert successfully tested the contact addition feature twice, confirming that the notification system was working properly.

### Contact Feature Implementation Demonstration

Robert demonstrated the successful implementation of a contact addition feature, though noted that the UI needs updates to show proper notifications. He also showed the ability to mark contacts as trusted and initiate witness verification processes, though this functionality is still in development. Additionally, Robert displayed the credential issuance feature, allowing users to issue credentials like being a parent.

### Proof of Age Verification System

Robert demonstrated a proof of age verification system that allows users to manually input or scan identity documents, with the verification process being zero-knowledge and cryptographically secure using the carry protocol. He showed how the system works for both issuers and verifiers, including the ability to scan QR codes or FC codes for verification. Robert also mentioned that while the basic functionality is working, they need to streamline the process further, and he briefly touched on interface updates including a new light color theme and upcoming features like passwords, wallet, and my data sections.

### Digital Identity Management System Presentation

Robert presented a comprehensive digital identity management system that includes device management, app installation capabilities, and a governance gateway for controlling data access. He explained that the system features a guardianship model for managing digital assets after death and covers the entire lifecycle of a digital identity from birth through post-death management. Robert noted that spam management and AI management features would be added through upcoming hubs.

### Comprehensive Identity Management System Demo

Robert demonstrated a comprehensive identity management system he built, covering various aspects including AI-specific features, health, finance, social media, legal, and security settings. He explained that the system includes features for managing agent security and privacy, appearance, notifications, API keys, tunneling, endpoints, service providers, governance, key rotation via the carry protocol, backup and recovery, developer tools, and system logs. Robert mentioned that organization features would be added later and indicated there was more development work planned for the following week.

### Identity Agent Core Architecture Decision

Robert explained that developing an organization identity agent within the same software application as the individual app would be too complex due to varying business needs. He decided to separate the functionality, making the Identity Agent Core for individuals open source, while business-specific features will be proprietary. This approach allows businesses to create their own organization identity agents using the core as an SDK. Robert plans to continue working on this and provide an update next week.
