## Details

### Personal Data Portability Protocol Discussion

Tim led a session on the Personal Data Portability Protocol (PDPnP), focusing on technical details of data modeling and communication between data source providers and clients. The discussion covered key concepts including record models, data source manifests, and selection requests, with emphasis on how data is structured and accessed over time. Tim explained the protocol's decision to use a cursor-based streaming model rather than static point-in-time queries, allowing for tracking of data changes, and noted the distinction between append-only and mutable records as a design consideration for simplifying client and server rules.

### PDP Design and Data Approach

Tim explained the design approach of PDP, noting that it does not enforce a canonical data model for different types of data, instead allowing data to be modeled according to its specific domain. He highlighted that while this approach may require understanding multiple schemas for aggregation, it reduces adoption barriers and aligns with the growing capability of AI agents to work with diverse schemas. Tim also described the client experience in PDP, emphasizing that clients initiate data access requests and must specify the data streams, fields, and intended use, with optional access available for users to control data sharing.

### Inventory Protocol Access Controls

Tim discussed the semantics around inventory representation in the protocol, explaining that clients should not be able to access all available data, and OAuth scopes will be used to define access levels. He outlined three categories of promises in the consent process: protocol-enforceable rules, machine-readable claims about data use, and non-programmatically consumable messages to users. Tim emphasized the importance of clearly distinguishing between enforceable and unenforceable client claims, particularly for AI training data, and noted that the current specification provides a framework but leaves implementation details like visual design open for further development.

### Digital Identity Protocol Standardization Discussion

The group discussed the balance between standardization and flexibility in digital identity protocols. Karen emphasized that standards should provide a framework for safe and secure interoperability while allowing room for unique data elements specific to certain companies or situations. The discussion highlighted the importance of establishing common data fields, such as standardized definitions for addresses, to enable portability across different systems. Tim suggested leveraging existing resources like schema.org and DTP data models to support compatibility with common data definitions within the protocol.

### Data Collection Standardization Challenges

Melbin discussed the challenges of standardizing data collection, focusing on two main issues: Agentic Coding and user identity standardization. He explained their solution involved creating a unified identity system using a Vana wallet that persists across different platforms and environments. Tim and Karen explored the implications of lacking unified identity, with Karen highlighting security concerns and Tim discussing the challenges of trust and data provenance when third parties build adapters for data sources.

### Data Verification Protocol Implementation Discussion

The team discussed the implementation of data verification and provenance in the protocol, debating whether it should be built into the core protocol or added as a later extension. Anna and Tim suggested taking a flexible approach that allows for different verification levels based on use case needs, rather than requiring strict verification across all data. The group agreed to document various use cases to better understand how the protocol might work with different scenarios, particularly as data volumes continue to grow and the line between human and AI-generated content becomes increasingly blurred.
