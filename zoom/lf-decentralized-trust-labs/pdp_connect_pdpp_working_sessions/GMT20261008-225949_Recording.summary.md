## Details

### PDPifornia Protocol Review Update

Tim provided a formal review update for PDPifornia, discussing changes made to the protocol based on feedback received during the comment period for the first draft (V0.1). The team aims to lock the first version of the protocol by the end of October, with the governance program set to go live shortly after. Most changes fall into three categories: enhancing user consent for personal data owners, improving clarity for apps requesting data, and creating space for future protocol growth. Tim outlined specific updates, including allowing users to narrow consent for data sharing, enabling multiple purposes per grant, and introducing the concept of a grantor to address cases where data subjects and grantors differ.

### Medical Records Access Protocol Enhancements

Tim explained that the protocol currently doesn't specify how to handle situations where a parent grants access to a child's medical records, such as for proactive healthcare. He noted that while the protocol allows for expressing grantor relationships with verifiable evidence, additional profiles would be needed to define specific verification mechanisms like DIDs or ZK-based proofs. Tim suggested that an initial implementation could establish a profile using a specific technology, with subsequent profiles building on previous ones for different technologies or domains.

### Data Source Handling Updates

Tim discussed several updates to data source handling, including the ability for data source maintainers to define consent text in multiple languages using IETF language tags, and a privacy fix ensuring different applications receive unique IDs for the same individual. He also explained improvements to data freshness tracking, allowing applications to determine how up-to-date the data is, and addressed bug fixes for data syncing functionality. Finally, Tim mentioned ongoing work on data provenance mechanisms based on community feedback, directing interested parties to review PR number 373 for further discussion.

### PDPβ Protocol Updates Discussion

Tim discussed updates to the PDPβ protocol, including improvements to data resilience, support for different token types, and extensibility for future authorization protocols beyond OAuth. Key privacy enhancements include preventing non-expiring tokens and implementing unique identifiers for applications to prevent user information discovery. The team is still working on solutions for AI training permissions and consent withdrawal scenarios, with a potential lease system being considered as a novel application of this pattern.

### Data Usage Protection Standards Discussion

Tim explained that while the standard provides some protections through grant agreements and terms and conditions, it cannot guarantee how data is used once it reaches the client application. He noted that technical verification of data usage would require advanced implementations like trusted execution environments, but such guarantees are not part of the standard. Art's question about preventing data use for AI training remained unanswered as Tim indicated this would require additional technical solutions beyond the standard's scope.

### Data Standardization and Verification Mechanisms

Tim explained that while provingance checks are possible within the current protocol framework, the technical mechanisms for verification would need to be developed later. When discussing data structure standardization, Tim clarified that while common schemas could help with data portability, the project decided against mandating them due to the complexity of handling diverse data formats, especially for smaller platforms. Tim noted that AI's ability to handle arbitrary schemas makes standardization less critical, and the Digital Markets Act provides alternative integration paths that reduce the need for common schemas.

### PDFEP Standard Composability Discussion

Tim discussed the importance of composability in the PDFEP standard, highlighting how it can integrate with existing standards like C2PA. He emphasized maintaining a small core protocol with flexibility for extensions and profiles to accommodate different use cases. Art ended the conversation by outlining next steps, including gathering further feedback, locking the standards, and encouraging community support through pdpp.dev.
