### PDP-Connect Data Connectors Overview

Tim provided a practical introduction to data connectors within the PDP-Connect lab, tailored for builders and others interested in working with data connectors. He explained the structure of the PDP-Connect GitHub repositories, including the PDPπ standard, website, DataConnect application, and data connectors that implement runtimes for connecting to various data sources. Tim highlighted the growing collection of 50-60 data connectors and mentioned the existence of shared tools and patterns in the polyfill connectors package for data connector implementations.

### Data Connectors Collection Profile Overview

Tim explained the importance of the collection profile in the Data Connectors repository, describing it as a companion specification to PDP Illinois that defines a protocol for collecting data from sources not under direct control. He detailed how all data connectors implement the collection profile through a manifest that extends the source declaration in the PDPα standard, containing information about data shape, identifier, version, runtime requirements, and human-in-the-loop requirements. Tim also outlined the lifecycle of a data connector, which follows a stateful execution protocol involving initialization, data collection, and completion phases, with potential human interaction points during the process.

### Data Connector Process Overview

Tim explained the data connector process, describing how it collects data through interactions that can be scripted, with the runtime validating manifests and ensuring proper setup. He detailed how data connectors can be efficient based on specific requests, collecting streams, time ranges, or specific resources, and emphasized the role of the runtime in connecting different components and mediating human interactions through collection profiles. Tim also discussed the process of emitting records in PDP conformant format and the logic required to verify data collection, including handling gaps and incomplete records. The conversation ended with Tim preparing to demonstrate building a data connector locally using the DataConnect tool.

### Data Connector Testing Demonstration

Tim demonstrated how to test a data connector by enabling developer settings and adding a local path to connect to a data source. He showed the process of connecting to a Workshop Ledger account using an API key and explained how DataConnect creates the appropriate runtime for the data connector. Tim also outlined the basic build loop involving manifest creation, collection code, and schema, and mentioned testing methods including using fixtures to replay the collection process.

### Data Connectors Shipping Process

Tim explained the process for shipping Data Connectors through the Data Connectors repo, which involves opening a pull request for approval by maintainers. He described the three tiers of data connectors: development, preview, and supported, with the latter typically having a major version of 1.0 or higher. Tim also mentioned that the collection profile is not opinionated about the runtime environment and highlighted the repo's support for mobile-friendly web-based data connectors through the page shim interface.
