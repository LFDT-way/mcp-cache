## Overview

这次会议主要讨论了OpenAPI项目的开发进展和技术实现方案。Haibo详细介绍了使用skills相比直接URL的优势，包括token消耗更低、支持渐进式披露机制等，并提出了通过API key方式来避免每次登录问题的解决方案。团队还讨论了前端重构工作的进展，Yu-Lin提到需要帮助完成前端部分的现代化重构。会议中还遇到了github权限问题，Haibo无法正常merge代码，需要联系foundation解决管理员权限问题。最后，团队确认需要优先处理PR 765以确保新PR可以正常运行。

## Details

### OpenAPI问题讨论方案

Haibo讨论了使用OpenAPI时遇到的问题，包括每次都需要提供端点和token的麻烦，以及大型JSON文件和高 token 消耗的问题。他提出了使用skills机制作为渐进式披露的替代方案，可以根据不同资源类型动态加载规则，减少 token 消耗。Haibo还建议通过api key方式来避免每次登录问题，并提出了读写操作的分离方案来处理敏感数据和安全边界。

### Swagger API 自动生成文档讨论

Haibo 讨论了使用 Swagger 来自动化 API 文档生成的想法，通过脚本解析 JSON 数据来生成相关的 Markdown 文档。他们认为这可以避免手动更新技能文档的工作量，并减少人为错误。顶层技能约束仍需手动编写，包括工作流程和错误处理等规则。

### API密钥管理方案讨论

Haibo和Baohua讨论了API密钥管理的实现方案，Haibo提出了使用文档存储API密钥的方法，认为这比直接在代码中存储更安全且更方便。Baohua建议比较这个方案与使用MC Server的方法，Haibo同意尝试实现并进行比较。

### PR审查和合并流程讨论

团队讨论了一个PR的审查和合并流程，确认PR已于5月12日开放申请。Baohua和Haibo讨论了CI测试流程需要更新，因为Yu-Lin进行了代码重构。会议中还遇到了GitHub权限问题，Haibo无法合并PR，Baohua建议检查DCO签名信息可能是原因。

### 代码提交签名合规问题

Baohua和团队讨论了提交的comment中缺少sign off的问题，Haibo提到遇到了merge error。Yu-Lin询问是否需要签名，并考虑可能是代码密度相关的问题。Baohua建议将问题发给codec查看，可能是github相关的问题。Yu-Lin还提到需要Haibo帮助重构前端部分以使页面看起来更现代化和简洁。
